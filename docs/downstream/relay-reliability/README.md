# 中继失败切换与错误可见性

中继请求在上游渠道失败时，根据请求类型、重试配置和候选渠道状态尝试后续渠道。失败渠道加入当前请求排除集合；渠道并发满载时同样排除并尝试其他候选，显式指定渠道满载则在等待窗口结束后返回 HTTP 429。

## 重试范围

重试支持 Chat Completions、Responses 和任务中继。重试次数由上游 `RetryTimes` 控制。重试上下文保留原始请求和计费边界，最终成功或最终失败写入用户可见日志；中间重试错误不会作为普通用户的独立成功记录。

不会重试的情况：

- 客户端已断开。
- 错误带不可重试标记，例如图像倍率未配置、读请求体失败、显式指定渠道。
- 令牌固定渠道使用单次尝试 pin（`PinRetrySingleAttempt`），抑制跨渠道重试。
- 任务来源 pin 可要求同渠道重试（`PinRetrySameChannel`），仍不换到其他渠道。
- 渠道亲和失败后的抑制标记。
- 状态码被配置为始终跳过重试。
- HTTP 2xx。

渠道错误和模型容量错误默认允许重试，除非错误码在始终跳过列表中。其他状态码按上游“按状态码重试”配置判断；非法状态码视为可重试。

智能调度开启时，后续尝试沿用当前分组的候选排除集合和权重；逻辑归组先选择逻辑候选，再在冻结成员中选择物理渠道。快速失败策略可配置同渠道重试次数和延迟，这发生在跨渠道切换之前。它要求智能调度总开关和匹配的分组/模型策略，独立于稳定性保护开关；默认最多 3 次、间隔 1000ms，次数为 0 时关闭。客户端取消、不可重试及固定渠道等边界仍生效。

## 最终成功与最终失败

- 最终成功：某次尝试对用户返回成功响应。中间失败仍计入实际成功率，但不计入最终成功率。
- 最终失败：重试预算用尽或错误不可重试后，把最后一次错误返回给用户。
- 管理员日志保留完整诊断字段、渠道名、内部错误和请求 IP（可按规则恢复）。
- 用户侧日志按[使用日志](../usage-logs/README.md)脱敏；优先使用 `user_visible_error_message`。

## 错误映射与屏蔽

渠道监控设置中的错误可见性配置作用于用户侧错误文本，不改变管理员日志：

- `ChannelMonitorErrorMessageMapping`：按上游错误码或 HTTP 状态码替换用户可见消息。
- `ChannelMonitorErrorMessageWhitelist`：命中的错误码/状态码跳过用户侧错误处理，也排除智能调度失败样本、稳定性保护和 429 冷却；普通监控仍记录真实失败。
- `ChannelMonitorErrorMessageKeywords`：按行匹配关键字，大小写不敏感，从用户可见文本中屏蔽。

无效的已保存配置在请求时被忽略，避免把上游失败变成新的网关错误。

## 响应头超时

`RelayResponseHeaderTimeoutSeconds` 限制等待上游响应头的时间，范围 `0..600` 秒，`0` 表示不额外限制。超时错误对用户显示为“等待上游响应超时”，并按普通上游失败进入重试判断。该超时只约束响应头，不截断已经开始的响应体。

## 客户端断开

读取上游响应体时，如果请求上下文已经因客户端取消而结束，归类为 `client_gone`，停止后续重试，不当作渠道故障惩罚。已取得的用量仍按已有结算规则处理；不能把客户端断开解释为上游必然没有产生费用。
