# 智能调度

## 调度方式与路由值

智能调度只按 `(分组, 模型)` 建立独立调度池。每条入选路由独立评分，并只把结果写入对应的 `Ability` 优先级和权重；同一渠道在不同分组或模型下可以得到不同结果，互不影响。

渠道表中的优先级和权重保留为渠道默认值，`Ability` 上的优先级和权重是实际选路值。它们不是两套同时参与竞争的规则：请求选路使用当前分组和模型对应的 `Ability` 值，渠道默认值用于未被智能调度接管的路由和页面对照。

可以限制参与分组和参与模型；未选择分组或模型时分别表示全部，模型选择顺序不影响结果。评分、相对权重拉伸、低成功率降级和稳定性试放都只在同一个 `(分组, 模型)` 池内比较和生效。

从旧版本升级时会执行一次迁移：把已有渠道参与和保护状态转换为路由状态，恢复曾暂存的路由优先级和权重，并固定使用分组模型调度。旧渠道级模式不再提供设置、接口或运行分支。

## 默认策略与分组独立配置

可以在同一套智能调度任务中为不同分组使用不同策略。设置页分为“默认策略”和“分组策略”：未单独配置的分组使用当前默认策略；新增分组策略时会复制当时的默认值，并保存为该分组的完整独立配置。

以下设置保持全局统一：智能调度开关、参与分组、执行间隔、统计窗口和上游响应等待时间。每个独立分组可以分别配置：

- 调度策略和应用方式。
- 参与模型；空数组表示该分组的全部模型。
- 稳定性保护开关、最低成功率、最少样本和降级时长。
- 稳定性占比、业务指标占比、得分曲线指数和相对权重拉伸。

分组策略即使与默认策略完全相同也会保留；以后修改默认策略不会改变已配置分组。删除某个分组策略后，该分组才重新使用默认策略。

## 启用与参与

智能调度定时修改参与路由的优先级和权重。全局开关、参与状态和稳定性保护状态彼此独立：

- 首次配置智能调度时，所有现有渠道默认“不参与”，需要管理员逐个确认。
- 关闭全局调度只停止新任务和正在执行任务的后续写入，不修改任何渠道的参与状态、优先级、权重或稳定性状态。关闭期间仍可调整渠道参与选择，再次开启时按最新选择继续。
- 渠道表中的参与开关会批量修改该渠道的全部分组模型路由；详情面板和调度页可以单独修改一条路由。退出调度只冻结当前路由和稳定性状态，不自动恢复或重置。重新参与时从当前值继续；如果正处于稳定性试放，会从重新参与的时间重新累计试放样本。
- 参与开关不会把渠道重置为优先级 `80`、权重 `10`。需要重算全部参与渠道时，应使用单独的“强制重置优先级和权重”任务。

禁用的渠道、不参与的渠道、没有所需模型或样本不足的渠道不会按正常评分分配流量。样本不足但符合参与条件的渠道使用优先级 `80`、权重 `10` 进行探索。

| 操作 | 参与选择 | 当前路由 | 稳定性状态 |
| --- | --- | --- | --- |
| 关闭或重新开启全局调度 | 保留 | 冻结 | 冻结 |
| 路由退出调度 | 改为不参与 | 冻结 | 冻结 |
| 路由重新参与 | 改为参与 | 保留 | 保留；试放重新计样 |
| 关闭稳定性保护 | 保留 | 受保护渠道冻结 | 冻结 |
| 手动解除保护 | 保留 | 恢复保护前保存值 | 清除 |

## 调度策略

| 策略 | 评分方向 |
| --- | --- |
| 智能调度 `smart` | 按可配置占比综合成本倍率、平均首字时间和平均 TPS，默认 `40% / 40% / 20%` |
| 按成本倍率 `ratio` | 按可配置占比综合成本倍率、平均首字时间和平均 TPS，默认 `70% / 20% / 10%` |
| 按首字 `first_token` | 平均首字时间越低得分越高 |
| 按 TPS `tps` | 平均 TPS 越高得分越高 |

两组百分比各自必须合计为 `100%`。指标占比配置为 `0%` 时，智能调度不再要求该指标达到最少样本。按成本倍率调度的成本倍率占比必须大于 `0%`；性能指标样本不足时，仅使用当前可用指标并按其配置占比重新归一化。

开启稳定性保护后，成功率按可配置占比参与最终得分，默认占 `50%`；所选调度策略的业务得分使用剩余占比。稳定性占比设为 `100%` 时不再要求业务指标。稳定性同时承担准入、降级和恢复判断。

```text
最终得分 = 稳定性得分 × 稳定性占比 + 业务得分 × (100% - 稳定性占比)
```

## 应用方式

“只调整权重”保留现有优先级，只在同优先级渠道间重新分配权重。

“优先级分层 + 权重”先按得分分为 `100`、`90`、`80` 三档，再计算权重。目标权重限制在 `10` 到 `100`，并通过步进和单次变化限制减少频繁抖动。

得分映射权重前可以配置曲线指数，范围为 `0.1..5`，默认 `1`：

```text
权重得分 = 最终得分 ^ 曲线指数
```

指数 `1` 为线性映射；大于 `1` 会放大渠道差距。旧版单指标调度的固定立方映射相当于指数 `3`。

默认开启相对权重拉伸，用同一调度组内的最高、最低最终得分扩大权重差距，减少多个相近得分渠道被近似平均分流。默认从 `3%` 分差开始拉伸，在 `10%` 分差时完整拉伸：

```text
绝对权重得分 = 最终得分 ^ 曲线指数
相对位置 = (最终得分 - 组内最低得分) / (组内最高得分 - 组内最低得分)
相对权重得分 = 相对位置 ^ 曲线指数
混合比例 = clamp((组内分差 - 开始拉伸分差) / (完整拉伸分差 - 开始拉伸分差), 0, 1)
权重得分 = 绝对权重得分 + (相对权重得分 - 绝对权重得分) × 混合比例
```

- 组内分差低于开始值时，保持原有绝对得分映射。
- 组内分差位于两个阈值之间时，渐进扩大权重范围。
- 组内分差达到完整值时，最低和最高得分分别映射到权重 `10` 和 `100`。
- 组内得分完全相同时不拉伸，继续平均分配，避免无依据地偏向某个渠道。
- 开始值设为 `0%` 时，任何非零分差都会开始拉伸；完整值越小，拉伸越激进。

可先用以下参数观察缓存率和成功率：

| 调节倾向 | 开始拉伸分差 | 完整拉伸分差 |
| --- | ---: | ---: |
| 保守 | `5%` | `15%` |
| 默认 | `3%` | `10%` |
| 激进 | `0%` | `3%` |

调度只更新目标 `Ability`。只要实际路由值发生变化，任务正常结束或中途取消都会刷新渠道缓存。

## 模型与样本

统计窗口可选近 `15` 分钟、`1` 小时、`6` 小时或 `24` 小时。最少样本数范围为 `1` 到 `100000`。

默认模型列表用于所有未单独配置的分组；分组策略保存自己的模型列表。每个入选模型形成独立调度池，列表顺序不影响结果。未配置模型时使用分组下的全部模型。

## 稳定性保护

稳定性保护要求同时开启消费日志和 `ERROR_LOG_ENABLED`。成功率按以下口径计算：

```text
实际成功率 = 成功调用数 / (成功调用数 + 渠道错误数)
```

重试过程中的失败也属于真实渠道错误，会进入稳定性样本。样本达到最少要求且成功率低于阈值时：

1. 保存当前优先级和权重。
2. 将该分组模型路由降为优先级 `0`、权重 `0`。
3. 保持到配置的冷却时间结束。
4. 恢复保存的优先级，并以 `min(保存权重, 10)` 的小流量权重进入试放，只统计试放开始后的新样本。
5. 试放样本不足时保持小流量；成功率仍不达标时再次降为 `0/0` 并重新进入冷却。
6. 试放成功率达标时恢复保存的完整优先级和权重、退出保护，下一轮起重新交给正常评分调度。系统暂时保留试放采样起点，直到它移出统计窗口，避免保护前的旧失败样本立即触发二次降级。

关闭智能调度、路由退出调度、关闭稳定性保护、稳定性统计不可用或发现无效状态时，系统不会推断管理员意图，而是冻结当前路由和保护状态。这样开关交叉切换不会隐式放量，也不会丢失待恢复的保存值。

管理端的“低成功率”和“稳定性试放”状态文本可以直接点击，确认后手动解除。即使全局调度已关闭或路由当前不参与，也可以在收到上游恢复通知后立即执行。该操作恢复进入保护前保存的完整优先级和权重，清除冷却及保存值，并从解除时刻重新统计稳定性样本，避免保护前的旧失败记录立即触发二次降级；它不改变路由参与选择，重复执行是幂等的。历史数据缺少保存值时回退到优先级 `80`、权重 `10`。

## 上游响应等待

“上游响应等待时间”限制每次上游请求等待 HTTP 响应头的时间，范围为 `0..600` 秒，`0` 表示不限制。超时后本次渠道请求失败，并交由现有重试、渠道亲和及渠道切换规则处理。

收到响应头后计时立即停止，不限制后续响应正文或流式输出时长。该设置会即时影响后续请求，普通渠道客户端和渠道代理客户端使用相同配置。

## 手动执行与重置

可以手动创建一次智能调度任务。保存设置时勾选“强制重置优先级和权重”，会创建一次性任务：先把符合条件的参与路由重置到探索基线，再根据当前日志重新计算。

同类型任务已有运行中实例时，任务队列复用现有任务并返回 `created=false`，避免重复执行。执行结果记录策略、模型、窗口、计划数、更新数、跳过数和失败明细，可在任务记录中查看。
