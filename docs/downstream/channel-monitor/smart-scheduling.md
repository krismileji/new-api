# 智能调度

> 本文描述 V2.4 已落地的按调度池流量准入、统一采样队列、事件驱动时序和运行时所有权；生产环境是否已经生效仍取决于实际部署版本。

## 调度边界

智能调度只按 `(分组, 模型)` 建立独立调度池。只有明确保存在 `smart_schedule_group_policies` 中的分组才会被调度；系统没有默认策略，也不会把未配置分组自动套用到某个策略。每个分组可以配置全部模型或一个明确的模型列表，每个模型分别计算，互不影响。

调度结果写入对应 `Ability` 的优先级和权重。全局智能调度关闭时，正常请求继续使用项目原有选路规则。全局智能调度开启时，只有命中已保存分组策略及其模型范围的调度池执行严格流量准入，路由必须明确参与调度；未配置策略的分组以及未命中策略模型范围的模型池继续使用项目原有选路规则。

渠道上的默认优先级和权重用于智能调度关闭时以及未命中策略范围的池的官方选路，也用于页面对照。同一渠道在不同分组或模型下可以拥有不同的实际 `Ability` 值；命中策略范围的池中，未参与路由即使保留历史 P/W 也没有流量资格。

观测数据和调度决策使用不同维度。首字、TPS、请求成功/失败、失败耗时和首字分布按 `(渠道, 模型)` 聚合，同一渠道模型在任何分组产生的请求都会进入同一份观测数据；原始日志仍保留请求实际使用的分组，便于审计。评分、候选集合、主渠道、优先级、权重、稳定性保护、管理员固定和执行记录仍按 `(分组, 模型)` 独立，因此多个调度池可以读取同一份渠道模型观测数据，但根据各自策略得到不同结果。

每个共享观测键还保存一个持久化的 `observation_since`。智能调度和渠道监控主表的实际统计起点统一为 `max(配置窗口起点, observation_since)`。该字段只是当前计算和展示的可见边界，不删除原始样本、业务日志或分钟聚合；稳定性恢复时推进一次边界，所有读取同一 `(渠道, 模型)` 的分组从同一时刻重新积累数据。

## 配置与参与

全局只保存开关、统计窗口和分组策略列表。每个分组策略都必须完整配置：

- 调度指标：综合评分、成本倍率、首字时间或 TPS。
- 应用方式：只调整权重，或优先级分层后再调整权重。
- 模型范围；空列表表示该分组全部模型。
- 最少样本、稳定性软评分、保护失败窗口、连续/窗口失败阈值、恢复条件、失败耗时惩罚和冷却时间。
- 是否在稳定性降级期间定时探测；默认关闭，开启后复用当前分组的探测间隔。
- 首字抖动免罚比例、固定慢成功阈值、主渠道目标流量和切换分差。
- 样本补充方式：关闭、探索流量或定时探测。
- 选择探索流量后，同一配置组依次展示目标探索流量、探索请求上限和统一采样顺序；顺序可以按成本倍率，或按当前分组模型的基础优先级和权重。
- 选择定时探测后展示探测间隔；稳定性释放请求上限位于后续稳定性配置组。两个请求上限都以 K Token 输入和回显，配置为 `0K` 表示无限制。

新增策略时页面会填入一套便于编辑的初始模板，但只有管理员保存的分组策略才生效；模板不是未配置分组的默认规则。

每条渠道、分组、模型路由还有独立的参与开关。首次初始化时现有路由均为不参与，需要管理员在渠道列、渠道详情或调度看板中明确开启。渠道列的开关批量修改该渠道所有路由，详情与看板可以修改单条路由。

禁用渠道和禁用 `Ability` 的路由不会进入调度或正常选路。对于命中策略及模型范围的调度池，未参与路由不会在智能调度开启时接收首请求、普通重试、同渠道快速重试或渠道亲和流量；参与候选为空时直接返回无可用渠道，不回退渠道默认 P/W。未配置策略的分组以及策略模型范围之外的模型池不进入智能调度，但仍按官方 Ability 候选集合正常提供流量。关闭全局调度会停止新任务，运行中的任务也会因控制版本变化而停止后续写入。修改任意智能调度配置时，系统会在保存配置的同一事务内撤回旧配置产生的统一探索采样和稳定性试放流量：探索采样恢复基础路由值，试放恢复为 `P0/W0` 的降级保护；现有降级保护和固定主渠道意图继续保留，仍有效的固定主渠道会在同一事务内重新置顶。数据库配置或清理失败时整笔保存回滚，事件刷新或下一轮完整调度再按新配置重新决策。

智能调度配置保存使用控制版本比较并交换。接口返回控制版本，管理端打开表单时保存并在提交时原样带回；同一旧版本的并发请求或之后提交的旧标签页只有第一笔成功。旧请求返回 HTTP `409` 时，当前节点同时从数据库刷新配置缓存，管理端刷新数据并关闭旧表单，重新打开后可立即重试。多实例中，新版本请求若命中仍持有旧配置缓存的节点，该节点必须先从数据库刷新完整智能调度配置，不能仅更新控制版本后继续使用旧策略。数据库提交成功后才同步 Redis 429 冷却版本；若 Redis 同步失败，接口明确提示“设置已保存但冷却同步失败”，写入管理审计，并禁止创建本次强制重置任务，管理员可重新打开设置完成同步。

## 四种评分策略

| 策略 | 业务得分 |
| --- | --- |
| 综合评分 `smart` | 按配置占比综合成本倍率、首字时间和 TPS；首字和 TPS 必须达到最少样本，缺少可比样本时不产生相对满分 |
| 成本倍率 `ratio` | 成本倍率是当前配置快照，必须存在；首字和 TPS 有足够可比样本时按配置占比加入，否则对可用指标重新归一化 |
| 首字时间 `first_token` | 首字越快得分越高，必须达到最少样本 |
| TPS `tps` | TPS 越高得分越高，必须达到最少样本 |

每个指标的原始观测值按渠道模型共享，再只和当前调度池或当前优先级队列中的候选做 `0..1` 归一化。所有候选渠道指标相同时得到相同分数。评分本身只描述渠道表现，评分后的主渠道确认和流量分配使用下一节的独立规则。

智能调度看板和执行记录会保留并展示本轮评分的完整快照：各指标的执行时输入、样本数、同池最小值/最大值和有效渠道数、配置权重、缺失指标剔除后重新归一的有效权重、分项贡献、业务得分、稳定性贡献与最终得分。成本倍率和首字使用 `(同池最大值 - 当前值) / (同池最大值 - 同池最小值)`，TPS 使用 `(当前值 - 同池最小值) / (同池最大值 - 同池最小值)`；同池值完全相同时统一按满分处理。业务得分是各项 `归一化得分 × 有效权重` 之和。

启用稳定性保护后，最终得分为：

```text
最终得分 = 业务得分 × (1 - 稳定性占比) + 稳定性得分 × 稳定性占比
```

稳定性占比设为 `100%` 时不再要求业务指标。关闭稳定性保护时只使用业务得分。

## 优先级与权重

全局智能调度开启后，命中有效策略的 `(group, model)` 只有池内存在可用参与路由时才会形成首请求和重试候选；没有参与路由时直接返回无可用渠道，不使用渠道菜单默认 P/W。没有分组策略或模型不在策略范围时，该池不受智能调度门禁约束，继续使用官方原有候选集合。

每个比较队列会选出一个当前主渠道。首次计算选择最高分；同分时优先保留当前主渠道，没有现任主渠道时按渠道 ID 稳定选择。新渠道必须先达到最少样本。为了避免轻微波动导致主渠道频繁切换，挑战渠道只有在得分至少高出“主渠道切换分差”时才会接管；强制重置会直接选择本轮最高分。当前主渠道被禁用、退出参与或进入稳定性降级后会立即退出候选，不受切换分差限制。

“只调整权重”保留现有优先级，并且只在同一优先级内比较渠道。当前主渠道取得配置的目标流量，可配置范围为 `51%..99%`，默认 `90%`；剩余流量按其他渠道的最终得分比例分配。内部使用总计 `1000` 的权重单位和稳定的最大余数分配，预计占比直接对应配置。低优先级仍遵循原有规则，最高优先级有可用渠道时不会收到正常用户请求。

“优先级分层 + 权重”按得分和主渠道切换保护建立唯一主备顺序。若池内有 `10` 条正常参与路由，就生成 `10` 个从高到低的基础优先级；同分时使用稳定顺序，避免无意义抖动。管理员固定只把固定渠道的当前应用优先级提升到最高层，不改写评分生成的基础排名和基础路由值；固定期间继续更新自动排名，解除或到期时立即恢复基础值。正常首请求只进入当前最高优先级；智能调度开启时，失败请求按当前 `(group, model)` 的有效路由顺序进入后续优先级，当前轮所有可用渠道都尝试过且普通 `RetryTimes` 仍有余额时回到队首。稳定性降级路由统一进入最后兜底层 `P0/W0`，不占正常排名，但在重试到最后时仍可兜底。

预计流量只计算当前最高优先级内可用渠道的 `权重 / 权重总和`。备用优先级显示为 `0%`，只有更高优先级全部不可用时才会接管请求。

同一优先级内仍按权重选择；本轮已经尝试过的渠道暂时排除，按权重无放回地尝试同层剩余渠道。只有 A 一条渠道时，失败重试顺序仍为 `A -> A -> A ...`；当前没有任何真正可用渠道时直接结束，不因循环队列空转。快速失败同渠道重试使用独立额度，先于普通队列执行，不消耗普通 `RetryTimes`。请求为 `auto` 分组时，先按现有自动分组规则确定当前分组，再应用该分组队列，不把不同分组的 P/W 混成一条队列。

“本轮全部候选已尝试”才会回到队首；“候选集合为空”则直接返回无可用渠道。

错误是否允许普通重试仍由现有错误分类、`skip_retry`、指定渠道限制和剩余 `RetryTimes` 决定；智能调度不会绕过这些条件。

## 保本兜底层

智能调度使用换算后的成本倍率判断经济身份：

```text
成本倍率 = 上游倍率 × 换算系数
```

当 `abs(成本倍率 - 分组倍率) <= 1e-9` 时，该 `(渠道, 分组, 模型)` 路由属于零毛利的“保本兜底”。判断使用基础 `GroupRatio`，不使用请求用户相关的 `GroupGroupRatio`；成本倍率高于分组倍率时仍执行既有倍率过高策略，不由保本规则接管。

自动调度使用固定的经济层级：

```text
正常评分层 P2+
保本兜底层 P1
稳定性降级层 P0/W0
```

正常路由与保本路由分别建立归一化范围。保本路由不参与正常选主，也不会获得统一探索采样提权；正常层存在时，P1 的预计流量为 `0%`。正常层全部不可用或池内只有保本路由时，P1 自动成为最高可用层并继续提供服务。多个保本路由共享 P1，并按性能与稳定性得分分配层内权重；样本不足时保留上一轮基础顺序并按渠道 ID 保证确定性。

“只调整权重”模式也会为经济安全保留优先级例外：保本路由统一移动到 P1；若正常路由的最低优先级小于 P2，则统一抬升正常路由的绝对优先级，但不改变它们之间的相对层级。“优先级分层 + 权重”模式下，正常基础排名最低从 P2 开始，所有保本路由固定在 P1。

管理员固定不受保本身份限制。保本路由可以直接固定为主渠道，固定结果覆盖 P1 自动层级；固定解除或到期后，下一轮调度重新把仍为零毛利的路由放回 P1。固定期间是否允许稳定性降级继续遵循原有选项。稳定性恢复时会重新应用当前经济身份：仍为保本则恢复到 P1，已经恢复盈利才重新进入正常评分层。

调度看板和执行记录会展示成本倍率、分组倍率、倍率差与经济身份，并区分“保本兜底”“保本兜底 · 接管中”和“保本兜底 · 已手动固定”。

倍率、成本换算、分组倍率、渠道分组关联或调度参与状态变化后，系统会请求一次立即调度；运行中的调度任务会保留一个后继任务。成本倍率与分组倍率读取使用同一个经济快照，并由 `ChannelMonitorEconomicRevision` 保护写入。若任务计算期间经济修订号变化，旧计划不会写入 `Ability`，对应调度池保留上一轮结果并由后继任务重新计算。

## 重试与特殊路由上限

分组策略保存两个独立的预估 Prompt Token 上限：

| 字段 | 默认值 | 适用路由 |
| --- | ---: | --- |
| `exploration_max_prompt_tokens` | `50K`（`50000 Token`） | 样本不足探索流量 |
| `stability_release_max_prompt_tokens` | `0K`（`0 Token`） | 稳定性释放 `P0/W10` |

管理端以 K Token 输入和回显，`1K = 1000 Token`；API、数据库和运行时仍保存实际 Token 数，只接受 `0` 或 `1000` 的整数倍，最大 `1000000 Token`。上限不是请求次数、QPS、计费上限或硬性拒绝条件。每次新请求和普通重试选路前，优先使用已解析的 Prompt Token 估算，无法取得时可按请求体大小估算；若估算值超过某类路由的上限，就把该特殊路由从本次优先候选中后移，优先使用普通或未超限候选；过滤后没有其他候选时仍允许它兜底。配置为 `0` 或无法取得估算值时不做该类过滤。

请求已经选中渠道并发往上游后，即使后续精确 Token 估算超过上限，也继续当前请求，不中途切换；只有下一次重试重新执行软过滤。稳定性降级 `P0/W0` 不使用这两个上限；定时探测和管理员手动测试默认不受真实业务上限过滤。完整场景和验收顺序见《智能调度产品需求文档》第 16.8、16.9 节。

## 管理员固定主渠道

管理员可以对某个 `(group, model)` 调度池手动指定主渠道，固定时间以分钟计。固定操作会先保存该路由当前的优先级和权重，立即把它提升到池内常规路由的最高优先级之上并设为权重 `1000`。智能调度已启用时还会触发一次调度任务，后续按当前应用方式维持主渠道：“只调整权重”保留它的独占最高层；“优先级分层 + 权重”中，统一探索采样可以临时提升到固定渠道同一优先级，并按配置取得小比例流量，固定渠道仍是实际主渠道并保留剩余大部分流量。固定期间它不会因为其他渠道得分更高而被替换。

同一 `(group, model)` 调度池同时最多只有一条管理员固定路由。对另一条路由设置固定时，系统会先解除并恢复该池之前的固定路由；对当前固定路由重新设置会同时更新“允许稳定性降级”选择，并从本次操作时间重新计算到期时间。设置 `0` 分钟会立即解除；后台每分钟清理一次到期状态，调度执行或调度看板刷新时也会再次检查。若到期时路由正处于稳定性保护，系统会结束固定意图并保留当前安全状态；否则恢复固定前保存的值。

固定主渠道不会绕过渠道状态和参与约束。禁用的渠道或 `Ability`、已退出参与的路由不能新设为固定主渠道。若目标路由当前正处于稳定性降级或试放，页面先显示风险确认；管理员确认后原子解除当前保护并完成固定。固定期间若渠道或对应 `Ability` 被禁用，原有选路会立即排除它，并在同一事务内撤回池内统一探索采样提权，避免临时路由独占最高层；未到期的固定意图继续保留，重新启用后立即恢复。若退出参与、移出分组模型池或删除，系统会清理已经失效的固定路由状态并撤回临时提权。

“允许稳定性降级”默认开启。开启时，固定期间仍持续采集稳定性样本；连续失败或保护失败窗口内失败请求占比达到策略阈值时会立即进入保护，并同时撤回池内统一探索采样提权。滚动稳定性评分只影响排名、流量和恢复参考，不单独触发硬降级。固定的到期时间和选主意图不会被清除；若路由在固定到期前恢复，它会重新作为该池的固定主渠道。保护时间不会暂停或延长原固定期限。

关闭“允许稳定性降级”表示严格固定。系统仍计算并展示稳定性样本、分数和异常，但在固定期内不会因运行时失败自动进入硬保护。手动解除或固定到期后，后续上游失败重新按正常的连续失败与保护失败窗口规则判定。

## 样本补充

低优先级或新渠道可能长期拿不到用户请求，因此每个分组可以选择一种样本补充方式。原“低优先级轮转采样”与“探索流量”合并为一套统一采样队列；两者都在给样本不足渠道临时分配小比例流量，不再保留两套开关、间隔、比例和轮转状态。`priority_sampling_enabled`、`priority_sampling_interval_minutes`、`priority_sampling_base_percent`、`priority_sampling_decay_percent`、`priority_sampling_min_percent` 从目标策略契约中删除，不做旧配置兼容。

统一采样队列只解决“给谁补样本”，不决定谁是主渠道。需要区分两类对象：

- **采样候选**：至少一个已启用指标存在样本欠账。健康备用只要样本不足就必须进入；所有必需样本已经充足的健康备用不再接受采样流量。
- **接管候选**：必需样本已经充足、健康确认通过且满足评分和切换条件。它不需要继续采样，但主渠道半可用时仍可直接参与接管判断。

候选先经过统一硬门禁：渠道与路由启用、明确参与、模型匹配、非保本兜底，并且 `(渠道, 模型)` 不在 429 冷却。通过后再分层：

1. **未硬降级**：可以接受探索流量或自适应备援流量；健康、未知和软压力状态只影响能否接管，不因样本不足被排除。
2. **已硬降级或稳定性试放**：保留在恢复候选层，但不得被业务采样临时提权，只能通过降级定时探测、稳定性试放或管理员手动测试恢复。

未硬降级层永远优先。已硬降级层不是普通业务流量的兜底采样对象，因此稳定性 `P0/W0` 不会被探索或自适应覆盖。

### 关闭

不主动制造请求或流量。完整调度仍为全部参与路由生成唯一的基础 P/W，并把样本不足渠道排在样本有效渠道之后；缺少必需样本的路由记录样本不足原因，只能通过自然业务流量或管理员手动测试补充样本。

### 探索流量

仅支持“优先级分层 + 权重”。页面选择“探索流量”后，在同一个配置组内按以下顺序展示：

1. **目标探索流量**：`exploration_traffic_percent`。
2. **探索请求上限**：`exploration_max_prompt_tokens`。
3. **统一采样顺序**：`sampling_order`。

统一采样顺序不再显示为探索流量组外的独立常驻字段。切换到“关闭”或“定时探测”后保留已保存值；自适应备援仍复用该值。`sampling_order` 的取值和排序规则如下：

| 值 | 排序规则 |
| --- | --- |
| `priority_weight` | 先按当前 `(分组, 模型)` 的基础优先级降序，再按基础权重降序；临时采样覆盖不参与排序，避免被提权的渠道反过来长期占住队首 |
| `ratio` | 按换算后的成本倍率升序；倍率缺失排在有效倍率之后 |

同一排序值下，继续采样当前仍有欠账的对象，然后按最久没有新增有效样本、最久没有被采样、渠道 ID 排序。`sampling_order` 只控制补样本顺序，不改写正常评分、基础排名或主渠道。

开启后，同一调度池一次只选择一条未硬降级且存在样本欠账的备用路由，把它临时提升到当前最高优先级并分配采样权重；其他等待路由保持基础值。

每个真实业务、手动测试或定时探测样本完成后，受影响的 `(分组, 模型)` 池进入事件刷新。普通采样与软健康事件按池合并 `1` 秒；合并只减少重复计算，不引入轮数或租约。刷新重新计算每个指标的样本欠账：当前采样渠道达到全部必需样本后，在同一次刷新中恢复其基础 P/W 并立即选择下一个欠账渠道。所有候选都已补足时立即停止采样，不等待一次性完整调度任务。

自适应备援启动时暂停常规探索覆盖，但保留统一采样队列和候选进度。自适应候选达到样本要求时立即切到下一个候选；自适应退出后，同一次事件刷新重新计算欠账并立即恢复探索流量，而不是等待下一次完整评分。

### 定时探测

系统按分组配置的间隔，为到期渠道模型发送一个很小的流式 `POST /v1/responses` 文本请求，`max_output_tokens` 固定为 `16`。正常路由和稳定性试放路由由 `sample_mode=probe` 开启探测；稳定性降级路由只有在分组开启 `degraded_probe_enabled` 时才探测，因此关闭常规样本补充并不影响单独启用降级探测。同一渠道模型同时关联多个符合条件的分组时只发送一次，使用最短探测间隔，并把结果保存为一份渠道模型共享样本。分组采样方式只决定是否为该渠道模型生成探测请求，不限制其他关联分组读取已经产生的共享样本。只探测本地明确支持 Responses 转换的文本渠道；图片、音频、视频、嵌入、重排以及不支持该协议的渠道会跳过，不记失败样本。

每次请求前都会重新检查全局开关、分组策略、模型范围、渠道状态、路由状态、参与状态和 429 冷却。探测与普通请求共用渠道并发限制；并发已满或渠道模型处于 429 冷却时直接跳过，成功取得配额后会在探测请求期间占用一个并发名额。任务取消会中止后续请求。

成功探测会写消费日志并进入渠道成本统计，日志带专用探测标记并保留实际发起请求所用的分组；真实发出的失败探测写带同一标记的错误日志。成功和失败的定时探测结果都直接进入渠道模型共享样本，即使未开启普通消费日志或错误日志，探测样本仍可供所有关联调度池评分。探测日志不会进入普通业务分钟统计，避免同一请求同时作为业务流量和探测样本计算。没有真正发出上游请求的本地转换或配置错误只记为跳过，不伪造失败与成本。

降级探测成功会原子累计持久化的连续成功次数；实际到达上游的非 429 稳定性失败会清零该次数，并把降级截止时间滚动到“本次失败时间 + 分组冷却时间”，不再等待连续失败或保护失败窗口阈值。达到分组配置的恢复探测成功次数后，立即恢复保护前保存的优先级和权重、清除保护并刷新路由缓存，不等待一次性完整调度任务。恢复计数必须能被多实例共享，进程重启不能丢失恢复进度。未开启该开关时，独立稳定性计时器在冷却结束后立即进入小流量试放。429 只进入独立冷却，不计探测成功或失败，不续期稳定性降级。

正常参与路由和探索流量发生真实上游失败时，系统在统一事件投影后更新同一 `(渠道, 归一化模型)` 的运行时保护状态；连续失败达到阈值，或最近 `burst_failure_window_minutes` 分钟内最多最近 `burst_failure_window_requests` 次请求的失败率达到 `burst_failure_threshold_percent`，就把命中策略的路由降为 `P0/W0`，不等待分钟聚合、下一轮任务或最少样本。成功请求会清零连续失败并进入失败率分母；429 不进入窗口。稳定性试放中的任意有效失败直接重新降级；降级期间的恢复探测失败直接续满冷却。生产请求、管理员手动渠道测试和智能调度定时探测只要请求确实到达上游，都进入同一判断；普通自动渠道维护测试、本地跳过错误和最终重试汇总不触发。当前请求窗口投影位于单进程内存；进程重启或多实例分流会使窗口覆盖不完整，API 必须通过 `projection_started_at` 和 `realtime_degraded` 明确暴露，不能把部分窗口显示为完整数据。

自适应备援也由这些有效请求完成事件触发，但使用独立的 `adaptive_sampling_window_minutes` 和 `adaptive_sampling_window_requests`，在时间范围内只取最近的有效请求。事件刷新更新软健康状态、应急采样对象和临时权重；当新的备用渠道达到成熟条件时，只重算受影响调度池的接管条件，不扫描无关池。硬保护始终优先；已经降级的路由不会被自适应刷新重新提权。同一池并发软事件合并 `1` 秒，刷新期间的新事件必须安排后继刷新。完整调度正在计算时先保留事件，待新的基础路由提交后再刷新覆盖，避免写入旧基础值；429 和硬保护仍立即执行。没有请求时无需轮询自适应窗口，下一次事件会先淘汰过期观测再判断。

429 不计入稳定性保护，而是按全局配置进入短时 `(渠道, 模型)` 冷却。普通业务选路把冷却作为优先避让条件：同一已确定分组仍有其他符合分组、模型、请求路径、渠道状态和请求级排除条件的候选时，必须跳过冷却渠道；分组只有这一路由，或本轮其他候选都已尝试、被排除或不可用时，允许把冷却渠道作为最终兜底，避免整个分组在冷却时间内无路可用。渠道亲和不会直接命中冷却渠道；统一探索采样、自适应备援采样、常规定时探测、降级恢复探测和管理员手动测试仍把冷却作为硬门禁。冷却到期后由独立计时或下一次选路立即重新放行，不等待完整调度。Redis 可用时，冷却截止时间保存在 Redis 并由所有实例共享；Redis 未启用、访问失败或共享状态接管失败时使用当前节点的内存状态兜底。相同渠道模型再次收到 429 只会把截止时间延长到更晚时间，不会缩短已有冷却。冷却写入和运行时稳定性保护都校验请求读取到的调度控制版本；管理员修改任意智能调度配置后，新修订会统一隔离旧的保护窗口并清空本地与 Redis 冷却，仍在途的旧请求不能重新创建已清理的冷却或覆盖新配置路由。多实例并发保存配置时，Redis 版本只接受数据库当前控制版本，较早请求不能在数据库提交顺序之后反向覆盖较新的版本或误清空新冷却；选路只读取与当前本地控制版本一致的 Redis 冷却，其他修订的数据一律忽略。Redis 丢失版本键或恢复旧快照时，收到新 429 的实例会重新校验数据库控制版本，再通过 Redis 比较并交换接管共享状态、清除归属不明的旧冷却并写入本次冷却；比较失败时不会覆盖并发产生的新状态。

全局智能调度开启后，命中分组策略及模型范围的渠道亲和必须通过参与状态门禁，并且只能命中当前实际最高优先级。纳管池仅有未参与或已取消参与状态的路由时不保留官方亲和行为；旧亲和记录命中无资格路由时按无效处理。未配置分组和策略外模型池保留官方亲和行为。开启内存缓存后，纳管路由的参与状态直接使用渠道缓存快照，请求过程中不额外查询数据库。缓存刷新在一个数据库事务中读取 Channel、路由状态和 Ability，完整构建后一次替换；读取失败时继续使用上一份可用快照。

手动渠道连接测试与自动采样方式解耦。全局智能调度已启用、测试能确定原始模型，且至少存在一条已配置、未禁用并正在参与调度的对应分组模型路由时，每次测试只写一份渠道模型共享样本；所有关联调度池都可读取，不按分组复制。`关闭`、`探索流量` 和 `定时探测` 三种模式都适用，稳定性降级中的参与路由也可以通过手动测试积累恢复数据。成功记录可取得的流式首字时间和 TPS，失败记录失败耗时与错误；非流式测试只补成功或失败，不把完整响应耗时当作首字时间。

手动测试仍只写原有的一条模型测试消费日志并进入渠道成本统计，不会额外写探测消费日志。模型测试日志带独立标记，不进入普通业务分钟统计，因此同一次测试不会同时作为业务样本和探测样本重复计算。

## 稳定性得分

稳定性不再把每次错误都当作相同损失：

- 用户请求最终失败按 `100%` 失败惩罚计算。
- 中间重试失败根据该次上游耗时计算。耗时不超过“快速失败界限”时只扣配置的快速失败惩罚；从快速界限到慢失败界限之间线性增加；达到慢失败界限后按 `100%` 惩罚。
- 无法取得精确耗时的中间失败按快速失败惩罚处理。

```text
基础稳定性得分 = 1 - (最终失败完整惩罚 + 重试失败耗时惩罚) / 稳定性总样本数
最终稳定性得分 = clamp(基础稳定性得分 - 超额慢成功数 / 稳定性总样本数, 0, 1)
```

这样，偶发且很快完成切换的上游错误不会和长时间卡住或最终失败等价。

分组策略还可以设置“同渠道快速重试”，范围为 `0..10` 次，默认 `0` 次（关闭）。只有错误本身符合现有重试规则、没有被归类为客户端断开、没有 `skip_retry` 或指定渠道限制，并且本次上游失败耗时不超过“快速失败界限”时才使用这份额度。每次同渠道快速重试前按固定间隔等待，间隔范围为 `0..60000` 毫秒、默认 `1000` 毫秒；请求被取消时立即停止等待，普通跨渠道重试不使用该间隔。快速失败同渠道重试不会增加普通 `RetryTimes` 计数，也不会把当前渠道加入本轮排除列表；额度用尽后，下一次可重试失败才消耗普通重试次数并切换渠道。普通重试选中新的渠道访问后，同渠道快速重试计数重新开始。实际尝试序号仍逐次增加，因此覆盖模板、错误日志和重试观测能正确识别这些请求为重试。

## 首字抖动

开启抖动保护时，系统按成功流式请求的首字延迟分布计算 P50、P95 和 P95 截尾平均值。业务首字评分使用截尾平均值，极少数超慢请求不会直接把平均值拉高。

慢成功直接按固定首字阈值判定，不学习或叠加历史基线。阈值单位为秒，默认 `10` 秒；达到阈值的请求仍然是成功请求，不计作失败，只在超过容忍数量后参与抖动处罚。实际请求失败上限由“上游响应等待时间”控制。

```text
慢成功 = 首字耗时 >= jitter_slow_threshold_seconds
允许慢请求数 = 允许比例为 0 时取 0，否则 max(1, floor(成功流式首字样本数 × 允许抖动比例))
超额慢成功数 = max(慢成功数 - 允许慢请求数, 0)
最终稳定性得分 = clamp(基础稳定性得分 - 超额慢成功数 / 稳定性总样本数, 0, 1)
```

允许比例大于 `0%` 时，达到最少样本的有效窗口至少允许一次慢请求；设为 `0%` 时则不保留这一次容差。默认允许比例为 `5%`，因此 `20` 个成功流式首字样本允许 `1` 次慢成功，`40` 个样本允许 `2` 次；这是根据比例计算，不是写死为每 `20` 个样本一次。只有超过允许数量的部分才从稳定性得分中扣除，每一个超额慢成功的处罚强度等同于在稳定性总样本中增加一次完整失败。

例如窗口内有 `100` 个稳定性样本，基础稳定性得分为 `98%`；其中有 `100` 个有效首字样本、慢成功 `8` 次、允许抖动比例 `5%`，则允许 `5` 次，超额 `3` 次，最终稳定性得分为 `98% - 3/100 = 95%`。如果基础得分原本为 `100%`，相同抖动会得到 `97%`。

首字分布按桶聚合时，完全位于慢阈值以上的桶全部计为慢成功；跨越阈值的桶使用桶内总耗时估算“必然超过阈值”的最小数量，向上取整并限制在桶样本数以内，避免把无法确认的整桶全部判慢。

慢成功统计在每次有效成功样本后进入 `1` 秒池级事件合并，并立即更新滚动稳定性得分、看板和自适应延迟压力，不等待完整调度。慢成功本身不触发 `P0/W0`；正常路由的硬降级仍只由连续失败和失败窗口触发。对于降级恢复，协议成功仍累计恢复探测成功次数，抖动得分只影响“稳定性得分达到恢复参考值”这条恢复路径；两条恢复条件必须在页面分别展示，避免把慢成功误报成失败。

## 降级、试放与手动恢复

正常路由连续失败达到阈值，或保护失败窗口内失败请求占比达到阈值时：

1. 保存进入保护前的完整优先级和权重。
2. 把该分组模型路由降为 `0/0`，进入冷却；若开启降级期间定时探测，连续成功达到恢复要求时立即恢复，每次实际到达上游的非 429 稳定性失败则从失败时刻重新计算完整冷却时间。
3. 未提前恢复时，独立稳定性计时器在冷却结束时立即进入 `P0/W10` 稳定性试放；只有所有更高优先级都不可用时才接收少量兜底流量，也可通过手动测试和常规定时探测积累恢复样本。
4. 只统计试放开始后的新样本。任意实际到达上游的非 429 稳定性失败立即重新降级；连续成功达到恢复要求，或新样本稳定性评分达到恢复参考值时，立即恢复完整保存值。
5. 自动恢复或管理员手动解除保护时，把恢复时刻写入共享 `(渠道, 模型)` 的 `observation_since`，并清除恢复前的运行时失败队列、连续失败数和恢复成功数。后续性能评分、稳定性计算、智能调度看板和渠道监控主表只读取边界后的新数据；尚无新数据时显示样本数 `0` 和 `-`，不能显示成 `0%`。恢复前的原始样本、日志和分钟聚合仍保留，继续供历史明细、按日趋势、长期模型统计以及成功率和缓存利用率历史统计使用。

滚动稳定性评分参与正常排名、流量分配和试放恢复参考；请求事件负责及时更新当前值，完整调度只负责在常规评分时消费该值。正常路由是否进入 `P0/W0` 只由近期连续失败和保护失败窗口决定，不再保留单独的降级评分阈值。关闭稳定性保护或暂时没有可用稳定性数据时不会自动释放已有硬保护状态；自适应备援采样仍由自己的开关控制。

渠道列、渠道详情和调度看板中的“稳定性降级”或“稳定性试放”标签可以直接点击。确认后会立即恢复保护前保存的优先级和权重、清除保护状态，并推进共享观测边界；该操作不改变参与选择。

## 执行与审计

完整智能调度只按需执行：配置、参与状态、成本等管理变更会创建一次任务，管理员也可以在看板中立即执行。设置中的“强制重置优先级和权重”是一次性命令：本轮从基线重新计算已配置且参与的路由，不影响未配置分组。

分组策略中的保护与采样使用独立时钟：

| 机制 | 触发与合并 | 是否等待完整调度 |
| --- | --- | --- |
| 常规评分和基础 P/W | 配置或管理变更、管理员立即执行 | 是，这就是按需完整调度职责 |
| 统一探索采样及切换下一个欠账渠道 | 有效样本完成，按池合并 `1` 秒 | 否 |
| 自适应备援健康、预算和成熟候选接管判断 | 有效请求完成，按池合并 `1` 秒 | 否 |
| 首字慢成功与抖动稳定性得分 | 有效成功样本完成，按池合并 `1` 秒 | 否 |
| 连续失败、失败窗口硬保护 | 有效非 429 失败完成 | 否，立即执行 |
| 429 冷却 | 收到 429 或冷却到期 | 否，立即更新避让或恢复正常候选资格 |
| 降级期间定时探测 | `probe_interval_minutes` | 否 |
| 探测成功恢复、失败续期、冷却结束试放 | 探测结果或独立稳定性计时器 | 否，立即执行 |

完整调度与事件刷新并发时，完整调度只提交新的基础快照；执行期间到达的软事件保留，提交后基于新快照重放。硬保护和 429 门禁不等待完整调度。这样可以避免完整调度覆盖刚发生的保护或采样状态，也不会用高频事件反复重算无关调度池。

任务历史保存每条调整的渠道、分组、模型、旧值、新值、得分、动作和原因。每条明细还记录不可变的执行时评分快照，以及“原主渠道、评分第一、最终主渠道、切换分差、主渠道目标流量、选择原因、调整原因”，因此后续样本或配置变化不会改写历史解释。固定路由还记录执行时该路由是否为管理员固定主渠道、固定到期时间及是否允许稳定性降级；管理员设置、续期或解除固定的操作本身也会把固定时长、到期时间和该选项写入管理审计。页面通过单独的“执行记录”入口查看调度批次，并可按分组、模型、渠道和动作筛选明细。运行期间若管理员修改开关或策略，后续结果会因控制版本或路由修订号不一致而拒绝写入；固定主渠道等必须重算的操作遇到正在运行的调度时，会保留当前任务并只排入一个后继任务，确保新状态最终被重新计算。已实际修改过路由值时会刷新渠道缓存。任务结束时，终态、结果摘要、完整执行明细和任务租约删除在同一数据库事务提交；任一步失败都会整体回滚，避免页面看到已完成任务却缺少明细，或任务已完成但租约仍残留。

智能调度配置中的性能窗口和稳定性评分窗口都接受 `1..43200` 分钟。智能调度实际启用时，渠道监控主表的“近 N 分钟”由性能窗口接管，页面隐藏手动分钟输入，查询允许使用完整的 `1..43200` 范围；智能调度关闭时才显示手动输入，并继续限制为 `1..1440` 分钟。后端返回实际采用的 `range_minutes` 和 `range_source=smart_schedule|manual`，页面以返回值为准。两种模式都继续应用 `observation_since`，且不影响按日统计、历史明细和长期模型统计。稳定性硬保护另用分组策略中的分钟数加请求数窗口，不读取分钟级评分窗口代替。

评分快照的 `sample_scope` 固定为 `channel_model`，`sample_group_count` 记录当前业务观测窗口实际覆盖的分组数。执行记录中的分组表示独立决策所属的调度池，不表示观测数据只来自该分组。

## 评分底线与公平补量

> 本节已经实现。它解决“只有一个渠道有首字或 TPS 样本时被归一化为满分”的问题，并把样本补量限制在可追踪的临时流量内。

### 设计目标

过去的边界是：当只有一个渠道达到最少首字/TPS样本时，该渠道可能成为唯一评分候选；由于同池最大值和最小值相同，归一化结果会变成满分。现在该指标会被标记为不可比较，不再给唯一渠道伪造相对满分。

当前规则是：

1. 没有比较对象时不产生相对满分。
2. 样本不足渠道可以获得有限、可追踪的补量，但不能直接抢占正常主渠道。
3. 不用零值、平均值或伪造成功值填充缺失样本。
4. 保留优先级、权重、稳定性保护、管理员固定和官方重试语义。
5. 区分总请求数与首字、TPS、稳定性有效样本数。

### 池级可比性

首字和 TPS 这类动态观测指标先在当前 `(分组, 模型)` 池内判断是否可比：

```text
动态指标可比 = 有效值数量 >= 2
```

首字和 TPS 的有效值必须是有限数值，且对应渠道满足该指标的最少样本要求并处于当前统计窗口。只有一个渠道有有效值时，这类动态指标应标记为“不可比较”，归一化分数保持为空，不能返回 `1`。成本倍率来自当前配置快照，不是统计窗口样本；只要渠道存在成本倍率就可以参与成本项，不能把它误报成首字/TPS样本。

参与路由按以下四种计算状态处理：

| 状态 | 条件 | 是否可以成为新主渠道 |
| --- | --- | --- |
| 成熟 | 当前启用指标均有足够样本，且池内存在可比对象 | 可以 |
| 临时候选 | 有部分数据，但缺少一个或多个启用指标 | 不可以，只能备用或补量 |
| 样本补充中 | 正在接受探索流量或定时探测 | 不可以 |
| 保护/不可用 | 稳定性保护、禁用、未参与或路由不可用 | 由硬规则处理 |

### 各策略的评分修改

#### 综合评分 `smart`

由“每个渠道都必须有全部指标”改为“池级启用指标”：

1. 先判断首字和 TPS 是否达到最少可比渠道数；成本倍率只检查配置快照是否存在。
2. 不可比指标从本轮业务评分中剔除。
3. 剩余指标的配置权重重新归一化。
4. 只有具备所有剩余启用指标的渠道进入成熟渠道评分。
5. 成熟渠道少于两个时，不进行评分主渠道切换，保留上一轮路由并继续补样本。

例如只有 A 有首字样本，但 A/B/C 都有成本倍率时，首字暂不计入，仍可按成本倍率比较；如果所有业务指标都只有一个有效渠道，则整池等待可比样本。

#### 成本倍率 `ratio`

保留成本倍率主指标语义。首字和 TPS 只有至少两个渠道达到最少样本时才加入评分；不可比的可选指标剔除后重新归一化。成本倍率只有一个有效配置时仍可作为配置项参与，不把配置项数量当作观测样本数。

#### 首字优先和 TPS 优先

这两种策略没有可替代指标：至少两个渠道达到最少样本后，才允许评分选主。只有一个渠道达到条件时，保持当前主渠道或基础顺序，并继续补量。

#### 归一化

当可比渠道数至少为两个时，继续使用当前的相对公式。至少两个渠道值完全相同时保持相同分数和稳定顺序；这与“只有一个渠道”的不可比状态必须区分。

稳定性评分也不应凭单个候选触发评分选主，但稳定性硬保护、故障摘除和管理员固定不受该门槛影响。

### 路由决策

当成熟渠道少于两个时：

1. 已有可用主渠道时，保持其基础优先级和权重。
2. 没有唯一主渠道时，沿用上一轮基础排名；仍无法确定时按渠道 ID稳定排序。
3. 不写入基于单渠道的 `LastScheduleScore`。
4. 仅对样本不足渠道增加临时补量标记。

正常评分切换仍使用现有切换分差。启用自适应采样时，新主渠道还必须在自适应窗口内达到配置的健康请求比例；渠道禁用、退出参与或进入稳定性硬保护时，继续立即切换。

### 样本补量

总请求数不等于首字或 TPS 有效样本数。应分别计算每个渠道的样本欠账：

```text
样本欠账 = max(最少样本 - 当前有效样本, 0)
```

补量对象按以下顺序选择：

1. 先应用启用、参与、模型范围和 429 冷却硬门禁。
2. 未硬降级候选优先；硬降级候选只进入恢复探测层，不接受业务采样提权。
3. 只保留至少一个启用指标存在样本欠账的渠道。
4. 按 `sampling_order=priority_weight|ratio` 排序。
5. 同序时优先继续当前仍有欠账的采样对象，再按最久没有新增有效样本、最久没有被采样和渠道 ID 排序。

每个池同时只给一个备用渠道临时采样名额，不再使用独立租约或轮转间隔。每次有效样本完成后按池合并 `1` 秒，重新比较当前样本欠账；达到目标有效样本后立即选择下一个欠账渠道。一个渠道达到最少样本后，不能结束整个池的补量，必须继续补充下一个渠道。该切换是“采样目标切换”，不是无条件把新渠道切成主渠道。

正常探索流量默认 `3%`，最高不超过 `20%`。主渠道健康度触发的应急采样另按下一节的预算计算，最高不超过 `30%`。常规补量方式由 `sample_mode` 明确决定，不在运行时自动把 `traffic` 改成 `probe`；手动渠道测试始终可以补充共享样本，但 429 冷却会拦截。Token 上限、渠道并发和请求类型限制仍然有效，被限制时需要把原因返回看板。

### 看板与评分快照

首字颜色继续表示绝对延迟，不参与调度评分：绿色小于 `5` 秒，黄色为 `5` 到 `10` 秒以内，红色为 `10` 秒及以上。

看板显示：

- `首字有效样本 1/5`。
- `TPS有效样本 0/5`。
- `首字可比渠道 1/3`。
- `评分状态：正常评分 / 不可比较 / 样本补充中 / 保留上一轮`。
- `样本补充原因`，例如非流式请求、超过 Token 上限、探测不支持或并发不足。

单个指标不可比较时，评分详情显示“不可比较”，不显示 `100 分`。评分快照可以在现有 `cohort.*.available_count` 基础上增加：

```text
comparison_state: comparable | insufficient | none
candidate_state: mature | provisional | sampling | protected
sample_debt: {...}
```

评分快照只解析当前版本的字段，不为历史快照补齐健康状态、相对评分或可比状态字段；版本不匹配时作为不可用明细展示。新增健康状态和样本欠账信息保存在现有路由状态与快照扩展中，不要求新增独立的调度配置文件。

### 验收

已覆盖的核心场景包括：A有100个样本、B/C没有样本时不产生单渠道满分；A/B达到最少样本后才比较；首字优先只有一个有效渠道时保持原路由；样本补充按当前窗口欠账和健康证据选择，且不会把临时候选直接设为主渠道。

自适应采样还会额外检查主渠道健康状态、备用渠道风险和 Prompt Token 上限；这些条件不满足时只保留基础路由或跳过临时采样。

## 稳定性保护中的软降级与备援采样

> 本节把“正常情况下保留主渠道，主渠道逐渐变差时逐步提高备用渠道采样概率”定义为稳定性保护中的软降级阶段。当前实现使用软健康状态、秒级滚动窗口、请求比例判断和应急采样预算，不配置探索租约或独立轮转间隔。

### 设计原则

1. 健康的主渠道继续承接绝大多数正常流量，不为了追求样本齐全而平均分流。
2. 主渠道出现错误增加、首字变慢或抖动时，逐步释放一部分主渠道流量给备用渠道采样。
3. 健康备用只要仍有样本欠账就必须进入采样候选；没有足够证据前不能直接成为新主渠道。
4. 样本已经充足的健康备用不再接受采样流量，但继续作为成熟接管候选参与即时切换判断。
5. 备用渠道自身如果也出现错误或高首字，只降低其采样额度，不把它当成健康备援。
6. 稳定性硬保护、自适应备援和统一探索采样是独立条件：命中硬规则立即降级；仅命中软压力规则时执行备援采样；自适应期间暂停探索，结束后立即恢复。
7. 管理员固定和 429 冷却仍然优先；健康度采样不能绕过 `P0/W0`、429 冷却或禁用状态。

### 主渠道健康信号

主渠道健康度不依赖备用渠道是否已经有样本，优先使用主渠道自己的滚动观测和稳定基线。信号分成三类：

| 信号 | 观测内容 | 说明 |
| --- | --- | --- |
| 错误压力 | 最近自适应窗口内的非 429 错误请求比例 | 429 继续由独立冷却处理，不进入比例分母或风险分子 |
| 延迟压力 | 最近自适应窗口内达到首字告警/高风险阈值的成功请求比例 | 按每个请求的首字耗时计算，非流式或没有首字数据的成功请求按健康处理 |
| 证据可信度 | 窗口内请求数与最近有效请求时间 | 请求数不足时状态为“未知”，不能误判为健康 |

首字的绿色、黄色、红色仍只是页面的绝对延迟提示；自适应调度使用同一组首字告警/高风险秒数对窗口内请求逐条分类，不读取页面颜色，也不把单次红色首字直接解释为渠道失效。

实现复用现有稳定性失败窗口、慢成功阈值和首字分布，不另造失败计数；新增的“软健康状态”不替代现有 `StabilityState`。

### 健康状态机

软降级与硬保护共享错误、首字、样本新鲜度等健康信号，但动作和状态分离：

| 状态 | 进入条件 | 备用采样预算 | 正常主渠道处理 |
| --- | --- | ---: | --- |
| 健康 | 错误率未超过错误告警阈值，首字告警成功请求占比也未达到独立阈值，且没有恢复滞回 | 仅为样本不足渠道保留 `1%..3%` | 保持现有主渠道和正常流量策略 |
| 观察 | 任一进入信号成立，且 `max(错误压力, 延迟压力) < 0.5` | `3%..8%` | 主渠道继续为主，不切换 |
| 降压 | 任一进入信号成立，且最大压力为 `0.5..0.8` | `8%..20%` | 主渠道保留最大预算推导出的流量下限，优先验证成熟备用 |
| 高风险 | 任一进入信号成立，且最大压力达到 `0.8` | `20%..30%` | 主渠道保留最大预算推导出的流量下限；没有成熟备用时优先探测而不是盲目分流 |
| 恢复滞回 | 已在压力状态，当前进入信号已消失，但健康请求占比尚未达到恢复阈值 | 按当前压力公式收缩，最低可回到基础预算 | 保留原软状态，达到恢复健康比例后才退出 |
| 硬保护 | 命中现有稳定性硬规则 | 不再走正常主渠道流量 | 按现有 `P0/W0` 和重试兜底处理 |

这里的百分比是池级备用采样预算，不是每个备用渠道各拿一份。健康状态下如果所有备用渠道都已达到最少样本，预算可以降为 `0%`，完全保持当前路由。

软降级只增加备用渠道的验证流量，不写入 `stability_state`，也不会绕过管理员固定、429 冷却或硬保护；硬保护一旦触发，立即停止软采样并按 `P0/W0` 处理。`stability_enabled` 和 `adaptive_sampling_enabled` 是独立开关，关闭其中一个不会隐式修改另一个。

状态转换使用同一秒级窗口内的独立进入信号和恢复滞回：

```text
错误进入信号 = 非 429 错误请求数 / 窗口有效请求数 × 100% > 错误告警率
首字进入信号 = 首字达到告警秒数的成功请求数 / 窗口有效请求数 × 100% >= 首字告警请求占比阈值
进入压力状态 = 错误进入信号 OR 首字进入信号
```

- 非 429 错误率超过 `adaptive_sampling_error_warning_percent` 时，错误信号独立触发压力状态。
- 首字达到告警秒数的成功请求占比达到 `adaptive_sampling_first_token_warning_request_percent` 时，首字信号独立触发压力状态。
- 两个进入信号按 OR 判定，不先合并为风险请求再通过统一比例门槛。风险请求占比仍用于看板和执行明细解释，不决定是否进入。
- 压力状态只有在错误和首字两个进入信号都解除，且窗口内健康请求比例达到 `adaptive_sampling_recover_request_percent` 后才恢复健康；仍命中的进入信号优先于恢复判断。首字告警请求占比阈值与恢复健康比例之和必须大于 `100%`，保证首字进入和恢复不会在同一边界同时成立。
- 命中硬保护、渠道禁用或明确退出参与时立即执行，不等待软状态滞后。

### 备用渠道风险分层

备用渠道先按路由状态分层，再按统一采样顺序选择：

1. **未硬降级且有样本欠账**：可以接受探索或自适应业务采样；其中已验证健康、未知和逐渐不可用都保留为候选，是否能够接管另行判断。
2. **已硬降级或稳定性试放**：只接受降级探测、试放或手动测试，不得被业务采样临时提权。
3. **429 冷却、禁用或未参与**：禁用或未参与会完全阻断；429 冷却会阻断探测和采样，并让普通请求优先选择其他渠道，只有无其他可用候选时才作为最终兜底。

第一层始终优先于第二层；第一层内部统一使用 `sampling_order`。`priority_weight` 读取当前分组模型的基础 P/W，`ratio` 读取换算后的成本倍率。健康证据用于限制接管和控制风险预算，不替代管理员配置的候选顺序。

如果所有未硬降级备用都是未知或逐渐不可用，不把其中任何一个直接提升为主渠道，只使用最大预算约束的受控采样流量。所有备用都已硬降级或处于 429 冷却时，业务采样预算归零；降级探测仍按自己的间隔运行，但 429 冷却会阻断探测。

### 备用采样预算

备用预算由“样本欠账”和“主渠道健康压力”共同决定：

```text
样本欠账 = max(最少样本 - 当前有效样本, 0)
样本需求 = clamp(最大样本欠账比例, 0, 1)
健康压力 = max(错误压力, 延迟压力)
备用预算 = 样本需求 × (基础补量预算 + 健康压力 × (最大预算 - 基础补量预算))
```

错误压力和延迟压力都归一化到 `0..1`。建议初始值：基础补量预算 `3%`，最大预算 `30%`。如果所有备用渠道都已达到最少样本，样本需求为 `0`，不产生额外采样。实际预算还要经过以下限制：

健康主渠道的正常 `sample_mode=traffic` 补量仍沿用现有 `exploration_traffic_percent`，不因启用自适应采样而改变；上式的基础预算从主渠道进入观察、降压或高风险后才用于应急采样。

- 实际备用预算不得超过最大预算；例如最大预算为 `30%` 时，正常单主渠道至少保留 `70%`。
- 只能从主渠道当前权重中切出，不改变正常主备顺序。
- 受到探索 Token 上限、请求类型和渠道并发限制。
- 每个池同时只给一个欠账渠道使用预算；对象按 `sampling_order` 和统一同序规则选择，达到样本要求后在下一次 `1` 秒事件刷新中立即切换。

当使用“优先级分层 + 权重”时，采样渠道可以临时进入主渠道的同一优先级，但只拿预算权重；主渠道仍保留剩余权重。这样既能获得真实样本，又不会把正常流量平均打散。采样结束后恢复基础优先级和权重。

### 软降级可配置参数

自适应采样参数属于稳定性保护中的软降级分支，每个分组策略独立配置，不使用全局隐藏常量。它与硬保护使用同一组健康观测，但不改变硬保护状态。下表字段可直接配置，页面新建策略时使用表内默认值；保存时必须完整提交当前版本字段，旧的“轮数”字段不再输出或参与运行。管理端允许直接修改这些值用于观察和调试。

| API 字段 | 默认值 | 允许范围 | 作用 |
| --- | ---: | ---: | --- |
| `adaptive_sampling_enabled` | 开启 | 布尔值 | 是否根据当前主渠道的错误和首字压力启动应急采样 |
| `adaptive_sampling_base_percent` | `3%` | `0%..10%` | 主渠道进入软压力后，应急采样使用的池级起始预算 |
| `adaptive_sampling_max_percent` | `30%` | `1%..49%` | 主渠道尚未硬保护时，应急采样可使用的池级最大预算；正常单主渠道最低保留比例自动为 `100% - 本值` |
| `adaptive_sampling_error_warning_percent` | `5%` | `0%..100%` | 非 429 稳定性错误率超过该值后开始产生错误压力，并独立触发压力状态 |
| `adaptive_sampling_error_critical_percent` | `15%` | `0%..100%` | 非 429 稳定性错误率达到该值时错误压力记为 `1` |
| `adaptive_sampling_first_token_warning_seconds` | `5` 秒 | `0..60` 秒 | 首字时间达到该值后开始产生延迟压力 |
| `adaptive_sampling_first_token_critical_seconds` | `10` 秒 | `0..60` 秒 | 首字时间达到该值时延迟压力记为 `1` |
| `adaptive_sampling_first_token_warning_request_percent` | `10%` | `>0..100%` | 窗口内首字达到告警秒数的成功请求占比达到该值后，独立触发压力状态 |
| `adaptive_sampling_recover_request_percent` | `95%` | `>0..100%` | 窗口内健康请求（成功且首字未达到告警阈值）达到该占比后恢复健康 |
| `adaptive_sampling_window_minutes` | `10` 分钟 | `1..60` 分钟 | 计算风险请求比例、健康请求比例和切换确认的最长时间范围 |
| `adaptive_sampling_window_requests` | `100` 次 | `1..1000` 次 | 时间范围内只统计最近的业务请求、手动测试和定时探测 |
| `adaptive_sampling_switch_confirm_request_percent` | `95%` | `>0..100%` | 评分胜出的备用渠道窗口内健康请求达到该占比且证据足够后才允许成为新主渠道 |
| `adaptive_sampling_min_comparable_channels` | `2` | `2..10` | 一个指标允许相对归一化和选主所需的最少有效渠道数 |

阈值采用线性压力，便于管理员直接推算预算：错误率在错误告警和高风险阈值之间线性归一；每个成功首字样本在首字告警和高风险秒数之间线性插值，再按窗口有效请求聚合为延迟压力。错误率超过告警值，或首字告警成功请求占比达到独立阈值，任一信号即可进入；进入后的预算压力取两者最大值。风险比例和健康比例仍使用窗口内等价计数的真实业务、手动测试和定时探测样本，其中风险比例只用于展示，健康比例继续用于恢复和切换确认。生产日志中的探测和手动测试标记会先排除，再从共享样本缓冲区各计一次，避免重复。429 和最终重试汇总不计入比例；没有首字数据的成功请求按健康处理。样本过旧或不足时记为“未知”，不能用缺失值推导健康。每个有效请求完成后刷新受影响池，不等待完整调度周期或分钟聚合。

旧字段 `adaptive_sampling_enter_request_percent` 会被明确拒绝，不读取、不回显、不迁移；当前策略必须显式提交 `adaptive_sampling_first_token_warning_request_percent`，不提供旧配置兼容。`adaptive_sampling_primary_min_percent` 已从当前契约移除，旧持久化配置中的该字段兼容忽略且不再输出。

保存时执行以下组合校验：

1. 错误高风险阈值必须大于错误告警阈值，首字高风险阈值必须大于首字告警阈值。
2. `adaptive_sampling_first_token_warning_request_percent + adaptive_sampling_recover_request_percent` 必须大于 `100%`，保证首字进入和健康恢复之间存在滞回。
3. `adaptive_sampling_base_percent` 不能大于 `adaptive_sampling_max_percent`。
4. 开启自适应采样时，应用方式必须为“优先级分层 + 权重”；其他应用方式无法把低优先级备援临时提升到同层采样。
5. `adaptive_sampling_min_comparable_channels` 只控制相对评分和软切换，不影响禁用、退出参与、429 冷却、稳定性硬保护及管理员固定。

自适应采样开启时，应用方式必须为“优先级分层 + 权重”；“只调整权重”仍可用于不启用自适应采样的独立策略。两种策略都必须完整提交当前版本字段，不做旧配置兼容。

### 与常规样本补充的关系

`sample_mode` 和 `adaptive_sampling_enabled` 是两套独立开关：前者控制主渠道健康时是否常规补量，后者控制主渠道出现软压力时是否为了验证备援而临时补量。二者共用候选资格、`sampling_order`、样本欠账和 Prompt Token 上限，不再维护两条轮转状态。

| 配置组合 | 主渠道健康 | 主渠道进入观察、降压或高风险 |
| --- | --- | --- |
| `sample_mode=off`，自适应采样关闭 | 不补量 | 不因软压力补量，只有现有硬保护和重试生效 |
| `sample_mode=off`，自适应采样开启 | 不补量 | 按健康压力启动应急采样 |
| `sample_mode=traffic`，自适应采样关闭 | 按探索比例执行统一采样队列 | 仍使用固定探索比例，不自动放大 |
| `sample_mode=traffic`，自适应采样开启 | 按探索比例执行统一采样队列 | 暂停探索覆盖，由自适应预算接管同一候选队列；自适应结束后立即恢复探索 |
| `sample_mode=probe`，自适应采样开启 | 按探测间隔补量 | 软压力期间可用自适应业务流量验证欠账备用；恢复健康后继续原定时探测方式 |

应急采样预算始终只分给有样本欠账且未硬降级的备用渠道。健康备用有欠账时必须在候选中；健康备用样本充足时预算为 `0%`，但它仍可作为成熟接管候选。所有备用都已硬降级、处于 429 冷却、禁用或退出参与时预算也为 `0%`，不能为了凑满配置比例把流量发给不可用渠道。429 继续使用独立冷却，不计入普通错误压力，并阻断该渠道模型的探测和采样；普通业务请求仅在没有其他可用候选时兜底使用。

系统不配置探索租约或轮转间隔。每次事件刷新都从当前窗口重新计算样本欠账并使用 `sampling_order` 选择候选。同一候选仍有欠账时继续采样；达到要求、进入硬降级或 429 冷却时立即换到下一个候选。选择变化只修改临时采样覆盖，不改变基础排名和正常主渠道。

### 调试示例

下面的数值使用默认 `最少样本=5`、`基础预算=3%`、`最大预算=30%`；正常单主渠道最低保留比例由最大预算自动推导为 `70%`：

| 场景 | 观测与配置 | 结果 |
| --- | --- | --- |
| 正常主渠道 | A 为当前主渠道且健康；B/C 各缺少首字样本；`sample_mode=off` | A 保持原有主渠道流量，不为了补齐样本分流；如果改成 `traffic`，只按现有探索流量配置给一个欠账渠道小比例采样 |
| 主渠道变慢 | A 的首字告警成功请求占比已达到 `10%`，独立触发压力状态，首字延迟压力为 `0.5`；B 欠账 `5/5` | 备用预算为 `5/5 × (3% + 0.5 × (30%-3%)) = 16.5%`，A 当前保留 `83.5%` 且最低保留 `70%`；该预算只给一个风险最低的备用渠道 |
| 按倍率采样 | B/C 都有欠账，B 倍率 `0.8`、C 倍率 `1.1`；`sampling_order=ratio` | 先采样 B；B 达到样本要求后的下一次 `1` 秒刷新立即切到 C |
| 按分组 P/W 采样 | B 基础 `P80/W20`，C 基础 `P70/W100`；`sampling_order=priority_weight` | 优先级先于权重，因此先采样 B；临时提权不参与下一次排序 |
| 备用渠道已降级 | B 有欠账但已为 `P0/W0`，C 有欠账且未降级 | 业务采样优先 C；B 只走降级探测，不被探索或自适应提权 |
| 单渠道满分 | A 有 `100` 个首字样本，B/C 为 `0`；首字指标最少可比渠道为 `2` | 首字指标显示“不可比较”，A 不获得基于首字的 `100` 分；主渠道沿用上一轮并继续补样本 |
| 自适应结束 | A 恢复健康，B 正在接受自适应采样，常规探索原本开启 | 同一次事件刷新撤回自适应覆盖；若仍有欠账候选，立即按探索比例恢复统一采样队列 |
| 候选接管 | C 已达到最少样本、与另一渠道可比较且自身健康；切换分差满足 | 事件刷新只重算当前池并检查健康请求比例；满足确认比例后立即接管，不等待完整调度；主渠道进入硬保护时仍直接退出 |

调试时可以先把 `adaptive_sampling_first_token_warning_request_percent` 调为 `10%`、`adaptive_sampling_window_minutes` 调为 `1` 分钟、`adaptive_sampling_window_requests` 调为 `20` 次、`adaptive_sampling_recover_request_percent` 和 `adaptive_sampling_switch_confirm_request_percent` 调为 `95%`，把 `adaptive_sampling_base_percent` 调为 `5%`。先分别制造“错误率超过错误告警值”和“首字告警成功请求占比达到 10%”两种场景，确认任一信号都能独立进入，再观察风险/健康请求占比、健康状态、压力和备用采样；确认行为后恢复默认的 `10%/10 分钟/100 次/95%/95%` 和 `3%`。首字告警请求占比与恢复健康比例之和必须大于 `100%`，最大预算也不能超过业务可接受的备援流量。

### 从采样到接管

备用渠道必须满足以下条件才允许成为新主渠道：

1. 达到对应指标的最少有效样本。
2. 至少存在另一个可比渠道，不能以单渠道相对满分作为依据。
3. 自身没有处于逐渐不可用或硬保护状态。
4. 在自适应窗口内健康请求比例达到 `adaptive_sampling_switch_confirm_request_percent`，并达到现有主渠道切换分差。
5. 主渠道当前健康状态确实允许切换，或者主渠道已经不可用。

备用渠道刚完成样本补量时立即进入“成熟候选”，同一次事件刷新先停止对它采样并切换下一个欠账渠道，再对当前池执行接管确认。只有健康请求比例、可比渠道数、切换分差和主渠道压力同时满足时才接管；不再额外等待一轮完整调度。

### 主渠道流量保护

主渠道流量保护是策略的硬约束之一：

- 健康状态不因为样本补量而降低主渠道的正常目标流量。
- 观察和降压状态只从主渠道权重中切出预算，不把所有备用渠道提升为同级正常流量。
- 看板展示“主渠道预计流量 / 备用采样流量”，让流量变化可解释。
- 渠道缓存利用率仍可在原有渠道监控页面查看，但不参与自适应采样预算、健康状态或主渠道切换判断。

### 看板状态

建议在当前路由状态之外增加：

- `主渠道健康：健康 / 观察 / 降压 / 高风险`。
- `健康压力：错误 xx% · 首字 xx ms`。
- `主渠道流量：90%`。
- `备用采样：10%（B 6%，C 4%）`。
- `备用证据：已验证健康 / 未知 / 逐渐不可用`。
- `未切换原因：备用渠道样本不足 / 备用预算未达到接管条件 / 切换分差不足`。

“首字红色”只表示首字达到绝对慢阈值；真正触发降压还需要自适应窗口具备足够证据，且首字告警成功请求占比达到配置阈值。错误率超过错误告警阈值则可以作为另一条独立信号触发，二者都不会把单次慢请求直接解释为渠道失效。

### 实现与运行时所有权

1. 策略契约只保留统一采样字段；`priority_sampling_*`、旧轮数和探索租约字段被明确拒绝，不读取、不回显、不迁移。
2. 完整调度只写评分、正常选主、基础排名和基础 P/W；固定、硬保护、试放、探索、自适应及滚动健康状态由运行时路径持有，基础提交后按池立即排队重放。
3. 普通采样、软健康和抖动事件按池合并 `1` 秒。当前候选补足或失效后立即切换；自适应结束时在同一次刷新恢复仍有欠账的常规探索。
4. 降级探测连续成功数保存在 `(渠道, 模型)` 共享样本状态中。达到次数阈值的探测结果立即恢复；试放达到最少样本和恢复稳定性分时也由运行时事件恢复，均不等待完整调度。
5. 429 冷却优先避让普通请求并阻断亲和、手动测试、常规/降级探测和全部采样；普通请求没有其他可用候选时可使用冷却渠道兜底，独立到期处理立即触发池刷新。
6. 自适应采样只支持“优先级分层 + 权重”；“只调整权重”仍只使用正常评分和基础路由。
7. 主渠道流量保护由最大备援预算、压力状态和切换确认控制；正常单主渠道最低保留比例直接按 `100% - 实际备用预算` 计算，缓存利用率不参与自适应采样、健康状态或主渠道切换判断。
8. 首字颜色仅用于绝对延迟提示：绿色 `<5` 秒、黄色 `5..10` 秒、红色 `>=10` 秒；真正的健康状态还需要自适应窗口内请求比例和最少样本。
9. 自适应进入由错误率超过错误告警阈值，或首字告警成功请求占比达到独立阈值触发；两个信号按 OR 判定，合并风险请求占比只用于解释展示，健康请求占比继续控制恢复。

验收重点：主渠道健康时主渠道分配基本不变；主渠道错误或首字持续恶化时，备用渠道采样比例逐步上升；备用渠道样本不足时只能被验证，不能凭单渠道满分接管；备用渠道自身恶化时不会被提升；主渠道硬保护时仍沿用现有稳定性兜底。
