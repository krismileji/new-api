# 智能调度与保本兜底

智能调度按分组和模型建立渠道候选池，根据成本、首字时间、TPS、成功率和稳定性选择主渠道、备用渠道及流量权重。管理入口位于 `/channel-monitor` 的智能调度设置和任务页面。

## 调度准入

只有显式配置策略且标记为参与的路由进入下游托管池；禁用、暂停、未参与或不满足模型能力的路由会被排除。没有托管策略时，系统回退到原有 Ability 和渠道优先级/权重。

策略支持 smart、ratio、first_token 和 tps，并可选择 weight 或 priority_weight 应用方式。策略字段会校验范围和组合关系，旧版已废弃字段会被拒绝。

## 评分与保本

调度使用当前观测窗口的成本、首字、TPS 和成功率计算分数；稳定性保护会根据失败和恢复状态调整候选。成本经济分类把渠道分为正常、保本兜底和未知：成本倍率与分组倍率差值在 epsilon 内的渠道进入保本层，不能作为正常主渠道，但可在正常候选不可用时接管。

保本渠道按独立 P1 层处理，正常渠道至少处于 P2；同一层内仍按配置的权重和优先级选路。未知经济数据不参与正常调度。

## 运行时保护

请求事件会触发 429 冷却、稳定性保护、自适应采样和候选刷新。大请求会受探索和采样 token 上限影响；候选全部被保护时回退到可用候选。调度写回带 control、economic、participation 和 revision 检查，旧任务不会覆盖新配置。

失败重试会沿用当前分组的候选排除集合和权重；逻辑归组先选择逻辑候选，再在冻结成员中选择物理渠道。管理员设置固定主渠道时，只改变池内优先级和权重，不绕过渠道禁用、模型能力、参与状态或 429 冷却。

固定主渠道在有效期内因渠道自动禁用、手动禁用或路由能力临时禁用而不可用时，固定意图会暂挂，池内其他可用渠道继续接管；渠道和路由恢复且仍未到期时自动重新置顶。移除分组、模型或智能调度参与关系属于结构变更，会清理对应路由状态，不会在重新加入后恢复旧固定意图。

## 数据边界

调度状态、评分细节和临时流量写入调度模型；成本、余额、日志和并发仍按物理渠道保存。Redis 实时事件、调度运行时和本地历史队列并存，不能视为单一强一致决策账本。
