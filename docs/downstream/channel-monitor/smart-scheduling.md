# 智能调度

## 调度边界

智能调度只按 `(分组, 模型)` 建立独立调度池。只有明确保存在 `smart_schedule_group_policies` 中的分组才会被调度；系统没有默认策略，也不会把未配置分组自动套用到某个策略。每个分组可以配置全部模型或一个明确的模型列表，每个模型分别计算，互不影响。

调度结果写入对应 `Ability` 的优先级和权重。正常请求仍使用项目原有选路规则：先选择当前分组和模型下最高优先级的可用路由，再按权重分流。因此智能调度没有另建一套与官方规则并行竞争的路由系统，只是在任务执行时维护官方选路实际读取的 `Ability` 值。

渠道上的默认优先级和权重仍用于新建或未被调度接管的路由，也用于页面对照。同一渠道在不同分组或模型下可以拥有不同的实际 `Ability` 值。

观测数据和调度决策使用不同维度。首字、TPS、请求成功/失败、失败耗时和首字分布按 `(渠道, 模型)` 聚合，同一渠道模型在任何分组产生的请求都会进入同一份观测数据；原始日志仍保留请求实际使用的分组，便于审计。评分、候选集合、主渠道、优先级、权重、稳定性保护、管理员固定和执行记录仍按 `(分组, 模型)` 独立，因此多个调度池可以读取同一份渠道模型观测数据，但根据各自策略得到不同结果。

每个共享观测键还保存一个持久化的 `observation_since`。智能调度和渠道监控主表的实际统计起点统一为 `max(配置窗口起点, observation_since)`。该字段只是当前计算和展示的可见边界，不删除原始样本、业务日志或分钟聚合；稳定性恢复时推进一次边界，所有读取同一 `(渠道, 模型)` 的分组从同一时刻重新积累数据。

## 配置与参与

全局只保存开关、调度间隔、统计窗口和分组策略列表。每个分组策略都必须完整配置：

- 调度指标：综合评分、成本倍率、首字时间或 TPS。
- 应用方式：只调整权重，或优先级分层后再调整权重。
- 模型范围；空列表表示该分组全部模型。
- 最少样本、稳定性软评分、保护失败窗口、连续/窗口失败阈值、恢复条件、失败耗时惩罚和冷却时间。
- 是否在稳定性降级期间定时探测；默认关闭，开启后复用当前分组的探测间隔。
- 首字抖动免罚比例、固定慢成功阈值、主渠道目标流量和切换分差。
- 样本补充方式：关闭、探索流量或定时探测。
- 样本不足探索和稳定性释放分别配置最大预估 Prompt Token；配置为 `0` 表示无限制。

新增策略时页面会填入一套便于编辑的初始模板，但只有管理员保存的分组策略才生效；模板不是未配置分组的默认规则。

每条渠道、分组、模型路由还有独立的参与开关。首次初始化时现有路由均为不参与，需要管理员在渠道列、渠道详情或调度看板中明确开启。渠道列的开关批量修改该渠道所有路由，详情与看板可以修改单条路由。

禁用渠道、禁用 `Ability`、未参与路由和未命中策略模型范围的路由不会进入调度。关闭全局调度会停止新任务，运行中的任务也会因控制版本变化而停止后续写入。修改任意智能调度配置时，系统会在保存配置的同一事务内撤回旧配置产生的探索流量、低优先级轮转和稳定性试放流量：探索和轮转恢复基础路由值，试放恢复为 `P0/W0` 的降级保护；现有降级保护和固定主渠道意图继续保留，仍有效的固定主渠道会在同一事务内重新置顶。数据库配置或清理失败时整笔保存回滚，下一轮任务再按新配置重新决策。

智能调度配置保存使用控制版本比较并交换。接口返回控制版本，管理端打开表单时保存并在提交时原样带回；同一旧版本的并发请求或之后提交的旧标签页只有第一笔成功。旧请求返回 HTTP `409` 时，当前节点同时从数据库刷新配置缓存，管理端刷新数据并关闭旧表单，重新打开后可立即重试。多实例中，新版本请求若命中仍持有旧配置缓存的节点，该节点必须先从数据库刷新完整智能调度配置，不能仅更新控制版本后继续使用旧策略。数据库提交成功后才同步 Redis 429 冷却版本；若 Redis 同步失败，接口明确提示“设置已保存但冷却同步失败”，写入管理审计，并禁止创建本次强制重置任务，管理员可重新打开设置完成同步。

## 四种评分策略

| 策略 | 业务得分 |
| --- | --- |
| 综合评分 `smart` | 按配置占比综合成本倍率、首字时间和 TPS；启用且占比大于 `0` 的指标都必须达到最少样本 |
| 成本倍率 `ratio` | 成本倍率必须存在；首字和 TPS 有足够可比样本时按配置占比加入，否则对可用指标重新归一化 |
| 首字时间 `first_token` | 首字越快得分越高，必须达到最少样本 |
| TPS `tps` | TPS 越高得分越高，必须达到最少样本 |

每个指标的原始观测值按渠道模型共享，再只和当前调度池或当前优先级队列中的候选做 `0..1` 归一化。所有候选渠道指标相同时得到相同分数。评分本身只描述渠道表现，评分后的主渠道确认和流量分配使用下一节的独立规则。

智能调度看板和执行记录会保留并展示本轮评分的完整快照：各指标的执行时输入、样本数、同池最小值/最大值和有效渠道数、配置权重、缺失指标剔除后重新归一的有效权重、分项贡献、业务得分、稳定性贡献与最终得分。成本倍率和首字使用 `(同池最大值 - 当前值) / (同池最大值 - 同池最小值)`，TPS 使用 `(当前值 - 同池最小值) / (同池最大值 - 同池最小值)`；同池值完全相同时统一按满分处理。业务得分是各项 `归一化得分 × 有效权重` 之和。

启用稳定性保护后，最终得分为：

```text
最终得分 = 业务得分 × (1 - 稳定性占比) + 稳定性得分 × 稳定性占比
```

稳定性占比设为 `100%` 时不再要求业务指标。关闭稳定性保护时只使用业务得分。

## 优先级与权重

只有全局智能调度开启、当前 `(group, model)` 命中有效策略且池内至少有一条参与路由时，下面的智能重试队列才生效；否则继续使用渠道菜单默认 P/W 和官方原有重试行为。

每个比较队列会选出一个当前主渠道。首次计算选择最高分；同分时优先保留当前主渠道，没有现任主渠道时按渠道 ID 稳定选择。新渠道必须先达到最少样本。为了避免轻微波动反复冲掉上游缓存，挑战渠道只有在得分至少高出“主渠道切换分差”时才会接管；强制重置会直接选择本轮最高分。当前主渠道被禁用、退出参与或进入稳定性降级后会立即退出候选，不受切换分差限制。

“只调整权重”保留现有优先级，并且只在同一优先级内比较渠道。当前主渠道取得配置的目标流量，可配置范围为 `51%..99%`，默认 `90%`；剩余流量按其他渠道的最终得分比例分配。内部使用总计 `1000` 的权重单位和稳定的最大余数分配，预计占比直接对应配置。低优先级仍遵循原有规则，最高优先级有可用渠道时不会收到正常用户请求。

“优先级分层 + 权重”按得分和主渠道切换保护建立唯一主备顺序。若池内有 `10` 条正常参与路由，就生成 `10` 个从高到低的基础优先级；同分时使用稳定顺序，避免无意义抖动。管理员固定只把固定渠道的当前应用优先级提升到最高层，不改写评分生成的基础排名和基础路由值；固定期间继续更新自动排名，解除或到期时立即恢复基础值。正常首请求只进入当前最高优先级；智能调度开启时，失败请求按当前 `(group, model)` 的有效路由顺序进入后续优先级，当前轮所有可用渠道都尝试过且普通 `RetryTimes` 仍有余额时回到队首。稳定性降级路由统一进入最后兜底层 `P0/W0`，不占正常排名，但在重试到最后时仍可兜底。

预计流量只计算当前最高优先级内可用渠道的 `权重 / 权重总和`。备用优先级显示为 `0%`，只有更高优先级全部不可用时才会接管请求。

同一优先级内仍按权重选择；本轮已经尝试过的渠道暂时排除，按权重无放回地尝试同层剩余渠道。只有 A 一条渠道时，失败重试顺序仍为 `A -> A -> A ...`；当前没有任何真正可用渠道时直接结束，不因循环队列空转。快速失败同渠道重试使用独立额度，先于普通队列执行，不消耗普通 `RetryTimes`。请求为 `auto` 分组时，先按现有自动分组规则确定当前分组，再应用该分组队列，不把不同分组的 P/W 混成一条队列。

“本轮全部候选已尝试”才会回到队首；“候选集合为空”则直接返回无可用渠道。

错误是否允许普通重试仍由现有错误分类、`skip_retry`、指定渠道限制和剩余 `RetryTimes` 决定；智能调度不会绕过这些条件。

## 保本兜底层

智能调度使用换算后的成本倍率判断经济身份：

```text
成本倍率 = 上游倍率 × 换算系数
```

当 `abs(成本倍率 - 分组倍率) <= 1e-9` 时，该 `(渠道, 分组, 模型)` 路由属于零毛利的“保本兜底”。判断使用基础 `GroupRatio`，不使用请求用户相关的 `GroupGroupRatio`；成本倍率高于分组倍率时仍执行既有倍率过高策略，不由保本规则接管。

自动调度使用固定的经济层级：

```text
正常评分层 P2+
保本兜底层 P1
稳定性降级层 P0/W0
```

正常路由与保本路由分别建立归一化范围。保本路由不参与正常选主，也不会获得样本不足探索流量或低优先级轮转提权；正常层存在时，P1 的预计流量为 `0%`。正常层全部不可用或池内只有保本路由时，P1 自动成为最高可用层并继续提供服务。多个保本路由共享 P1，并按性能与稳定性得分分配层内权重；样本不足时保留上一轮基础顺序并按渠道 ID 保证确定性。

“只调整权重”模式也会为经济安全保留优先级例外：保本路由统一移动到 P1；若正常路由的最低优先级小于 P2，则统一抬升正常路由的绝对优先级，但不改变它们之间的相对层级。“优先级分层 + 权重”模式下，正常基础排名最低从 P2 开始，所有保本路由固定在 P1。

管理员固定不受保本身份限制。保本路由可以直接固定为主渠道，固定结果覆盖 P1 自动层级；固定解除或到期后，下一轮调度重新把仍为零毛利的路由放回 P1。固定期间是否允许稳定性降级继续遵循原有选项。稳定性恢复时会重新应用当前经济身份：仍为保本则恢复到 P1，已经恢复盈利才重新进入正常评分层。

调度看板和执行记录会展示成本倍率、分组倍率、倍率差与经济身份，并区分“保本兜底”“保本兜底 · 接管中”和“保本兜底 · 已手动固定”。

倍率、成本换算、分组倍率、渠道分组关联或调度参与状态变化后，系统会请求一次立即调度；运行中的调度任务会保留一个后继任务。成本倍率与分组倍率读取使用同一个经济快照，并由 `ChannelMonitorEconomicRevision` 保护写入。若任务计算期间经济修订号变化，旧计划不会写入 `Ability`，对应调度池保留上一轮结果并由后继任务重新计算。

## 重试与特殊路由上限

分组策略保存两个独立的预估 Prompt Token 上限：

| 字段 | 默认值 | 适用路由 |
| --- | ---: | --- |
| `exploration_max_prompt_tokens` | `16384` | 样本不足探索流量 |
| `stability_release_max_prompt_tokens` | `0` | 稳定性释放 `P0/W10` |

上限不是请求次数、QPS、计费上限或硬性拒绝条件。每次新请求和普通重试选路前，优先使用已解析的 Prompt Token 估算，无法取得时可按请求体大小估算；若估算值超过某类路由的上限，就把该特殊路由从本次优先候选中后移，优先使用普通或未超限候选；过滤后没有其他候选时仍允许它兜底。配置为 `0` 或无法取得估算值时不做该类过滤。

请求已经选中渠道并发往上游后，即使后续精确 Token 估算超过上限，也继续当前请求，不中途切换；只有下一次重试重新执行软过滤。稳定性降级 `P0/W0` 不使用这两个上限；定时探测和管理员手动测试默认不受真实业务上限过滤。完整场景和验收顺序见《智能调度产品需求文档》第 16.8、16.9 节。

## 管理员固定主渠道

管理员可以对某个 `(group, model)` 调度池手动指定主渠道，固定时间以分钟计。固定操作会先保存该路由当前的优先级和权重，立即把它提升到池内常规路由的最高优先级之上并设为权重 `1000`。智能调度已启用时还会触发一次调度任务，后续按当前应用方式维持主渠道：“只调整权重”保留它的独占最高层；“优先级分层 + 权重”中，样本不足探索或低优先级轮转可以临时提升到固定渠道同一优先级，并按配置取得小比例流量，固定渠道仍是实际主渠道并保留剩余大部分流量。固定期间它不会因为其他渠道得分更高而被替换。

同一 `(group, model)` 调度池同时最多只有一条管理员固定路由。对另一条路由设置固定时，系统会先解除并恢复该池之前的固定路由；对当前固定路由重新设置会同时更新“允许稳定性降级”选择，并从本次操作时间重新计算到期时间。设置 `0` 分钟会立即解除；后台每分钟清理一次到期状态，调度执行或调度看板刷新时也会再次检查。若到期时路由正处于稳定性保护，系统会结束固定意图并保留当前安全状态；否则恢复固定前保存的值。

固定主渠道不会绕过渠道状态和参与约束。禁用的渠道或 `Ability`、已退出参与的路由不能新设为固定主渠道。若目标路由当前正处于稳定性降级或试放，页面先显示风险确认；管理员确认后原子解除当前保护并完成固定。固定期间若渠道或对应 `Ability` 被禁用，原有选路会立即排除它，并在同一事务内撤回池内探索或低优先级轮转提权，避免临时路由独占最高层；未到期的固定意图继续保留，重新启用后立即恢复。若退出参与、移出分组模型池或删除，系统会清理已经失效的固定路由状态并撤回临时提权。

“允许稳定性降级”默认开启。开启时，固定期间仍持续采集稳定性样本；连续失败或保护失败窗口内累计失败达到策略阈值时会立即进入保护，并同时撤回池内探索和低优先级轮转提权。分钟级稳定性评分只影响排名和流量，不单独触发降级。固定的到期时间和选主意图不会被清除；若路由在固定到期前恢复，它会重新作为该池的固定主渠道。保护时间不会暂停或延长原固定期限。

关闭“允许稳定性降级”表示严格固定。系统仍计算并展示稳定性样本、分数和异常，但在固定期内不会因运行时失败自动进入硬保护。手动解除或固定到期后，后续上游失败重新按正常的连续失败与保护失败窗口规则判定。

## 样本补充

低优先级或新渠道可能长期拿不到用户请求，因此每个分组可以选择一种样本补充方式。

### 关闭

不主动制造请求或流量。缺少必需样本的路由保持当前优先级和权重并记录跳过原因，需要通过真实业务流量获得样本。

### 探索流量

仅支持“优先级分层 + 权重”。同一调度池一次选择一条缺少样本的路由，把它临时提升到当前最高优先级，并按配置比例计算一个小权重；其他等待路由保持原值。样本补足后恢复临时值，再交给正常评分。调度取消、策略变化或路由退出参与时也会恢复探索前值。

### 定时探测

系统按分组配置的间隔，为到期渠道模型发送一个很小的流式 `POST /v1/responses` 文本请求，`max_output_tokens` 固定为 `16`。正常路由和稳定性试放路由由 `sample_mode=probe` 开启探测；稳定性降级路由只有在分组开启 `degraded_probe_enabled` 时才探测，因此关闭常规样本补充并不影响单独启用降级探测。同一渠道模型同时关联多个符合条件的分组时只发送一次，使用最短探测间隔，并把结果保存为一份渠道模型共享样本。分组采样方式只决定是否为该渠道模型生成探测请求，不限制其他关联分组读取已经产生的共享样本。只探测本地明确支持 Responses 转换的文本渠道；图片、音频、视频、嵌入、重排以及不支持该协议的渠道会跳过，不记失败样本。

每次请求前都会重新检查全局开关、分组策略、模型范围、渠道状态、路由状态和参与状态。探测与普通请求共用渠道并发限制；并发已满时直接跳过，成功取得配额后会在探测请求期间占用一个并发名额。任务取消会中止后续请求。

成功探测会写消费日志并进入渠道成本统计，日志带专用探测标记并保留实际发起请求所用的分组；真实发出的失败探测写带同一标记的错误日志。成功和失败的定时探测结果都直接进入渠道模型共享样本，即使未开启普通消费日志或错误日志，探测样本仍可供所有关联调度池评分。探测日志不会进入普通业务分钟统计，避免同一请求同时作为业务流量和探测样本计算。没有真正发出上游请求的本地转换或配置错误只记为跳过，不伪造失败与成本。

降级探测成功会累计恢复探测连续成功次数；实际到达上游的非 429 稳定性失败会清零该次数，并把降级截止时间滚动到“本次失败时间 + 分组冷却时间”，不再等待连续失败或保护失败窗口阈值。达到分组配置的恢复探测成功次数后，下一轮调度即使尚未到达降级截止时间，也会恢复保护前保存的优先级和权重；未开启该开关时，降级路由仍按原流程等待冷却结束后进入稳定性试放。429 仍只进入独立的限流冷却，未实际发出的探测仍按跳过处理，二者都不续期稳定性降级。

正常参与路由和探索流量发生真实上游失败时，系统立即更新同一 `(渠道, 归一化模型)` 的运行时保护状态；连续失败达到阈值，或保护失败窗口内累计失败达到阈值，就立即把命中策略的路由降为 `P0/W0`，不等待分钟聚合、下一轮任务或最少样本。成功请求只清零连续失败数，不会提前删除仍处于滚动窗口内的失败。稳定性试放中的任意有效失败直接重新降级；降级期间的恢复探测失败直接续满冷却。生产请求、管理员手动渠道测试和智能调度定时探测只要请求确实到达上游，都进入同一判断；普通自动渠道维护测试、本地跳过错误和最终重试汇总不触发。Redis 可用时保护失败窗口由所有实例共享，Redis 失败时回退当前节点内存窗口；连续失败仍是节点内的快速信号。

429 不计入稳定性保护，而是按全局配置进入短时 `(渠道, 模型)` 冷却；冷却期间所有分组的新选路和已有渠道亲和命中都会跳过该渠道模型。Redis 可用时，冷却截止时间保存在 Redis 并由所有实例共享；Redis 未启用、访问失败或共享状态接管失败时使用当前节点的内存状态兜底。相同渠道模型再次收到 429 只会把截止时间延长到更晚时间，不会缩短已有冷却。冷却写入和运行时稳定性保护都校验请求读取到的调度控制版本；管理员修改任意智能调度配置后，新修订会统一隔离旧的保护窗口并清空本地与 Redis 冷却，仍在途的旧请求不能重新创建已清理的冷却或覆盖新配置路由。多实例并发保存配置时，Redis 版本只接受数据库当前控制版本，较早请求不能在数据库提交顺序之后反向覆盖较新的版本或误清空新冷却；选路只读取与当前本地控制版本一致的 Redis 冷却，其他修订的数据一律忽略。Redis 丢失版本键或恢复旧快照时，收到新 429 的实例会重新校验数据库控制版本，再通过 Redis 比较并交换接管共享状态、清除归属不明的旧冷却并写入本次冷却；比较失败时不会覆盖并发产生的新状态。

渠道亲和只在池内存在至少一条已参与且未取消参与的智能调度路由时受最高优先级约束；仅有已取消参与状态的池继续使用官方亲和行为。开启内存缓存后，该判断直接使用渠道缓存快照，请求过程中不额外查询数据库。缓存刷新在一个数据库事务中读取 Channel、路由状态和 Ability，完整构建后一次替换；读取失败时继续使用上一份可用快照。

手动渠道连接测试与自动采样方式解耦。全局智能调度已启用、测试能确定原始模型，且至少存在一条已配置、未禁用并正在参与调度的对应分组模型路由时，每次测试只写一份渠道模型共享样本；所有关联调度池都可读取，不按分组复制。`关闭`、`探索流量` 和 `定时探测` 三种模式都适用，稳定性降级中的参与路由也可以通过手动测试积累恢复数据。成功记录可取得的流式首字时间和 TPS，失败记录失败耗时与错误；非流式测试只补成功或失败，不把完整响应耗时当作首字时间。

手动测试仍只写原有的一条模型测试消费日志并进入渠道成本统计，不会额外写探测消费日志。模型测试日志带独立标记，不进入普通业务分钟统计，因此同一次测试不会同时作为业务样本和探测样本重复计算。

## 稳定性得分

稳定性不再把每次错误都当作相同损失：

- 用户请求最终失败按 `100%` 失败惩罚计算。
- 中间重试失败根据该次上游耗时计算。耗时不超过“快速失败界限”时只扣配置的快速失败惩罚；从快速界限到慢失败界限之间线性增加；达到慢失败界限后按 `100%` 惩罚。
- 无法取得精确耗时的中间失败按快速失败惩罚处理。

```text
稳定性得分 = 1 - (最终失败完整惩罚 + 重试失败耗时惩罚 + 超额抖动惩罚) / 总样本数
```

这样，偶发且很快完成切换的上游错误不会和长时间卡住或最终失败等价。

分组策略还可以设置“同渠道快速重试”，范围为 `0..10` 次，默认 `0` 次（关闭）。只有错误本身符合现有重试规则、没有被归类为客户端断开、没有 `skip_retry` 或指定渠道限制，并且本次上游失败耗时不超过“快速失败界限”时才使用这份额度。快速失败同渠道重试不会增加普通 `RetryTimes` 计数，也不会把当前渠道加入本轮排除列表；额度用尽后，下一次可重试失败才消耗普通重试次数并切换渠道。普通重试选中新的渠道访问后，同渠道快速重试计数重新开始。实际尝试序号仍逐次增加，因此覆盖模板、错误日志和重试观测能正确识别这些请求为重试。

## 首字抖动

开启抖动保护时，系统按成功流式请求的首字延迟分布计算 P50、P95 和 P95 截尾平均值。业务首字评分使用截尾平均值，极少数超慢请求不会直接把平均值拉高。

慢成功直接按固定首字阈值判定，不学习或叠加历史基线。阈值单位为秒，默认 `10` 秒；达到阈值的请求仍然是成功请求，只参与抖动处罚。实际请求失败上限由“上游响应等待时间”控制。

```text
慢成功 = 首字耗时 >= jitter_slow_threshold_seconds
允许慢请求数 = 允许比例为 0 时取 0，否则 max(1, floor(成功流式首字样本数 × 允许抖动比例))
```

允许比例大于 `0%` 时，达到最少样本的有效窗口至少允许一次慢请求；设为 `0%` 时则不保留这一次容差。默认允许比例为 `5%`，因此 `20` 个成功流式首字样本允许 `1` 次慢成功，`40` 个样本允许 `2` 次；这是根据比例计算，不是写死为每 `20` 个样本一次。只有超过允许数量的部分才从稳定性得分中扣除。

## 降级、试放与手动恢复

正常路由连续失败达到阈值，或保护失败窗口内累计失败达到阈值时：

1. 保存进入保护前的完整优先级和权重。
2. 把该分组模型路由降为 `0/0`，进入冷却；若开启降级期间定时探测，连续成功达到恢复要求时可在冷却到期前直接恢复，每次实际到达上游的非 429 稳定性失败则从失败时刻重新计算完整冷却时间。
3. 未提前恢复时，冷却结束后进入 `P0/W10` 稳定性试放；只有所有更高优先级都不可用时才接收少量兜底流量，也可通过手动测试和常规定时探测积累恢复样本。
4. 只统计试放开始后的新样本。任意实际到达上游的非 429 稳定性失败立即重新降级；连续成功达到恢复要求，或新样本稳定性评分达到恢复参考值时，恢复完整保存值。
5. 自动恢复或管理员手动解除保护时，把恢复时刻写入共享 `(渠道, 模型)` 的 `observation_since`，并清除恢复前的运行时失败队列、连续失败数和恢复成功数。后续性能评分、稳定性计算、智能调度看板和渠道监控主表只读取边界后的新数据；尚无新数据时显示样本数 `0` 和 `-`，不能显示成 `0%`。恢复前的原始样本、日志和分钟聚合仍保留，继续供历史明细、按日趋势、长期模型统计以及成功率和缓存率历史统计使用。

分钟级稳定性评分只参与正常排名、流量分配和试放恢复参考。即使评分低于兼容字段 `degrade_stability_score`，只要近期失败没有达到硬保护阈值，正常路由也不会进入 `P0/W0`。该兼容字段继续保存和回显，但不再约束恢复评分。关闭稳定性保护或暂时没有可用稳定性数据时不会自动释放已有保护状态。

渠道列、渠道详情和调度看板中的“稳定性降级”或“稳定性试放”标签可以直接点击。确认后会立即恢复保护前保存的优先级和权重、清除保护状态，并推进共享观测边界；该操作不改变参与选择。

## 执行与审计

智能调度按全局间隔运行，也可以在看板中立即执行。设置中的“强制重置优先级和权重”是一次性命令：本轮从基线重新计算已配置且参与的路由，不影响未配置分组。

任务历史保存每条调整的渠道、分组、模型、旧值、新值、得分、动作和原因。每条明细还记录不可变的执行时评分快照，以及“原主渠道、评分第一、最终主渠道、切换分差、主渠道目标流量、选择原因、调整原因”，因此后续样本或配置变化不会改写历史解释。固定路由还记录执行时该路由是否为管理员固定主渠道、固定到期时间及是否允许稳定性降级；管理员设置、续期或解除固定的操作本身也会把固定时长、到期时间和该选项写入管理审计。页面通过单独的“执行记录”入口查看调度批次，并可按分组、模型、渠道和动作筛选明细。运行期间若管理员修改开关或策略，后续结果会因控制版本或路由修订号不一致而拒绝写入；固定主渠道等必须重算的操作遇到正在运行的调度时，会保留当前任务并只排入一个后继任务，确保新状态最终被重新计算。已实际修改过路由值时会刷新渠道缓存。任务结束时，终态、结果摘要、完整执行明细和任务租约删除在同一数据库事务提交；任一步失败都会整体回滚，避免页面看到已完成任务却缺少明细，或任务已完成但租约仍残留。

智能调度配置中的性能窗口和稳定性评分窗口都接受 `1..43200` 分钟。智能调度实际启用时，渠道监控主表的“近 N 分钟”由性能窗口接管，页面隐藏手动分钟输入，查询允许使用完整的 `1..43200` 范围；智能调度关闭时才显示手动输入，并继续限制为 `1..1440` 分钟。后端返回实际采用的 `range_minutes` 和 `range_source=smart_schedule|manual`，页面以返回值为准。两种模式都继续应用 `observation_since`，且不影响按日统计、历史明细和长期模型统计。稳定性硬保护另用分组策略中的秒级保护失败窗口，不读取分钟级评分窗口代替。

评分快照的 `sample_scope` 固定为 `channel_model`，`sample_group_count` 记录当前业务观测窗口实际覆盖的分组数。执行记录中的分组表示独立决策所属的调度池，不表示观测数据只来自该分组。
