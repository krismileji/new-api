# 智能调度

## 启用与参与

智能调度定时修改渠道的优先级和权重。首次从关闭切换为开启时，系统会先把所有渠道标记为“不参与”，需要管理员逐个确认参与，避免启用开关立即改写现有路由。

渠道加入时可以重置为探索基线；退出时如果正处于稳定性降级，会恢复降级前保存的优先级和权重。

禁用的渠道、不参与的渠道、没有所需模型或样本不足的渠道不会按正常评分分配流量。样本不足但符合参与条件的渠道使用优先级 `80`、权重 `10` 进行探索。

## 调度策略

| 策略 | 评分方向 |
| --- | --- |
| 智能调度 `smart` | 按可配置占比综合成本倍率、平均首字时间和平均 TPS，默认 `40% / 40% / 20%` |
| 按成本倍率 `ratio` | 按可配置占比综合成本倍率、平均首字时间和平均 TPS，默认 `70% / 20% / 10%` |
| 按首字 `first_token` | 平均首字时间越低得分越高 |
| 按 TPS `tps` | 平均 TPS 越高得分越高 |

两组百分比各自必须合计为 `100%`。指标占比配置为 `0%` 时，智能调度不再要求该指标达到最少样本。按成本倍率调度的成本倍率占比必须大于 `0%`；性能指标样本不足时，仅使用当前可用指标并按其配置占比重新归一化。

开启稳定性保护后，成功率按可配置占比参与最终得分，默认占 `50%`；所选调度策略的业务得分使用剩余占比。稳定性占比设为 `100%` 时不再要求业务指标。稳定性同时承担准入、降级和恢复判断。

```text
最终得分 = 稳定性得分 × 稳定性占比 + 业务得分 × (100% - 稳定性占比)
```

## 应用方式

“只调整权重”保留现有优先级，只在同优先级渠道间重新分配权重。

“优先级分层 + 权重”先按得分分为 `100`、`90`、`80` 三档，再计算权重。目标权重限制在 `10` 到 `100`，并通过步进和单次变化限制减少频繁抖动。

得分映射权重前可以配置曲线指数，范围为 `0.1..5`，默认 `1`：

```text
权重得分 = 最终得分 ^ 曲线指数
```

指数 `1` 为线性映射；大于 `1` 会放大渠道差距。旧版单指标调度的固定立方映射相当于指数 `3`。

调度结果同时更新渠道表和能力缓存对应的优先级、权重，完成后刷新渠道缓存。

## 模型与样本

统计窗口可选近 `15` 分钟、`1` 小时、`6` 小时或 `24` 小时。最少样本数范围为 `1` 到 `100000`。

可以按优先级配置多个基准模型。每个渠道使用它支持的第一个基准模型；一个都不支持时跳过该渠道。未配置基准模型时汇总渠道全部模型的指标。

## 稳定性保护

稳定性保护要求同时开启消费日志和 `ERROR_LOG_ENABLED`。成功率按以下口径计算：

```text
实际成功率 = 成功调用数 / (成功调用数 + 渠道错误数)
```

重试过程中的失败也属于真实渠道错误，会进入稳定性样本。样本达到最少要求且成功率低于阈值时：

1. 保存当前优先级和权重。
2. 将渠道降为优先级 `0`、权重 `0`。
3. 保持到配置的冷却时间结束。
4. 恢复保存值并进入试放状态，只统计试放开始后的新样本。
5. 新样本达标则退出保护；仍不达标则再次降级。

关闭智能调度、关闭稳定性保护或发现无效状态时，系统会恢复被保护渠道原来的优先级和权重，并清理稳定性状态。

## 上游响应等待

“上游响应等待时间”限制每次上游请求等待 HTTP 响应头的时间，范围为 `0..600` 秒，`0` 表示不限制。超时后本次渠道请求失败，并交由现有重试、渠道亲和及渠道切换规则处理。

收到响应头后计时立即停止，不限制后续响应正文或流式输出时长。该设置会即时影响后续请求，普通渠道客户端和渠道代理客户端使用相同配置。

## 默认设置

| 设置 | 默认值 |
| --- | ---: |
| 开启智能调度 | 否 |
| 上游响应等待时间 | `0` 秒（不限制） |
| 调度间隔 | `10` 分钟 |
| 调度策略 | `smart` |
| 稳定性保护 | 否 |
| 稳定性占比 | `50%` |
| 智能调度指标占比 | 成本倍率 `40%`、首字 `40%`、TPS `20%` |
| 成本倍率调度指标占比 | 成本倍率 `70%`、首字 `20%`、TPS `10%` |
| 得分曲线指数 | `1`（线性） |
| 应用方式 | 只调整权重 |
| 统计窗口 | `60` 分钟 |
| 最少样本 | `5` |
| 最低成功率 | `80%` |
| 降级时长 | `30` 分钟 |

## 手动执行与重置

可以手动创建一次智能调度任务。保存设置时勾选“强制重置优先级和权重”，会创建一次性任务：先把符合条件的参与渠道重置到探索基线，再根据当前日志重新计算。

同类型任务已有运行中实例时，任务队列复用现有任务并返回 `created=false`，避免重复执行。执行结果记录策略、模型、窗口、计划数、更新数、跳过数和失败明细，可在任务记录中查看。
