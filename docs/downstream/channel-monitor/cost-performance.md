# 成本、性能与成功率

## 成本口径

渠道成本以本地分组倍率生效前的结算额度为基础，再应用渠道的人民币成本倍率：

```text
渠道成本(CNY) = 分组倍率前额度 / QuotaPerUnit × 成本倍率
```

这样统计的是获取上游额度的实际成本，不会把本地对用户设置的分组加价算入渠道成本。

文本、音频、任务和按次计费路径在获得权威用量或结算结果后记录成本。用量为估算值、缺少必要用量、换算溢出或结算信息不完整时，不猜测成本，而是增加“未解析”计数。

## 存储与聚合

成本按北京时间自然日聚合，金额以十亿分之一人民币的整数保存，避免浮点累计误差。写入先在内存中按渠道、日期和密钥归并，再批量写入数据库；批次写入有超时和有限重试。

概览接口支持 `1` 到 `90` 天窗口，默认 `30` 天。页面提供今日、昨日、区间累计，以及“成本趋势”“渠道汇总”“API Key 明细”三个视图；三个视图共用北京时间日期选择，日期明细按每页 `7` 天加载。渠道汇总展示当前备注、启停状态和成本倍率，并按启用优先、成本倍率升序排列。

接口继续保留未解析事件计数用于内部审计，但页面只展示已结算成本，不展示未解析计数或完整性提示。未解析事件不会混入已结算金额。

## API Key 归因

成本可以按入站 API Key 和实际选择的上游凭据拆分。数据库只保存入站 Key 的 ID/名称、上游凭据的 SHA-256 指纹和遮罩展示值，不保存完整凭据。

旧数据、管理端渠道测试或其他无法识别入站 Key 的成本显示为“未识别 API Key”，保证渠道总成本与 Key 视图之间的差额仍然可见。

## 数据保留

渠道日成本默认保留 `30` 天，路由分钟指标和延迟分桶默认保留 `30` 天，API Key 分钟明细默认保留 `7` 天。三类保留期都可在渠道监控设置的“数据保留”Tab 中独立配置，范围为 `1` 到 `3650` 天。独立系统任务按批次删除各自截止日期之前的渠道日成本、API Key 日成本、路由分钟指标、API Key 分钟指标和延迟分桶。

智能调度性能窗口会保护路由分钟指标和延迟分桶，不会因为配置了更短的路由保留期而删除仍在使用的窗口数据；API Key 分钟明细不参与调度评分，可以按独立的 7 天默认值清理。

系统任务按类型独立清理：渠道比例监控、智能调度、清理、模型检测、渠道测试和模型更新任务默认保留 7 天，智能调度探测任务默认保留 3 天；未分类任务使用 7 天兼容默认值。清理只删除已结束任务，`pending` 和 `running` 任务始终保留。

| options 配置                                      | 默认值 | 有效范围          | 说明                         |
| ------------------------------------------------- | -----: | ----------------- | ---------------------------- |
| `ChannelMonitorCleanupEnabled`                    | `true` | `true` / `false`  | 是否创建和续排保留清理任务   |
| `ChannelMonitorCleanupBatchSize`                  | `1000` | `1` 到 `10000`    | 单条删除语句的最大记录数     |
| `ChannelMonitorCleanupBudgetSeconds`              | `10`   | `1` 到 `300`      | 单轮清理任务的时间预算       |
| `ChannelMonitorCleanupContinuationSeconds`        | `60`   | `15` 到 `3600`    | 预算耗尽后的续跑等待秒数     |
| `ChannelMonitorCleanupIntervalMinutes`            | `1440` | `60` 到 `10080`   | 周期清理间隔，保存后下轮生效 |
| `ChannelMonitorRouteMetricRetentionDays`          | `30`   | `1` 到 `3650`     | 路由分钟指标和延迟分桶保留期 |
| `ChannelMonitorApiKeyMetricRetentionDays`        | `7`    | `1` 到 `3650`     | API Key 分钟明细保留期       |

关闭清理任务不会停止新成本写入，也不会自动删除已有数据。

## 性能指标

性能数据从消费日志聚合，按渠道和模型提供：

- 首字样本数、平均首字时间和最近首字时间。
- TPS 样本数、平均 TPS 和最近 TPS。
- 最后使用时间。

智能调度实际启用时，渠道监控主表查询窗口固定使用智能调度性能窗口，允许 `1` 到 `43200` 分钟；智能调度关闭时才使用页面手动窗口，允许 `1` 到 `1440` 分钟，默认 `15` 分钟。接口返回权威的 `range_minutes` 和 `range_source`。统计结果带生成时间并使用短期缓存，页面查询只读取分钟聚合表。

每个 `(渠道, 模型)` 保存稳定性恢复后的共享观测边界。主表性能、成功率和缓存利用率的实际起点取“配置窗口起点”和“共享观测边界”中的较晚者；恢复后尚无新样本时返回样本数 `0` 和空指标，页面显示 `-` 而不是 `0%`。边界只影响当前调度和主表展示，不删除分钟聚合、日志或原始样本，今日统计、按日趋势、历史明细和长期模型统计继续读取完整保留数据。

## 成功率与失败明细

成功率需要同时开启消费日志和错误日志。关闭任一项时，API 会明确返回 `success_metrics_available=false`，页面不会把缺失数据误显示为 `0%`。

两种口径分别为：

- 实际成功率：消费成功数与所有渠道错误数共同计算，包含重试过程失败。
- 最终成功率：排除 `is_retry_attempt=true` 的中间错误，反映用户最终结果。

缓存利用率按 `缓存读取 tokens / 总输入 tokens` 计算。所有消费成功日志的输入 tokens 都进入分母，包括没有缓存字段或缓存读取为 `0` 的请求；聚合时按 token 数量加权，而不是对单请求百分比取平均。无有效输入 token 时页面显示 `-`。

页面顶部的成功率/缓存利用率卡片同时展示缓存写渠道数与请求数，并可打开按日统计。弹窗使用一张双轴组合图展示成功率、缓存利用率与缓存写请求趋势，左轴为成功率和缓存利用率，右轴为缓存写请求数；顶部汇总依次展示请求数、成功率、缓存利用率、缓存写渠道数和写入请求数，渠道明细直接包含每个渠道的写入请求数，不再单独展示缓存写渠道明细。图表与明细共用近 `7`、`30`、`90` 天范围及北京时间日期选择；点击任一柱子或折线数据点都会切换全部明细日期。

成功率、缓存利用率、性能和按日趋势统一读取后台每分钟从日志生成的分钟聚合表，页面请求不会触发日志扫描。聚合任务在自然分钟结束 `1` 秒后只处理尚未越过 `completed_through` 的新分钟并推进水位；启动或中断后从持久化水位连续追赶，不重复回扫已完成分钟。迟到日志和跨分钟重试会幂等标记脏分钟，worker 小批领取后只替换对应一分钟，成功删除标记，失败释放租约并保留标记重试。路由分钟表按路由指标保留期清理，默认 `30` 天，API Key 分钟表按独立保留期清理，默认 `7` 天。

渠道明细可按模型过滤，并按 HTTP 状态码、错误类型和错误码聚合失败；分组明细提供总计和渠道拆分。错误示例会经过脱敏和长度限制。

## 关键实现

- `service/channel_daily_cost.go`、`service/channel_daily_cost_batcher.go`：成本采集和批量写入。
- `model/channel_daily_cost.go`、`model/channel_daily_api_key_cost.go`：日成本存储。
- `controller/channel_monitor_cost.go`：成本查询和展示模型。
- `model/channel_monitor_performance.go`：首字与 TPS 聚合。
- `model/channel_monitor_success.go`：实际/最终成功率和失败分类。
