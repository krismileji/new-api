# 余额预估与恢复

余额保护使用最近成功同步的上游余额，扣除尚未纳入该基准的完成消费和在途预估。它不读取日成本增量来推算余额，也不改变用户钱包或真实扣费。

## 计算与单位

```text
估算余额 = 上游余额基准 − 本轮已完成消费 − 进行中预估
```

各项统一使用上游额度单位。人民币成本须先除以配置的换算系数，不能直接当上游额度，也不能再次乘上游倍率。每次请求使用发起时的模型计价、倍率和换算参数。

例如余额 24，一笔请求预估 3 时显示 21；完成费用为 2 时移除预估 3、加入完成费用 2，显示 22。再次成功同步得到 22 后，该已完成消费被基准吸收；仍在执行的其他请求继续保留占用。

本地完成费用来自可信 usage 和本地计价，没有逐笔上游账单时不能承诺它与实际扣款完全相等。此估算针对请求结束后扣款的上游；预扣或延迟记账的接口须核对其余额语义。

## 在途费用来源

1. 优先使用同渠道、账户、模型及匹配计价配置的近期有效业务样本：最近 `30` 分钟、最多 `100` 笔，至少 `5` 笔后取平均。
2. 样本不足时使用已有输入估算和有界输出预算，按请求的计价表达式或旧倍率重新计算，去掉用户分组售价倍率，不假定未知缓存命中。用户钱包的免预扣门槛和输入预扣倍率不影响上游在途成本估算；图片数量采用本次实际发送前确认的数量。
3. 连预算也无法可靠计算时标记不完整，不把未知费用当作零。

样本包含实际缓存读写影响；探测、模型检测、未知费用和未确认完成的请求不训练业务均值，可信零费用可成为样本。新样本仅影响后续请求，已有请求保留发起时的预估。成功同步不清空仍有效的费用样本。

## 请求与余额同步

每次上游尝试开始时登记占用，费用确认后用实际消费替换预估，重复或迟到结果不再次扣减。明确未发往上游时释放；取消、异步提交、WebSocket 中间用量或缺少可信 usage 时，不能直接认定上游已完成。

未使用余额预估的渠道，在请求准入时确认未配置或未启用后，发送上游前不再单独查询余额配置，减少首字等待。此确认仅供当前渠道的本次准入短时使用，不缓存到后续请求；其他节点启用预估或关联共享账户后，新准入会重新确认。已启用预估、共享账户成员、配置异常或确认过期的请求继续检查当前账户配置；共享账户成员暂停自身余额同步仍须登记消费。

Responses WebSocket 按每次 `response.create` 登记未知在途费用，不套用普通 HTTP 输出预算或训练均值。收到该次请求的终止事件并取得可信成本后，移除其在途占用并记入完成消费；连接可继续使用。断开、缺少终止事件或用量仍无法确认时保留未确认状态。Realtime 的中间用量更新不表示整条上游连接已经结束。

成功同步后更新余额基准，忽略已过期的查询结果。新余额吸收可确认已包含的完成费用，保留真实在途。查询期间完成的费用可能已被上游扣除，单列为待确认，不能仅凭这部分费用触发余额不足禁用；下一次成功同步吸收。

失败查询不清零占用。Redis 启用但故障时，不接纳无法校验同步顺序的余额响应；显式无 Redis 时仍可保存原始余额，但本地预估不可用，不回扫日志或日账代替。

## 未确认及残留占用恢复

成功同步后，查询开始前已经结束的普通未确认请求，其占用可被新余额吸收；费用本身仍保留未解析状态，不伪造实际成本。

当余额查询前后都没有真实在途请求，并且可以确认请求已经结束时，系统会回收遗留占用。异步任务、WebSocket、无法判断类型的请求和查询期间新增的请求继续保留。失败或过期的余额响应不执行回收。

迟到的完成结果不会再次增加已吸收的消费。无法确认的请求会使估算标为不完整，不能仅凭等待时间经过就认定费用为零。

## 保护与恢复的区别

| 场景 | 判断 |
| --- | --- |
| 余额预警 | 仅控制页面和通知，独立于自动禁用阈值 |
| 常规监控自动禁用 | 估算可用且覆盖完整时使用有效余额；严格小于阈值才禁用，等于时不禁用 |
| 缺少可靠估算 | 可依据有效上游余额禁用，不能据此自动恢复 |
| 常规监控自动恢复 | 要求恢复开关、完整余额判断、对应自动禁用原因及成本倍率等条件 |
| 独立上游自动任务恢复 | 使用本轮成功复查的上游原始余额，不扣本地预估、不等待本地估算完整；仍要求恢复开关及倍率条件 |
| 人工禁用 | 所有自动路径均不覆盖 |

请求开始和结算都会触发异步余额检查。自动禁用不主动中断已在途请求，仍须完成结算和占用释放。对于 Responses 和 Realtime WebSocket，禁用后拒绝新的生成；当前生成的终止事件送达后关闭连接，空闲连接立即关闭。Realtime 在等待当前生成结束期间只接受取消生成和截断播放等结束控制，不再接收新的音频或会话修改；仅有语音输入缓冲、尚未开始生成的连接视为空闲。客户端收到关闭码 `1008` 后需重新连接，由系统选择可用渠道。自动任务具体行为见[上游自动任务](upstream-automation.md)。

## 共享账户与页面

关联[上游账户](upstream-accounts.md)后，多个成员共享余额基准和总占用，样本仍按匹配的物理渠道及计价配置隔离；某渠道暂停同步不应漏记其真实消费。解除关系后，在途仍结算到原余额池。

余额详情保留原始余额及同步时间，另展示完成消费、在途预估、边界待确认、估算余额、完整性、均值/预算/未知笔数和最近一次预估来源。共享账户余额不可按渠道重复相加。

预估异常时，先查看估算是否可用和完整、未知费用笔数、当前并发与最后同步时间。并发为零但预估非零可能是遗留占用，满足条件后会在成功余额同步时回收。
