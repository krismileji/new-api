# 利润统计

利润统计按「用户最终扣费 − 渠道总成本」计算人民币账面利润。渠道监控总览在「今日已结算成本」卡片内合并展示成本和利润，并展示用户扣费与利润率；点击卡片打开利润分析，包含成本、利润和扣费汇总及明细。渠道列表按渠道显示今日利润；打开利润分析可查看日期趋势，并按渠道、用户、API Key 和模型下钻。渠道行里的成本入口仍打开对应成本明细。

扣费按钱包或订阅分别汇总，人民币金额为「实际扣费额度 ÷ 每美元额度 × 美元兑人民币汇率」，使用请求中保存的换算快照。订阅显示额度消耗的折算金额，不代表订阅销售回款；本页利润属于账面毛利。退款和异步任务补扣会修正原请求的收入记录。渠道成本包含业务请求、失败重试、探测和模型检测成本，按物理渠道归属。

收入记录从启用该功能后开始累计，不会从历史消费日志回填。因此，功能启用前的日期会提示收入历史不可用。扣费或退款尚未确认、成本尚未入账、成本未解析或统计覆盖不完整时，利润显示「利润待确认」；Midjourney 退款会先将原收入标记为待确认，再执行额度退还，避免退款完成后进程异常导致利润仍计入已退款收入。「仅展示亏损行」只筛选已确认的亏损行。顶部汇总和趋势始终保留当前筛选范围内的完整结果。

收入明细跟随成本保留期限清理。超出保留范围的历史、成本队列积压、无法读取队列或隔离成本事件未处理时，均不会显示为已确认利润。队列状态属于共享状态，可能使其他渠道的利润暂时待确认。普通请求归入成本结算当天（北京时间）；跨日实时会话的逐次扣费在成本入账时统一归入会话结束日；异步任务的补扣与退款修正任务提交日。Midjourney 退款修正收入，成本仍沿用渠道已记录成本。收入写入缺口会持续标记待确认，不会因重启自动消除。

利润分析沿用渠道监控的 Root 管理权限。接口为 `GET /api/channel_monitor/analytics/rows?metric=profit`，支持现有的日期、渠道、用户、API Key、模型和搜索筛选；`sort` 支持 `income`、`cost`、`profit`、`profit_rate`，`only_loss=true` 仅返回已确认的亏损行。统计区间最多 90 天，收入为零时利润率为空。

启用时先让主节点完成数据库迁移，再启动其他节点。可靠成本队列使用现有 `CHANNEL_DAILY_COST_RELIABLE_OUTBOX` 配置，关闭后利润始终待确认。功能启用当天因起始时刻之前没有收入记录，也会标记待确认；之后的完整日期可正常确认。
