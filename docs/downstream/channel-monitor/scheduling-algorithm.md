# 智能调度算法

智能调度按分组 + 模型维护候选池，用当前观测窗口的成本倍率、首字时间、TPS 和稳定性计算分数，再按经济分类、保护状态和应用方式改写优先级与权重。没有托管策略时，系统回退到原有 Ability 和渠道优先级/权重。

本文对应当前实现：`controller/channel_ratio_monitor_schedule*.go`、`controller/channel_ratio_monitor_schedule_scoring.go`、`controller/channel_ratio_monitor_schedule_economics.go`。页面行为见[智能调度](smart-scheduling.md)。

## 调度准入

只有同时满足以下条件的路由进入下游托管池：

- 该分组已配置策略，且智能调度总开关开启。
- 路由显式标记为参与。
- 渠道启用，路由未暂停。
- 渠道具备该模型能力。

禁用、暂停、未参与、能力不足或 429 冷却中的路由会被排除。逻辑归组先选择逻辑候选，再在冻结成员中选择物理渠道。

策略字段会校验范围和组合关系，旧版已废弃字段会被拒绝。分组策略最多 `100` 个。

## 策略与默认值

策略支持 `smart`、`ratio`、`first_token`、`tps`，应用方式为 `weight` 或 `priority_weight`。采样模式为 `off`、`traffic`、`probe`。

前端/规范化默认值：

| 字段 | 默认 | 含义 |
| --- | ---: | --- |
| 稳定性窗口 | `5` 分钟 | 稳定性统计窗口 |
| 性能窗口 | `60` 分钟 | 业务指标窗口，范围 `1..43200` |
| 最少样本 | `5` | 首字、TPS、稳定性可比较的下限 |
| 稳定性占比 | `50%` | 最终分中稳定性的权重 |
| 主渠道目标流量 | `90%` | 范围 `51%..99%` |
| 主渠道切换分差 | `3%` | 备用渠道需要超出的分数门槛 |
| 快速失败惩罚 | `20%` | 可重试失败的基础惩罚 |
| 快速失败时限 | `1s` | 不超过该耗时按基础惩罚计 |
| 慢失败时限 | `10s` | 达到该耗时按 `100%` 惩罚计 |
| 连续失败阈值 | `2` | 进入稳定性保护 |
| 恢复成功阈值 | `2` | 试放后恢复 |
| 冷却时间 | `30` 分钟 | 降级后进入试放前的冷却 |
| 降级期间定时探测 | 开启 | 降级期间主动探测，达到恢复成功阈值后可提前恢复 |
| 探索流量 | `3%` | 样本不足渠道的流量上限 |
| 自适应采样基础/上限 | `10%` / `30%` | 健康压力升高时扩大采样 |
| 429 冷却 | `30s` | 全局默认，范围 `0..300` 秒 |

`smart` 默认业务权重：成本 `40%`、首字 `40%`、TPS `20%`。`ratio` 默认：成本 `70%`、首字 `20%`、TPS `10%`。`ratio` 的成本占比必须大于 `0`。

## 评分公式

候选先在同一分组模型池内做归一化。成本倍率和首字是“越小越好”，TPS 是“越大越好”：

```text
lower_is_better(value) = (max - value) / (max - min)
higher_is_better(value) = (value - min) / (max - min)
```

当 `max - min` 过小（epsilon `1e-9`）时，该项得分为 `1`。某项要参与比较，必须：

- 该候选有值，且样本数达到 `min_samples`（成本倍率除外，它来自渠道记录而不是请求样本）。
- 同池可比较渠道数不少于 `max(min_comparable_channels, 2)`，默认 `2`。

业务分是可用项的加权平均，权重按策略类型取 `smart` 或 `ratio` 的三项占比；不可用项不进入分母：

```text
business = Σ(score_i × percent_i) / Σ(percent_i)
```

`first_token` / `tps` 策略只使用对应单项。如果开启稳定性且稳定性占比小于 `100%`，才需要业务分；稳定性占比为 `100%` 时可以没有业务指标。

最终分：

```text
final = (1 - stability_weight) × business + stability_weight × stability
stability_weight = stability_percent / 100
```

未开启稳定性，或稳定性样本不足时，`final = business`。分数裁剪到 `[0, 1]`。手动固定主渠道即使没有业务指标也会保留评分记录，但不拿零分去和普通候选比较。

## 稳定性分

稳定性分使用成功数、失败数、最终失败数和失败耗时分桶：

```text
sample = success + failure
penalty = final_failure
       + Σ(retry_failure_bucket_count × retry_penalty(duration))
stability = 1 - penalty / sample
```

可重试失败的惩罚：

- 耗时 `<= fast_failure_seconds`：`fast_failure_penalty_percent / 100`
- 耗时 `>= slow_failure_seconds`：`1`
- 中间线性插值

缺少分桶的可重试失败按耗时 `0` 处理，即按快速失败惩罚计。首字抖动惩罚按超过慢阈值的样本数减去容忍数量，再均摊到样本上，并从稳定性分中扣除。

## 经济分类与保本兜底

成本经济分类比较渠道成本倍率和分组倍率，epsilon 为 `1e-9`：

| 角色 | 条件 | 调度位置 |
| --- | --- | --- |
| `normal` | 成本倍率明显低于分组倍率 | 正常层，至少 P2 |
| `break_even_fallback` | 差值在 epsilon 内 | 独立 P1 保本层，不能当正常主渠道 |
| 未知 | 缺少成本或分组倍率 | 不参与正常调度 |

保本渠道只在正常候选不可用时接管。同一层内仍按配置的权重和优先级选路。`weight` 模式按分数分配权重；`priority_weight` 先分层再在层内按权重分配。

## 稳定性保护与试放

请求事件会更新稳定性状态。连续失败或突发失败超过阈值后，路由进入降级；冷却到期后进入小流量试放（`probing`），成功达到恢复阈值后解除保护。管理员可在页面确认后立即清除稳定性或探索状态。

试放和探索受 `exploration_max_prompt_tokens`、`stability_release_max_prompt_tokens` 限制。大请求不会被送到仍在探索或试放的渠道。候选全部被保护时，回退到仍可用的候选，而不是拒绝所有流量。

稳定性恢复不会删除原始样本或分钟聚合，只推进 `(渠道, 模型)` 的共享观测边界。主表和调度视图只显示边界后的新数据。

## 429 冷却

业务请求返回 429 且该事件允许运行时保护时，渠道 + 模型进入冷却，默认 `30` 秒。冷却中的路由不参与选路。管理员可按渠道和模型暂停 429 限制，最长 `300` 分钟；暂停期间的 429 不计入智能调度样本，也不触发冷却。该设置优先于自动冷却，并作用于该渠道同一模型的所有分组路由。到期后自动恢复，也可手动提前恢复。

## 自适应采样与探索

样本不足的渠道会进入探索。`traffic` 模式下探索流量不超过 `exploration_traffic_percent`；`probe` 模式使用智能探测补样本，不直接改写业务流量。

自适应采样根据主渠道健康压力和备用渠道样本缺口计算预算：

```text
demand = clamp(max_sample_debt / min_samples, 0, 1)
budget = demand × (base + pressure × (max - base))
```

健康状态为 `healthy` / `observation` / `pressure` / `high_risk`。备用渠道要替换主渠道，需要窗口内健康请求占比达到切换确认阈值（默认 `95%`），并且分数超过主渠道切换分差。样本不足或健康未确认时，只允许自适应采样，不切换主渠道。

## 固定主渠道

管理员设置的固定主渠道只改变池内优先级和权重，不绕过禁用、模型能力、参与状态或 429 冷却。有效期内因自动禁用、手动禁用或路由能力临时禁用而不可用时，固定意图暂挂，池内其他可用渠道接管；恢复且未到期时自动重新置顶。移除分组、模型或参与关系属于结构变更，会清理对应路由状态，不会在重新加入后恢复旧固定意图。

## 写回保护

调度写回带 control、economic、participation 和 revision 检查。旧任务不会覆盖新配置。经济修订号在分组倍率或成本换算变更时更新。强制重置会清临时流量并重建调度状态。

## 数据边界

调度状态、评分细节和临时流量写入调度模型；成本、余额、日志和并发仍按物理渠道保存。Redis 实时事件、调度运行时快照和本地历史队列并存，不能视为单一强一致决策账本。
