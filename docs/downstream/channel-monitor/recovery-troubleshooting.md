# 运行状态与诊断

渠道监控的“运行详情”展示当前健康状态、后台待处理工作、今日诊断和历史累计，帮助区分正在发生的故障与已经恢复的异常。

## 系统任务历史

Root 可在系统信息页的“系统任务”中按类型和状态筛选历史记录。下游类型包括渠道监控、渠道模型检测、智能调度、智能调度探测、监控历史清理、上游账户余额、上游自动任务和本地响应退款；筛选历史不影响活动任务展示。

“清理历史任务”经确认后清理所有分页中符合筛选条件的已结束任务，保留活动任务及每种类型的最新记录供调度使用。上游自动任务配置不属于任务历史，不会被列出或清理。

## 健康状态

健康状态默认每 10 秒更新。多实例部署时，不同节点的本地队列与累计数可能不同，应结合节点标识和检查时间查看。

| 状态或条件 | 含义 |
| --- | --- |
| 少量新事件或正常成本待办 | 可能仍然健康，非零待处理数不自动代表故障 |
| 统计滞后或相关积压持续约 30 秒 | 报告统计延迟，后台继续自动处理 |
| 成本待办异常或最早记录超过 120 秒 | 报告成本账本积压 |
| 观测失败、后台停止、新隔离或异常持续约 300 秒 | 需要管理员检查具体原因 |
| 故障后连续健康约 60 秒 | 确认恢复并更新恢复时间 |
| 超过 30 秒未获得新的健康观察 | 状态待确认，不能沿用旧健康结论 |

`manual_required` 表示需要管理员关注，不会自动停止后台重试。

## 待处理数量

后台待处理包括监控样本、待补发记录、待记账成本等不同阶段的工作。同一笔事件在交接时可能暂时出现于多个阶段，因此合计不是去重后的请求数。

待处理数量增加时，应结合最早待办时间和实际完成进度判断。今日成本已更新但历史账本仍有待办，属于可能出现的状态，详见[成本统计](cost-statistics.md)。

## 今日诊断与重置

今日诊断按北京时间换日，显示后台重试、接管、隔离和两种清理失败次数。启用前的累计不会反推为今天的数据。

“重置今日诊断”只清零这五类今日次数，不删除当前故障、待处理工作、隔离详情、历史累计或通知状态。跨午夜的旧确认会被拒绝，需重新确认当前日期。

恢复或重置诊断不会补齐已经丢失的样本。数据是否完整仍以相应查询的覆盖提示为准。

## 常见情况

| 现象 | 查看内容 |
| --- | --- |
| 今日成本未变化 | 日期与筛选是否一致、请求是否结算、未解析数及后台待办是否增加 |
| 今日成本与历史金额暂时不同 | 账本处理进度、异步费用及迟到修正 |
| 余额恢复但渠道仍停用 | 禁用原因、恢复开关、倍率条件和余额估算完整性；手动禁用不会自动解除 |
| 非 429 错误后渠道受保护 | 查看稳定性保护，不能只检查 429 冷却 |
| 分组没有缓存率 | 显示开关、上下文阈值、时间窗口及有效样本是否满足条件 |

## 通知

短暂积压先由后台重试，持续到人工关注阈值后通知。Redis 不可用、后台停止、观测失败、新增数据丢弃或隔离等故障可以直接通知。已通知故障稳定恢复后发送恢复通知，同类持续故障按冷却时间去重，发送失败继续重试。

通知需开启监控邮件总开关、填写收件人并启用 `monitoring_health` 类型；智能调度失败使用独立的 `smart_schedule_failed` 类型。

## 管理接口

以下接口均需要 Root 权限：

- `GET /api/channel_monitor/health`：运行健康与恢复状态。
- `GET /api/channel_monitor/diagnostics`：今日诊断。
- `POST /api/channel_monitor/diagnostics/reset`：确认日期后重置今日次数。
