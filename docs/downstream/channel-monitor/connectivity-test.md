# 渠道连通性测试

渠道管理和渠道监控的连通性测试使用同一测试控制器，实际请求会调用上游并校验响应、Usage、首字时间和 TPS。测试不经过公开中继入口，因此不会被本地探针响应拦截。

## 入口

- 渠道监控页全局“渠道连通性测试”，以及渠道行的单渠道测试。
- 渠道管理页的批量测试对话框。
- 管理 API 与渠道测试控制器共用，结果带来源标记 `manual_test`。

## 行为规则

- 单次测试按指定渠道和模型发真实上游请求。
- 批量测试按渠道和模型展开；并发循环限制并发数、循环次数和总请求数。
- 停止操作只阻止尚未发出的请求，已发出的请求继续完成。
- 测试结果记录测试来源、错误分类、耗时、首字、TPS 和成本。
- 测试会占用物理渠道并发租约；租约不足时该次测试失败或跳过，不会伪造成功。
- 状态探测和分组探测沿用测试请求，但使用独立来源标记和结果类型，不会伪装成普通业务请求。
- 测试流式能力取决于渠道适配器支持，不能假定所有渠道都支持相同的流式选项。

## 数据边界

测试成本记入对应物理渠道的日账，并带来源标记。默认不作为智能调度业务样本；只有探测链路在配置了“记录样本”后才会把成功样本写入调度观测。测试失败会计入管理员诊断，不作为普通用户的成功消费记录。
