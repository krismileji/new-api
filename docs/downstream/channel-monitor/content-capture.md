# 临时请求内容抓取

用于短时排查疑似蒸馏：开启后提取中继请求中的本轮用户输入和返回给客户端的模型回复，只保存在 Redis 中，不写入数据库。入口为渠道监控“用户请求统计”弹窗的“请求内容抓取”页签，仅 Root 可用，且需要启用 Redis。

## 使用

1. 设置保留条数（1–1000）、每项保存上限（1–256KB）和自动关闭时间（1–72 小时），确认后开始抓取。
2. 列表按时间倒序展示最新记录，超过保留条数时删除最旧的记录。“按用户汇总”统计当前已记录的条数、Key 数和模型数，点击后按该用户筛选。
3. 点击“查看”阅读和复制本轮用户输入和模型回复。需要检查协议字段时，可在抓取设置勾选“同时保留原始报文”，再在详情中展开查看。原始 JSON 自动格式化，复制时使用已保存的原始文本。旧记录继续显示原始报文。
4. “停止并清空”立即关闭抓取并删除全部记录。到达自动关闭时间后，配置和记录一起过期。

抓取中可修改保存上限、自动关闭时间和是否保留原始报文。设置适用于随后开始的抓取，既有内容依照原保留规则清理。调小保留条数时立即删除多出的旧记录。

## 记录范围

- 只记录 `relay` 路由的 POST 请求，包括 OpenAI、Claude、Gemini 兼容接口和 Responses 接口。Responses WebSocket 和 GET 查询不记录。
- 输入提取支持 OpenAI Chat Completions、Responses、Claude Messages 和 Gemini GenerateContent，也支持基础 Completions 的文本提示词。通过请求末尾连续的用户消息识别本轮输入，附件显示类型和数量。只提交工具结果的请求会单独标明。客户端在用户角色下拼接的文字会作为用户消息显示。
- 回复提取客户端收到的可见文本。流式回复会拼接 SSE 文本增量，带多候选的接口展示首个候选。仅调用具名工具时显示工具名称，失败时显示可提取的错误消息。
- 原始报文字节数和保存上限分别计算。纯文本、对话提取结果和选择保留的原始文本按每项上限截断。非流式响应 JSON 和单个 SSE 事件超过 4 MiB 时会提示内容不完整，后续 SSE 事件仍可提取。
- 非 JSON/文本报文（如音频上传）只记录大小。请求在读取正文前被拒绝时（如认证失败）不记录正文。
- 不保存请求头和 API Key。
- 各实例每 2 秒读取一次开关状态，开关变更最多延迟 2 秒生效。关闭后仍在进行的请求不会写入。

## 接口

以下路径位于 `/api/channel_monitor`，需要 Root 权限并禁止缓存。开启和关闭会写入操作审计日志。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /content-capture` | 当前配置和全部记录摘要 |
| `PUT /content-capture` | `{"enabled":true,"limit":200,"max_body_kb":64,"hours":24,"capture_raw":false}` 开启或更新；`{"enabled":false}` 关闭并清空 |
| `GET /content-capture/records/:id` | 单条记录正文；记录已被覆盖或清空时返回 404 |

## 注意

抓取期间，对话内容和选择保留的原始报文以明文保存在 Redis 中。按保留条数计算，每条最多保存两项提取结果。启用原始报文后，每条最多保存四项正文，另有 Redis 序列化与记录元数据的开销。请只在排查期间短时开启，并确认符合服务条款与隐私要求。
