# 临时请求内容抓取

用于短时排查疑似蒸馏：开启后记录中继请求的请求正文和返回给用户的响应正文，只保存在 Redis 中，不写入数据库。入口为渠道监控“用户请求统计”弹窗的“请求内容抓取”页签，仅 Root 可用，且需要启用 Redis。

## 使用

1. 设置保留条数（1–1000）、单侧正文上限（1–256KB）和自动关闭时间（1–72 小时），确认后开始抓取。
2. 列表按时间倒序展示最新记录，超过保留条数时删除最旧的记录。“按用户汇总”统计当前已记录的条数、Key 数和模型数，点击后按该用户筛选。
3. 点击“查看”打开单条记录的请求和响应正文，JSON 自动格式化，可复制原文。
4. “停止并清空”立即关闭抓取并删除全部记录。到达自动关闭时间后，配置和记录一起过期。

抓取中修改设置只更新上限和自动关闭时间，已记录内容保留；调小保留条数时立即删除多出的旧记录。

## 记录范围

- 只记录 `relay` 路由的 POST 请求，包括 OpenAI、Claude、Gemini 兼容接口和 Responses 接口。Responses WebSocket 和 GET 查询不记录。
- 请求正文是客户端发送的原文，响应正文是返回给客户端的内容，流式响应保存原始 SSE 文本。正文超过上限时截断，并记录原始字节数。
- 非 JSON/文本请求体（如音频上传）只记录大小。请求在读取正文前被拒绝时（如认证失败）不记录正文。
- 不保存请求头和 API Key。
- 各实例每 2 秒读取一次开关状态，开关变更最多延迟 2 秒生效。关闭后仍在进行的请求不会写入。

## 接口

以下路径位于 `/api/channel_monitor`，需要 Root 权限并禁止缓存。开启和关闭会写入操作审计日志。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /content-capture` | 当前配置和全部记录摘要 |
| `PUT /content-capture` | `{"enabled":true,"limit":200,"max_body_kb":64,"hours":24}` 开启或更新；`{"enabled":false}` 关闭并清空 |
| `GET /content-capture/records/:id` | 单条记录正文；记录已被覆盖或清空时返回 404 |

## 注意

抓取期间所有用户的对话内容以明文保存在 Redis 中。Redis 内存占用上限约为“保留条数 × 2 × 单侧正文上限”。请只在排查期间短时开启，并确认符合服务条款与隐私要求。
