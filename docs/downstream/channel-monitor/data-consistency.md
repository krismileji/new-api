# 统计口径与数据完整性

核对不同页面的数据时，应使用相同的日期、时间窗口、渠道和筛选条件。成本、成功率、调度与余额分别更新，刷新后不一定处于同一进度。

## 指标之间的区别

| 数据 | 统计对象 |
| --- | --- |
| 实际成功率 | 每次真实上游尝试；一次请求的重试可产生多次尝试 |
| 最终成功率 | 用户请求的最终结果 |
| 普通业务统计 | 排除系统探测和本地响应后的业务样本 |
| 调度指标 | 符合当前调度策略和观测范围的样本 |
| 渠道成本 | 实际物理渠道产生的上游费用 |
| 余额预估 | 上游余额基准减去未被该基准吸收的消费和在途预估 |
| 当前并发与 RPM | 正在执行的请求，以及最近 60 秒已准入的尝试 |

不同统计对象的数量或成功率无需相等。探测成功、本地回应、用户最终成功不能直接当作同一种成功样本。

## 时间范围

- 日统计统一按北京时间，查询区间为左闭右开 `[from, to)`。
- 近期性能和调度窗口可以跨零点，换日不会清空仍有效的窗口样本。
- 跨日查询合并今天与历史记录，同一笔费用或同一份统计不会因跨日重复相加。
- 异步任务的费用修正计入原发生日，不计到回调当天。
- 稳定性恢复后，调度视图使用新的观测范围；今日累计、历史趋势、余额与并发不因此归零。

分组业务周期按固定周期划分，与自然日统计用途不同，具体见[探测策略](probe-policy.md)。

## 完整性提示

`coverage.status` 表示当前范围的数据完整程度：

| 状态 | 含义 |
| --- | --- |
| `complete` | 当前查询范围的数据完整 |
| `partial` | 有可用数据，但存在缺口、截断或未补齐的明细 |
| `unavailable` | 当前无法提供有效数据 |

无样本的比例显示无数据，不显示为 0% 或 100%。未知归属、未回填明细和窗口不足分别提示；渠道总成本完整不代表每个用户或模型的明细也完整。

监控过载或故障可能丢失部分样本。后台恢复正常后，已有缺口仍会保留提示；不能把待处理数量清零视为历史数据已经完整。

## 重启与历史保留

今天和近期指标依赖 Redis，历史日统计保存在数据库。重启后会恢复可恢复的数据；缺少恢复所需记录时报告不完整，不用旧数据冒充实时结果。Redis 连接故障与安装时未启用 Redis 是不同状态。

今日成本和成功率/缓存日统计缺失时，临时读取一致的数据库基线，并复用原后台重建接上 outbox/Stream 增量。恢复期间结果标记不完整，发布有效日统计后才切回 Redis；同日同指标共用初始化结果。Redis 故障导致无法共享时，基线只在当前节点复用，并保持原时间和降级状态。数据库没有恢复依据或读取失败时不能把缺失统计解释为完整的零。

刚跨零点时，昨日费用、统计或迟到修正可能仍在处理中，历史值可以随后补齐。历史可查询也不代表今天的实时数据已经恢复。

各类历史按[保留配置](../configuration-reference.md)清理。调整保留期在后续清理任务生效，不会立即删除全部历史；尚未完成的结算和检测费用不按已完成记录清除。

## 三种共享关系

| 关系 | 共享内容 | 仍独立的内容 |
| --- | --- | --- |
| [逻辑归组](../channel-logical-group/README.md) | 调度、状态探测、模型检测身份 | 物理渠道成本、余额、转发配置与并发 |
| [上游账户](upstream-accounts.md) | 显式关联的余额、认证与换算 | 渠道转发 Key、倍率查询、调度和历史成本 |
| [共享限流组](shared-limits.md) | 并发/RPM 总上限与等级预留 | 物理渠道计数、独立限额、成本与余额 |

相同 Base URL 不会自动建立这些关系。公开分组监控展示某分组，也不会授予该分组的调用权限。
