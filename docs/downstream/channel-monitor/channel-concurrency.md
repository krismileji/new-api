# 渠道并发限制

每个渠道可配置 `0` 到 `100000` 的并发上限，`0` 表示不限制。管理入口为渠道监控渠道行的并发设置，接口为：

- `GET /api/channel_monitor/concurrency`
- `PUT /api/channel_monitor/channel/:id/concurrency`

## 租约

Redis 启用时，配置、活动租约和 revision 使用 `channelConcurrency:v1:*` 键，租约 TTL 为 `2` 分钟并每 `30` 秒续租；Redis 未启用时使用进程内计数。上游请求结束后释放租约，重复释放不会重复扣减。

状态探测、连通性测试和模型检测使用相同的物理渠道租约。逻辑归组只在冻结成员中改选物理渠道，不创建逻辑组级并发计数。

## 满载选路

自动选路遇到满载渠道会加入当前请求排除集合并尝试其他候选。系统会按 `ChannelMonitorChannelConcurrencyWaitSeconds`（默认 `1` 秒，范围 `0..600`）等待租约，轮询间隔 `100ms`；超时后：

- 未指定渠道：排除满载渠道并改选。
- 显式指定渠道，或全部候选满载：返回 HTTP `429`，错误标记为不可跨渠道重试。
- 客户端断开时立即停止等待。

RPM 限制与并发限制同时生效；达到 RPM 上限时同样视为满载。

## 数据边界

当前并发数包含所有渠道，即使上限为 `0`。页面刷新后仍能看到真实当前并发。并发状态不是成本账本，也不改变用户扣费。
