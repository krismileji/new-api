# 渠道并发与 RPM

Root 管理员在渠道监控的渠道行配置并发和 RPM 上限，各为 `0..100000`，`0` 表示该单渠道维度不限。接口为：

- `GET /api/channel_monitor/concurrency`
- `PUT /api/channel_monitor/channel/:id/concurrency`

## 用量与租约

当前并发是仍占用物理渠道租约的请求数。租约 TTL 为 `2` 分钟，每 `30` 秒续期，上游请求结束后释放，重复释放不重复扣减；流式请求占用到转发结束。异步任务只覆盖提交阶段，不代表远端任务整个运行时长。

当前 RPM 是最近 `60` 秒成功准入的上游尝试数。重试重新准入另计一次；结束、失败或取消不返还 RPM，等待和被拒绝的准入不计入。没有设置限额的渠道也登记用量，在线加入共享组后沿用原计数。消费日志写入时间不影响 RPM。

状态探测、智能探测、连通性测试和模型检测使用物理渠道准入；已有租约不重复申请。直接测试另有用于余额空闲判断的活动跟踪，不能与业务并发重复计数。

## 满载与等待

自动选路会尝试原路由权限允许的其他可用渠道；满载候选加入本次请求排除集。共享组总额耗尽时临时跳过整组，单渠道或等级受限时仍可尝试组内其他合适成员。

没有可用替代时，按 `ChannelMonitorChannelConcurrencyWaitSeconds` 等待，默认 `1s`，范围 `0..600`。未分组的租约等待按 `100ms` 轮询，共享组使用有界优先级队列。客户端断开立即停止。

显式指定渠道不切换其他渠道；等待超时或全部候选不可用时返回 HTTP 429。限流拒绝不制造上游成功样本。

## 多实例与共享组

Redis 启用时配置及租约使用 `channelConcurrency:v1:*` 键；未启用时只提供进程内计数。Redis 故障不退化为各节点独立放行，多实例必须共享同一 Redis。

逻辑归组只帮助选择物理成员，不创建逻辑组并发计数。需要多个渠道共用上游额度时配置[共享限流组](shared-limits.md)：单渠道限制与组限制同时生效，资源优先级和路由优先级分别设置。

在线修改上限不终止已有请求。即使用量暂时超过新上限，也保留原计数，等用量回落后继续准入。并发与 RPM 不作为成本账本或用户扣费依据。
