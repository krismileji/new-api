# 分析与下钻

渠道监控的成本、成功率与缓存分析共用按需加载的分析表。API Key 指客户端入站令牌，不是渠道配置中的上游密钥；页面只展示名称、ID 和不可逆身份，不展示完整 Key。

## 展开顺序与查询范围

| 页签 | 展开顺序 |
| --- | --- |
| 渠道汇总 | 渠道 → 模型 → 用户 → API Key |
| API Key 明细 | 用户 → API Key → 模型 → 物理渠道 |

用户、Key、模型和渠道各层都有独立分页；只展开选中节点，不一次返回整棵树。每层继承日期、搜索和全部父级筛选，从单渠道入口打开时保留该渠道限制。

成本与利润分析的 API Key 层按来源合并同一用户下的系统探测：智能调度探测合并为“智能调度探测”一行，模型测试合并为“手动测试”一行，展开后再按模型、物理渠道查看；不同上游密钥不会拆成多个探测行。历史上误记为业务来源、入站 API Key ID 为 `0` 且名称为“智能调度探测”或“模型测试”的记录也分别按此规则展示，无需回填或改写历史账目。真实 API Key 即使使用同名，也保持独立；其他探测来源仍分别展示。

父级及顶部总览采用后端 `scope_summary`，代表完整筛选范围，不能用当前页或已展开子行相加代替。同范围刷新保留已有内容和展开状态；更换日期、页签、搜索或指定渠道后按新范围查询，不展示另一范围的旧明细。

## 指标口径

| 指标 | 计算方式 |
| --- | --- |
| 人民币成本 | 整数 `cost_nano_cny / 1,000,000,000`，先聚合后格式化 |
| 解析率 | 已结算数 ÷（已结算数 + 未解析数） |
| 上游尝试数 | 实际成功数 + 实际失败数；重试形成独立尝试 |
| 实际成功率 | 实际成功数 ÷ 实际样本数 |
| 最终成功率 | 最终成功数 ÷ 最终样本数；最终失败摘要不另加一次上游尝试 |
| 请求缓存命中率 | 命中缓存请求数 ÷ 有效缓存样本数 |
| 流式缓存利用率 | 流式缓存读取 tokens ÷ 流式总输入 tokens，按 token 加权 |
| 缓存写入次数 | 有正数缓存写入 tokens 的请求尝试数，单位为次 |
| 平均首字 | 有效首字耗时总和 ÷ 对应样本数 |
| 聚合 TPS | 有效输出 tokens 总和 ÷ 有效生成秒数总和 |

分母为零显示无样本，不能简单平均子级百分比或每请求 TPS。缺计时的请求不补零。普通 OpenAI 输入以总 prompt tokens 为基准；已有 `input_tokens_total` 时优先使用，Anthropic 总输入需包含普通输入、缓存读和缓存写。

真实业务统计排除系统探测和本地响应；成本仍包含其适用的分类。探测成本、模型检测及无法归属的历史费用不能伪装成某个用户的业务消费。

## 日期与未知归属

- 今天的成本、成功率和缓存持续更新，历史数据按日保存。
- 渠道汇总与用户、Key、模型明细分别提供覆盖提示，明细缺失不代表渠道总额为零。
- 跨日范围按北京时间合并，比例根据合并后的原始计数计算，不简单平均每天的百分比。
- 分钟明细用于成功率和性能，读取近期窗口，不与日范围参数混用。

`user_id`、`api_key_id` 未传表示不限制，显式 `0` 表示精确查询未知身份。Key 下钻还保留 `api_key_key`，模型下钻保留 `model_key`，避免同 ID 的历史指纹或未知模型行混合。

每层各自显示 `coverage`。渠道总账完整不意味着用户/模型明细完整；未知归属、未回填、检查点缺失、截断和投影不可用分别报告，不把空明细宣称为零成本。

## 管理 API

以下路径位于 `/api/channel_monitor/analytics`，全部需要 Root 权限。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /summary`、`GET /rows` | 范围汇总与当前页 |
| `GET /trend` | 按日趋势，不接受分钟模式 |
| `GET /options` | 渠道 ID/名称选项；不是通用用户或 Key 搜索接口 |
| `POST /backfill` | 有界、幂等的历史成本明细回填 |

查询支持 `metric=cost/success/performance`、日期 `from/to`、`group_by`、父级筛选、`search`、白名单 `sort`、`direction` 和 `page/page_size`。

- `group_by` 可选 `day`、`channel`、`user`、`api_key`、`model`、`channel_model`、`api_key_channel_model`，默认 `channel`。
- `page` 从 `1` 开始，`page_size` 默认 `50`，范围 `1..200`。日范围最多 `90` 天；`summary/rows` 未指定日期时默认最近 `30` 天（含今天）。
- 分钟模式使用 `minutes=1..1440`，不接受成本、日分组或日期范围。`group` 筛选和 `success_mode=final` 只用于分钟模式，默认成功率口径为 `actual`。
- 性能指标必须指定分钟范围，且使用 `success_mode=actual`。`api_key_key`、`model_key` 最长 `64` 字节。

统计响应包含 `source`、`coverage`、`scope_summary`、`items`、`total` 和时间/版本信息。

搜索在分页前处理；用户名、显示名、渠道名和数字 ID 按当前接口规则解析。未知归属查询不能因缺少 ID 自动放宽为全部数据。

## 历史回填

`POST /backfill` 接收查询参数 `batch_id`、`from`、`to`、可选 `max_days`；日期采用北京时间半开区间。例如查询或回填 9 月 1 日应使用 `from=2026-09-01&to=2026-09-02`。

回填只补齐权威日账/Key 账到分析明细的差额，不重放扣费、不修改权威日账。同批次已完成日期可跳过，失败日期保留错误重试；负残差、Key 总额超过渠道账或计数不一致时回滚该日。无法还原模型时保留 unknown，只能用当前 Token 推断用户时标为 inferred。
