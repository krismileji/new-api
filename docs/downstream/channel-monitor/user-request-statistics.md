# 用户 API Key 渠道请求统计

> 设计稿：描述预期交互、统计口径和接口行为。

在渠道监控中按“用户 → API Key → 渠道”查看每日请求量、流式与非流式请求量，以及输入 Token 低于可配置阈值的请求占比。主要用途是发现可能与模型蒸馏或批量提取有关的异常调用线索，辅助管理员分析用户和 Key 的渠道调用分布；统计指标单独不能证明用户在蒸馏，自动禁用只在管理员另行启用策略并满足样本数和数据完整性条件后执行。页面不展示完整 API Key。

## 入口与交互

渠道监控工具栏增加“用户请求统计”按钮。点击后打开统计弹窗，默认查询上海时区当天。

弹窗顶部提供日期选择、阈值配置和刷新操作。日期一次选择一天，可用前一天、后一天和日期选择器切换；不能选择未来日期。列表按当前层级展示，点击行进入下一层，面包屑可返回上层：

| 层级 | 列表内容 | 点击后 |
| --- | --- | --- |
| 用户 | 用户名、显示名、用户 ID、该用户名下 API Key 的低输入自动禁用累计次数 | 查看该用户的 API Key |
| API Key | Key 名称、ID、该 Key 的低输入自动禁用累计次数 | 查看该 Key 调用过的渠道 |
| 渠道 | 渠道名称和 ID | 当前层级，不再向下展开 |

仅渠道监控的 Root 管理员弹窗显示用户及 API Key 的低输入自动禁用累计次数，不在用户侧 API Key 页面或其他用户界面展示。弹窗中用户和 API Key 行提供“禁用历史”入口；管理员可查看某个 Key 的每次低输入自动禁用记录，包括判定日期、当时的低输入阈值、占比、有效样本数、恢复时间和恢复方式。用户层累计次数是其名下所有 API Key 的记录数之和。历史次数与所选统计日期无关，表示系统保留的低输入自动禁用事件总数；手动禁用、上游错误规则自动禁用、条件不满足或幂等重试均不计入。用户自行恢复 Key 的能力仍按前文通过现有 API Key 页面提供，但禁用次数及历史只供 Root 管理员查看。

列表默认按低输入请求占比从高到低排序，也支持按请求次数或低输入自动禁用次数排序，并使用服务端分页。管理员可按用户、Key 名称或 ID、渠道名称或 ID 搜索。搜索、分页、排序和返回上层时沿用当前日期及已选父级。未知用户或 Key 归属保留为独立的“归属未知”行，不因缺少身份信息丢弃请求。

每层显示以下指标：

| 指标 | 展示方式 |
| --- | --- |
| 渠道请求次数（上游尝试） | 已实际发送到上游的请求尝试次数 |
| 流式请求 | 按客户端流式请求标记统计的次数 |
| 非流式请求 | 按客户端非流式请求标记统计的次数 |
| 低输入请求 | 输入 Token 数低于当前阈值的请求次数，以及可判定输入量的请求数 |
| 低输入占比 | 低输入请求数 ÷ 可判定输入量的请求数 |
| 输入量未知 | 请求已计入总次数，但没有可靠输入 Token 数的次数，包含仅有估算值的请求 |
| 用户 / API Key 低输入自动禁用次数 | 实际将 Key 从启用改为禁用的成功次数，包含用户自行恢复后的既往记录 |

顶部摘要展示当前筛选范围的总请求、流式请求、非流式请求、低输入请求、可判定输入量请求和低输入占比。百分比用完整筛选范围的原始计数计算，不对分页行或子级百分比取平均。

## 统计口径

- 日统计按上海时区自然日划分，日期范围为当天 `00:00:00` 至次日 `00:00:00`，左闭右开。
- 每次实际发送到某渠道的上游尝试计一次；重试是新的上游尝试，会计入其实际经过的渠道。请求在发送前被拒绝或直接由本地响应处理时，不属于渠道请求次数。
- 请求次数包含上游调用成功和失败的尝试。系统探测、模型检测、分组探测和本地响应不计入用户业务统计。
- 流式/非流式根据客户端请求的流式标记分类；同一筛选范围内，两类次数之和等于请求总次数。
- 输入 Token 采用上游实际返回、经监控事件规范化记录的可靠输入量，包含对应协议的缓存读取和写入输入 Token，不包含输出 Token；采集时区分实际用量、估算值和缺失用量，仅有估算值的请求按输入量未知处理，不使用估算值补齐缺失用量。
- `K` 按 `1000` Token 计算。阈值为 `4K` 时，输入量 `0–3999` 的请求算作低输入请求，`4000` 不算。输入量缺失的请求仍计入请求次数，但不进入低输入占比的分子或分母。
- 低输入占比 = `输入量小于阈值的请求数 / 输入 Token 已知的请求数`。分母为零时显示“暂无可判定样本”，不显示为 `0%`。
- 低输入占比及自动禁用只使用能拿到可靠输入 Token 数的请求，不设置这些请求占全部请求的覆盖率门槛。输入量未知的请求仍展示在总请求及未知次数中，不参与低输入占比，也不因其存在而阻止自动禁用判定。
- 未知用户、API Key 或请求用量必须保留在完整性提示或未知归属行中，不能当作零请求。

## 阈值配置与即时生效

阈值是渠道监控的全局设置，对所有管理员和日期查询使用同一个当前值。弹窗内显示当前值，管理员可修改并保存。建议初始值为 `10K`，可选 `1K`、`4K`、`8K` 常用档位并允许自定义，范围为 `1–1000K`，按整数 `K` 设置。`10K` 适合作为覆盖面较宽的初始观察口径；如果正常业务中的短输入请求较多，可下调阈值以减少误报。

保存成功后，页面立即使用新阈值重新计算当前日期和当前层级的低输入次数及占比，无需重启服务、等待下一统计周期或重新生成历史统计。阈值变化只改变低输入分类，不修改原请求次数和 Token 用量；切换到其他历史日期时也按当前阈值展示。上线后应结合正常业务流量观察一段时间，再决定是否从 `10K` 调整；不存在适用于所有模型和业务的固定最佳值。

识别疑似蒸馏行为时，应一起观察请求绝对量、低输入请求数、低输入占比及其按日变化，并按用户、Key 和渠道逐层核对。大量正常对话也可能是短输入；高占比但请求很少同样不足以判断为异常。该页面提供排查线索，不作自动定性。

为支持阈值即时变更，日统计需保留可按阈值重新归类的输入 Token 分布，而不能只持久化当前阈值下的低输入计数。整数 `K` 阈值可以按每 `1000` Token 的区间累计分布，再按当前阈值汇总；当天实时数据和历史日数据使用相同口径。

## API Key 自动禁用

管理员可启用自动禁用策略，并设置低输入请求占比门槛。策略默认关闭；启用时必须配置 `0–100%` 的占比门槛和最低有效样本数，避免单个或少量请求导致 Key 被禁用。占比门槛建议从 `80%` 开始观察，最低样本数建议初始为 `100`，两者都可按业务流量调整。

任务按上海时区每天 `00:00` 启动，检查刚结束的前一个自然日。按 API Key 汇总其所有渠道的业务请求，仅使用能拿到可靠输入 Token 数的请求计算低输入占比和有效样本数；当占比达到或超过配置百分比，且有效请求数达到最低样本数时，禁用该 Key，不设置输入量覆盖率门槛。例如共有 `1000` 次请求，其中 `200` 次拿到可靠输入量，`180` 次低于阈值，则低输入占比为 `180 / 200 = 90%`；采用建议的 `80%` 占比门槛和 `100` 次最低有效样本数时，满足禁用条件。任务启动时读取一份配置快照，整次判定使用同一版本的输入阈值和禁用策略，并把版本与判定值写入记录。判定前须完成已采集的前一日事件汇总；事件或日汇总尚未处理完时延后重试，仍未完成时跳过本次。单个请求未返回可靠输入量只代表该请求不参与低输入判断，不属于需要等待补齐的汇总延迟。自动禁用直接把 Key 状态改为与用户在 API Key 页面点击“禁用”相同的普通禁用状态：阻止后续新请求，不额外取消在途请求，也不启用仅管理员可解除的自动保护拦截。若 Key 已处于禁用、过期、额度耗尽、删除或其他不可用状态，则不覆盖原因、不新增自动禁用记录，也不发送自动禁用邮件。已有 Key 的禁用状态不影响用户的其他 Key。

自动禁用只针对判定日生成一次统计记录；同一 Key 和日期重复执行不得重复禁用或重复发通知。只有 Key 由启用成功变为普通禁用状态时才增加一次计数；Key 已因手动操作、过期、额度耗尽、删除或其他原因不可用时，不增加次数。用户自行恢复后，未来日期仍可再次触发自动禁用并累计新的一次。该功能只写入普通 Key 禁用状态，不注册现有“上游错误规则自动禁用”的独立拦截状态，不取消在途请求，也不复用其仅管理员解除的保护记录。用户可像恢复手动禁用的 Key 一样，在现有 API Key 页面自行重新启用。自助启用沿用现有状态更新流程，只有当前仍为普通“已禁用”状态且未过期、额度充足、未删除或受其他限制时才允许成功；更新 Key 状态与将统计记录标记为“用户自行恢复”必须协调提交，避免并发自动禁用、手动状态变更造成记录与真实状态不一致。自助恢复不要求管理员批准；过期、额度耗尽、已删除或其他独立限制仍然生效。管理员可查看统计禁用记录，并通过现有 Key 管理流程操作状态。记录应包含用户、Key ID、判定日、低输入阈值、配置版本、实际占比、有效样本数、禁用原因、恢复时间和恢复来源。历史记录独立于请求日统计和成本记录保留，不随这些统计数据过期清理；手动禁用记录不混入本功能计数。

禁用状态提交成功后，向该 Key 所属用户已验证的账户邮箱发送简体中文通知，说明禁用日期、低输入阈值、实际占比、样本数和在 API Key 页面自行恢复的方式。邮件不得包含完整 API Key、请求正文或其他凭据。若用户没有已验证邮箱，或邮件发送失败，保留禁用状态并记录通知状态；发送失败由后台重试，不重复执行禁用操作。邮件使用稳定的 `Message-ID` 帮助邮件系统识别重试，但 SMTP 在服务器已接收邮件后连接中断时无法确认投递结果，重试可能导致重复邮件。自动禁用、用户自行恢复、管理员解除等操作均写入审计，但审计内容不包含完整 Key 或请求正文。

### 用户通知邮件模板

主题：`【API Key 使用提醒】您的一枚 API Key 已暂停`

正文使用纯文本作为基准，并提供内容等价的 HTML 版本：

```text
{{display_name}} 您好：

为保护平台服务，您的 API Key 因 {{stat_date}}（北京时间）的调用统计达到已启用的自动禁用条件，现已暂停使用。禁用状态与您在 API Key 页面手动点击“禁用”相同。

API Key 名称：{{api_key_name}}
API Key ID：{{api_key_id}}
统计日期：{{stat_date}}（北京时间）
低输入判断阈值：小于 {{low_input_threshold_tokens}} Token
低输入请求：{{low_input_count}} / {{known_input_request_count}} 次
低输入请求占比：{{low_input_rate_percent}}%

本次处理是依据统计规则触发的自动禁用，不代表平台已认定您在进行模型蒸馏或违反使用规则。若您确认需要继续使用，可登录站点并在 API Key 页面自行重新启用此 Key；过期、额度耗尽或其他独立限制仍会继续生效。如无法重新启用，请检查 Key 状态或通过站点现有支持渠道联系管理员。

为保障账户安全，本邮件不会包含完整 API Key。请勿通过邮件发送 API Key、密码或验证码。
```

`display_name` 为空时使用“您好”；`api_key_name` 为空时回退显示 `API Key #{{api_key_id}}`。邮件中注明有效输入样本数的分母，避免低输入占比被误解为全部请求的占比。模板不放直接启用 Key 的链接；用户需先登录并通过现有 API Key 管理页面执行恢复。HTML 渲染时对所有动态字段进行转义；主题、纯文本和 HTML 内容都不得拼入请求正文或凭据。

定时判定应在多实例部署下全局幂等，避免多个节点重复处理同一日期和 Key。Key 状态沿用普通禁用状态，并按现有令牌状态更新机制使认证缓存失效；统计禁用记录和状态变化需持久化。用户恢复时需协调更新 Key 状态、将对应统计记录标记为用户恢复并刷新认证缓存，避免记录与实际状态不一致。自动禁用与用户恢复需和 Key 的其他状态变更串行协调。此功能不依赖现有上游错误自动禁用机制的本地运行时拦截；但多实例仍需验证各节点状态缓存的一致性。

## 更新与数据完整性

当天统计随渠道监控事件汇总更新，打开弹窗或点击刷新读取最新已处理数据。保存阈值后自动刷新，不依赖手动刷新。历史日期读取已保存的日统计；统计保留期限沿用渠道监控的历史数据保留策略。

统计响应应提供数据来源、覆盖状态和已处理截止时间。事件延迟、统计投影缺失、历史数据未采集或归属未知时，应明确显示“部分数据”或“暂不可用”；缺少数据不能解释为零流量。功能启用前没有保留请求事件或输入 Token 分布的日期，不承诺补算完整的低输入占比。

同一请求事件被修正或重放时，日汇总需替换该事件原有贡献后再写入新贡献，避免重复计数。日汇总的用户、Key、渠道身份以请求发生时记录的归属为准；展示名称可使用当前可见名称，统计归属不因后续账户资料变化而迁移。

## 权限与凭据展示

接口仅供 Root 管理员使用，并禁用 HTTP 缓存。页面展示 API Key 名称和 ID；绝不返回或展示可用的完整 Key、上游渠道密钥或用户凭据。未知身份作为统计分组显示，不尝试通过完整凭据反查身份。

## 管理 API 约定

以下为接口设计，均位于 `/api/channel_monitor`，需要 Root 权限并禁用缓存：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /request-stats` | 查询某一天在用户、API Key 或渠道层级的分页统计 |
| `GET /request-stats/settings` | 读取当前低输入阈值 |
| `PUT /request-stats/settings` | 校验并保存新的低输入阈值 |
| `GET /request-stats/disable-history` | 按用户或 API Key 查询低输入自动禁用历史及累计次数 |
| `GET /request-stats/auto-disable/settings` | 读取低输入占比自动禁用设置 |
| `PUT /request-stats/auto-disable/settings` | 更新开关、占比门槛和最低有效样本数 |

统计查询参数包含 `date=YYYY-MM-DD`、`level=user/api_key/channel`、可选 `user_id`、`api_key_id`、`search`、`sort`、`direction`、`page` 和 `page_size`。默认 `sort=low_input_rate&direction=desc`，也支持按请求次数排序。`level=user` 不传父级 ID；`level=api_key` 需指定 `user_id`；`level=channel` 需指定 `user_id` 和 `api_key_id`。响应包含当前阈值、层级摘要、分页项目、数据来源、覆盖状态和统计截止时间。

阈值保存请求使用 `low_input_threshold_k`。保存成功返回新的配置版本；统计缓存以配置版本区分，避免配置更新后读到旧占比。

自动禁用设置包含 `enabled`、`disable_rate_percent`、`minimum_known_input_requests`。启用前必须提供有效的占比门槛和最低样本数；关闭时保留配置但不执行判定。自动禁用统计记录提供 `reason=low_input_rate`、判定日、占比、输入阈值、样本数、邮件发送状态、恢复时间和恢复来源。请求统计中的用户/API Key 层返回 `low_input_auto_disabled_count`，为对应身份下本功能的历史禁用记录总数；当前日期筛选不影响该计数。`GET /request-stats/disable-history` 支持 `user_id` 或 `api_key_id`、`page` 和 `page_size`，分页返回禁用记录及恢复状态。所有管理查询需 Root 权限；用户自行重新启用沿用现有 API Key 状态更新接口，并仅能操作归属自己的 Key。用户恢复时记录恢复来源为 `user`，管理员通过 Key 管理流程启用时记录来源为 `admin`。

## 运行行为

请求统计从功能启用后收到的渠道监控事件建立日汇总，不会从历史请求日志推测输入 Token 分布。缺少可靠输入量的请求仍计入请求总数，但不会进入低输入比例的分子或分母。若事件写入、消费或日汇总尚未完成，相关日期显示数据不完整，自动禁用会等待队列就绪并按次日判定窗口重试；过期窗口之后跳过该日期。

同一判定日与 API Key 的禁用记录具有唯一性。成功禁用后重复调度不会再次禁用或再次创建记录；通知由后台独立重试，SMTP 投递结果不确定时可能出现重复邮件。历史禁用记录与每日请求统计使用不同保留策略，累计次数不受统计日期筛选影响。
