# 页面与功能

## 页面结构

页面顶部显示渠道总数、今日累计成本和今日成功率/缓存利用率。页面同时提供以下全局操作：

- 渠道连通性测试。
- 倍率更新和智能调度的任务记录。
- 渠道监控设置。
- 同时刷新概览、性能、成本摘要和当前并发快照。

页面不会自动刷新渠道监控数据。点击手动刷新时，概览、成本、性能和独立并发快照会同时重新读取；任务记录弹窗仍会在任务执行期间刷新状态。

主区域包含“渠道”“分组”“模型性能”“智能调度”四个视图，另有按需打开的分组监控设置面板。页面支持搜索、上游类型筛选、模型选择、统计时间范围和渠道排序；智能调度实际启用时统计范围由性能窗口接管，关闭时才显示手动分钟输入。人工顺序只影响渠道监控页面，不改变渠道优先级或路由策略。

点击成本或成功率/缓存利用率卡片可查看近 `7`、`30`、`90` 天趋势和指定日期明细；成功率、缓存利用率与缓存写请求趋势合并为一张双轴组合图，缓存写渠道数与请求数并入顶部汇总，每个渠道的缓存写请求数并入渠道明细。日期下拉框与柱子或折线数据点点击使用同一选择状态。

## 渠道视图

每行渠道展示：

- 启用状态、系统自动禁用原因、渠道备注和 ID。
- 上游余额、余额更新时间和手动刷新入口。
- 今日人民币已结算成本及成本历史入口。
- 当前与上次成本倍率、上游分组及倍率更新时间。
- 最近倍率读取状态、错误和连续失败次数。
- 本地关联分组、分组倍率及同步系数。
- 当前观测范围内的平均首字时间、平均 TPS、成功率和样本数；稳定性恢复后从共享观测边界重新积累。
- 每个渠道的当前并发数与并发上限；未限制渠道的上限显示“不限”。
- 智能调度参与路由数，以及各分组实际优先级和权重。点击该列可查看渠道下每条分组模型路由的性能、成功率、得分、调度状态和最近调度结果。

渠道级操作包括启用或禁用、单渠道连接测试、设置并发限制、更改关联分组、批量参与或取消智能调度、配置上游和查看倍率变更历史。低成功率或稳定性试放状态可直接点击，在确认后立即解除保护。已开启对应同步能力时，可直接刷新倍率或余额。

## 分组视图

分组视图汇总本地分组倍率、真实调用成功率、最终成功率以及关联渠道的成本倍率。Root 管理员可以：

- 管理分组关联渠道。
- 直接修改分组倍率。
- 取该组已启用且已有记录的渠道中最高成本倍率，再乘以分组系数同步分组倍率。
- 查看分组范围的成功率明细和各渠道拆分。

自动同步系数会持久化，下次定时策略计算继续使用。

## 分组监控入口

分组监控有两条用途不同的入口：

- Root 管理员在 `/channel-monitor` 的分组监控设置面板中维护监控开关、分组顺序、每组固定的 `probe_model`、探测间隔和状态展示范围，并可触发立即探测。该面板调用 `/api/channel_monitor/group_monitor/*`；Root 概览和执行明细由对应管理 API 提供，不会出现在普通用户侧。
- 模型广场用户侧页面为 `/group-monitor`，只读展示当前账号可用分组的状态卡片和时间窗。顶部导航仅在服务状态 `group_monitor_enabled=true` 且 pricing 导航模块可用时插入该链接；页面本身遵循 pricing 模块的公开/登录要求。

用户侧不显示渠道 ID、候选渠道、任务租约、配置修订号、连续成功/失败计数、错误信息或成本；这些字段只在 Root 管理 API 的概览/执行接口中提供。用户侧页面显示分组名称、探测模型、首字延迟、成功率、最近完成时间和按分钟/小时/天归一化的状态格。

### 分组状态

状态由配置、候选模型和最近一次逻辑探测的最终结果共同决定：

| 状态 | 事实含义 |
| --- | --- |
| `unconfigured` | 保存的探测模型不再属于该分组可用的启用文本模型；仅 Root 管理概览保留此项，用户侧过滤掉无效项。 |
| `paused` | 分组监控配置已保存但全局开关关闭。 |
| `pending` | 已启用但没有可用的完成状态，或状态结果尚未产生。 |
| `healthy` | 最近一次逻辑探测最终结果为 `success`。 |
| `unavailable` | 最近一次结果为 `unavailable`，没有可用路由完成探测。 |
| `unhealthy` | 最近一次结果为 `upstream_failure` 或 `local_failure`。 |
| `rate_limited` | 最近一次结果为 `rate_limited`。 |
| `stale` | 最近一次完成时间早于当前时间减去两倍探测间隔。 |

上游重试可能产生多个物理尝试，但状态、成功率和时间窗按每个分组的一条逻辑执行记录的最终结果计算；执行明细仍保留实际渠道、请求、耗时、首字、TPS、结算成本和错误字段。

## 模型视图

模型视图按所选模型对渠道排序，展示成本倍率、平均首字、平均 TPS、实际成功率、有效样本和最后请求时间。只显示支持该模型的渠道，适合在启用智能调度前检查数据覆盖。

## 智能调度视图

智能调度视图只展示当前已启用并已配置的分组模型调度池。顶部汇总运行状态、调度池数、参与路由数和当前可调度数，并提供执行记录、调度设置和立即调度入口；异常、试放和探索状态可直接定位到对应分组。

调度池按分组倍率从低到高排列，组内按模型排列。每个池展示候选层、预计流量分布，以及渠道名称、备注、成本倍率、实际优先级、权重和状态。备用、不可调度和未参与路由默认折叠；点击渠道名称打开与渠道菜单一致的右侧详情抽屉。稳定性降级或试放标签可点击并在确认后手动解除。

## 成功率与缓存利用率口径

“实际成功率”按真实上游调用统计，重试过程中的失败也算失败；“最终成功率”排除中间重试错误，表示请求最终对用户成功还是失败。

“缓存利用率”按 `缓存读取 tokens / 总输入 tokens` 计算，并按 token 数量加权聚合，不是“发生缓存读取的请求数 / 请求样本数”。普通 OpenAI 语义日志以 `prompt_tokens` 为总输入；存在归一化的 `input_tokens_total` 时优先使用该值；Anthropic 语义日志的总输入为普通输入、缓存读取和缓存写入 tokens 之和。没有输入 token 数据时页面显示 `-`。

渠道明细还能按 HTTP 状态码、上游错误类型和错误码聚合失败，并显示脱敏的错误示例和最近发生时间。

## 数据刷新

概览、成本、性能和并发快照使用独立查询。手动刷新会同时重新读取这些数据；单独修改倍率、分组、上游、调度或并发设置后，前端只使受影响的查询失效并重新获取。并发快照包含所有渠道，即使并发上限为 `0`，因此手动刷新后仍能看到真实当前并发。

性能和成功率是时间窗口统计，不是永久累计值。智能调度实际启用时，主表固定使用智能调度性能窗口的 `1` 到 `43200` 分钟范围，隐藏手动输入；智能调度关闭时，主表允许手动配置 `1` 到 `1440` 分钟。接口返回实际采用的分钟数和来源，页面以响应为准。

稳定性恢复时不会删除任何原始样本、日志或分钟聚合，而是推进 `(渠道, 模型)` 的共享观测边界。渠道主表和智能调度视图只显示边界后的新数据；没有新样本时显示样本数 `0` 和指标 `-`。今日统计、按日趋势、历史明细、长期模型统计以及余额、倍率、优先级、权重、并发等非样本数据不应用该边界。
