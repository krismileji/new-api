# 渠道成本统计

渠道成本用于查看上游支出，不改变用户钱包扣费、充值或订阅结算。入口为“渠道监控 → 成本”，汇总接口为 `GET /api/channel_monitor/cost`。

## 金额口径

成本展示为人民币，按请求发起时的成本倍率和换算参数计算；后续修改配置不会重新定价已记录请求。成本基数不包含用户分组售价倍率，换算方式见[上游同步](upstream-sync.md)。接口中的 `cost_nano_cny` 除以 `1,000,000,000` 得到人民币金额。

| 分类 | 含义 |
| --- | --- |
| 总成本 | 业务请求、探测和模型检测的全部已确认成本 |
| 探测成本 | 状态探测、分组探测、智能探测及适用的手动测试费用 |
| 分组探测成本 | 探测成本中的分组探测部分 |
| 模型检测成本 | 独立检测器执行模型检测的费用 |
| 业务成本 | 总成本减去探测成本和模型检测成本 |

分组探测已经包含在探测成本中，计算业务成本时不能重复扣除。费用无法归属到用户、模型或 API Key 时保留在未归属项，不丢弃该金额。

## 结算状态

- `settled_count`：已获得可信成本的次数，明确零成本也属于已结算。
- `unresolved_count`：尚不能确认费用的次数，不能当作免费请求。
- 解析率：已结算数 ÷（已结算数 + 未解析数）。没有样本时显示无数据。

缺少可信用量或有效计价配置时，费用保持未解析。异步任务在后续结算或修正后更新原请求发生日的金额，不重复计费；修正也可能使累计值降低。

## 查询与明细

支持按日期查看渠道汇总，并按渠道、模型、用户和 API Key 展开明细，详见[分析与下钻](analytics.md)。API Key 指客户端入站令牌，不是渠道的上游密钥。

自然日按北京时间划分，日期区间为左闭右开。例如查询 9 月 1 日，结束日期应选择 9 月 2 日。今天与历史日期可以一起查询，但跨日后昨日最后一批费用仍可能稍后补齐。

成本始终归属实际执行请求的物理渠道。逻辑归组、共享限流组和共享余额账户不会合并或改写历史渠道成本。

## 更新与完整性

今天成本持续更新，历史成本按日保存；页面以手动刷新为主。长请求、异步任务和后台积压会造成延迟，刷新按钮不会强制完成结算。

默认启用可靠成本记录。正常接收的费用可先出现在今日视图，再由后台按分钟写入历史账本；失败会自动重试。因此“账本有待处理记录”不一定表示今日页面未更新。

实时数据不可用、明细缺失或历史未回填时，页面会给出覆盖提示，不能把缺失明细解释为零成本。排查方式见[运行状态与诊断](recovery-troubleshooting.md)。

## 保留与关闭

成本历史默认保留 30 天，可通过 `ChannelMonitorCostRetentionDays` 调整。尚未完成结算的记录不会按已完成历史直接清除。

`CHANNEL_DAILY_COST_RELIABLE_OUTBOX=false` 会切换到内存记录方式，可靠性低于默认方式；关闭前已接受的可靠记录仍继续处理。相关配置见[配置参考](../configuration-reference.md)。
