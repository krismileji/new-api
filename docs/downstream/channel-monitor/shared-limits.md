# 共享上游限流与渠道优先级

入口：**渠道监控 → 共享限流组**，沿用渠道监控的超级管理员权限。

同一个上游账号由多个物理渠道使用时，把这些渠道加入一个共享限流组。组内共用总并发与最近 60 秒 RPM，同时继续执行每个渠道原有的单独限额。

## 配置示例

假设同一上游允许并发 10、RPM 300，希望优先保障渠道 A、B：

| 资源等级 | 成员 | 预留并发 | 预留 RPM |
| --- | --- | --- | --- |
| 100 | A、B | 3 | 90 |
| 0 | C、D | 0 | 0 |

- C、D 合计最多使用 7 个并发、210 RPM。
- A、B 共享等级 100 的预留，也可以使用公共剩余额度，所有成员合计仍不超过 10 / 300。
- A、B 没有流量时，C、D 也不能借用预留。
- A、B 若已经消耗自己的预留，后续请求仍需等待额度；优先级不会突破总上限，也不会中断已经发出的请求。
- 如果 A 的单独并发限制为 2，A 同时最多仍为 2。

资源优先级越大越优先，与原有路由优先级、智能调度权重分别配置。它保护的是**经过该渠道的流量**；路由到同一个渠道的普通用户和重要用户具有相同资源等级。

三个等级时，每条累计约束都生效。例如总并发 10，高等级预留 3、中等级预留 2，则“中 + 低”最多 7，低等级最多 5。中等级已经使用 7 时，低等级即使没有请求也不能继续准入。

## 创建与启用

1. 多节点部署先升级所有转发节点，使它们使用同一 Redis 和本功能代码。
2. 新建组，填写总并发、总 RPM、等级预留和成员。
3. 保存后直接启用，已有请求继续执行，新请求按共享配置判断。无需暂停或等待一分钟。

每个物理渠道最多属于一个组。最多 128 个组、每组 64 个成员、8 个等级；优先级范围 0–1000，额度范围 0–100000。总上限为 0 表示该维度不限，该维度的预留必须全部为 0。

逻辑组不会自动成为共享限流组，Base URL 相同也不会自动合并。复制渠道不会复制共享组成员关系。

## 等待与统计口径

请求会先尝试原路由权限允许的其他渠道。共享组总额耗尽时，临时跳过整个组；单渠道或某等级受限时，仍可尝试组内其他合适成员。指定渠道请求不会改走其他渠道。

没有可用替代渠道时，使用现有“渠道并发等待秒数”设置，默认 1 秒，0 表示不等待，最大 600 秒。组内优先放行可执行的高等级请求，同级按入队顺序；某个高等级渠道被自己的独立限额阻止时，不阻塞其他可执行请求。

每组最多 256 个等待项。取消、切换渠道或成功准入时出队；失联等待项在 15 秒租期后失去资格。等待和限流拒绝不占 RPM，超时或满额返回 429。

渠道行统一按“当前用量 / 上限”显示，不限时上限显示“不限”：

- **当前并发**：正在占用渠道租约的请求数。
- **当前 RPM**：最近 60 秒内成功准入的上游尝试数，直接使用限流器计数。重试重新准入时计新的一次，结束、失败和取消不会返还已经登记的 RPM。
- **组并发、组 RPM**：共享组的合计用量与组上限，渠道自身限额仍同时生效。

页面不再单独显示消费日志请求数，消费日志的写入时间与数量不影响当前 RPM。

一次准入同时占用并发和 RPM，释放只释放并发。流式请求占用到转发结束。异步视频等任务当前只覆盖提交请求阶段，不代表上游后台任务整个运行时长。

共享组内的 AWS Bedrock 请求关闭 SDK 内部自动重试，由网关重试流程重新申请额度；未加入共享组的 AWS 请求保留原 SDK 行为。

手动测试、状态探测、调度探测、模型检测也经过物理渠道准入；已持有租约的探测不重复计数。探测使用低于业务等级的内部等级 `-1`，不能占用业务预留。手动测试也受单渠道上限限制，以便加入组时能正确识别已在途的探测。

## 在线修改与删除

名称、总额度、成员、资源优先级和预留额度均可在线修改，保存后生效。降低额度时不会中断已有请求；如果当前用量已超过新上限，新增请求等待用量下降后再进入。总额度不能低于预留之和。

并发和最近 60 秒的 RPM 始终按物理渠道记录，共享组根据当前成员和资源等级汇总这些计数。因此修改等级、移出再加入、换组或删除组都不会清空渠道用量；在途请求完成后仍释放原渠道的占用。即使渠道此前没有设置 RPM 上限，也保留最近一分钟的准入记录，加入共享组后直接计入。

例如组上限为 100 RPM，成员最近一分钟已经使用 80 次，修改配置后仍保留这 80 次记录，不能因保存而重新获得 100 次额度。把渠道移出组后，该渠道按独立限额执行，组内只汇总剩余成员；移入另一组时，其现有用量计入新组。

“暂停准入”仅作为管理员主动停止新请求的开关；已有请求继续执行，可随时恢复。任何配置修改都不要求先暂停。删除组后成员恢复独立限流，无需等待。绑定中的物理渠道仍需先移出组，才能删除渠道本身。

表单携带版本号，过期表单会收到冲突提示。数据库提交后原子发布完整配置，发布前继续使用上一版规则，成功后整体切换；发布失败会明确提示尚未生效，刷新后重新保存即可。

## 运行环境

共享组复用现有渠道并发租约：正常请求每 30 秒续期，失联租约按既有两分钟超时回收，RPM 使用最近 60 秒滑动窗口。无需额外的人工恢复流程。

多实例必须使用同一 Redis；Redis 连接故障时限流请求报错，不退化为每节点独立放行。未启用 Redis 时仅支持单实例。运行状态丢失、Redis 重启及内存进程重启的行为与原单渠道限流一致，内存计数不跨进程持久化。配置缓存可以从数据库重建，不影响仍然存在的渠道计数。

当前使用项目既有的单 Redis 客户端，不支持 Redis Cluster。升级时应统一转发节点版本，旧版节点不认识共享配置，也不会记录未设 RPM 上限时的历史用量。

## 管理接口

前缀为 `/api/channel_monitor/limit-groups`，均使用超级管理员权限：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | 前缀本身 | 组配置及实时总量、等级和成员用量 |
| POST | 前缀本身 | 创建组，可立即启用 |
| PUT | `/:id` | 完整更新配置，携带 `revision` |
| DELETE | `/:id?revision=...` | 在线删除组，保留渠道计数 |

限流原因通过请求响应返回，管理页面显示实时用量、队列长度及运行状态。首版不提供历史拒绝原因累计统计。
