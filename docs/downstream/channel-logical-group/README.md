# 渠道逻辑归组

逻辑归组让多个物理渠道共享智能调度、状态探测和模型检测身份。逻辑组不是新的渠道、计费账户或普通监控展示维度。

## 共享和隔离

- 智能调度将同组物理候选合并为一个逻辑候选，样本和路由保护按逻辑组保存。
- 状态探测按逻辑目标去重，每轮选择一个物理成员执行。
- 模型检测按逻辑配置和目标去重，执行和成本仍记录实际物理渠道。
- 成本、余额、倍率、普通性能、日志、审计和并发租约仍按物理渠道记录，不生成逻辑组汇总。

## 归组规则

管理员在渠道管理的“同渠道配置”入口创建逻辑组。成员必须非空、不能重复，一个物理渠道最多属于一个组；weight 默认 1，最大为 1,000,000，显式 0 表示不分配权重。

归组预检比较渠道基础地址的规范化结果：统一 scheme 和主机名大小写、折叠默认端口、清理末尾斜杠和片段、排序查询参数；账号密码和敏感参数不能用于归组。

## 管理接口

接口位于 `/api/channel/logical-groups`，查询和预检需要 ChannelRead，创建、替换成员和启停需要 ChannelWrite，删除需要 ChannelSensitiveWrite。成员替换、状态变更和删除使用 revision；旧 revision 返回 409。响应只返回脱敏成员信息，不返回渠道 Key。

## 运行时行为

运行时使用包含 logical ID、revision、成员 ID、weight 和地址摘要的冻结快照。关系变更不会改写已经运行的调度、探测或检测任务；缓存刷新失败时不会发布半套关系。全局开关 `CHANNEL_LOGICAL_GROUP_ENABLED` 或单组 disabled 时，新请求回退到物理渠道路径，关系和历史保留。

组内选成员时先过滤禁用、冷却、模型不支持和并发不可用渠道，再按 weight 选择；并发仍调用物理渠道租约，不创建逻辑组租约。
