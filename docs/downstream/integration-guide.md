# 下游功能使用指南

本文说明功能依赖、启用顺序和关闭后的行为。

## 依赖与部署边界

| 能力 | 依赖与限制 |
| --- | --- |
| 当日统计、健康窗口、被动周期监测 | Redis >= 6.2，并启用主节点后台任务 |
| 利润统计 | 主节点先完成收入表迁移，再启动其他节点；需保持 `CHANNEL_DAILY_COST_RELIABLE_OUTBOX=true` 才能确认利润。收入从启用后累计，不回填历史 |
| 请求级余额预估 | Redis 与成功的上游余额同步；原始余额查询仍可在无 Redis 安装使用 |
| 共享上游限流 | 多实例必须共用同一 Redis；无 Redis 仅支持单实例，不支持 Redis Cluster |
| 上游账户、独立请求、共享变量、自动任务 | 主数据库与可用上游接口；自动任务由主节点独立调度 |
| 模型检测 | 独立检测器、其内部中继配置与网络可达性 |
| API Key 自动禁用 | 当前仅支持单个后端实例；本地恢复日志须持久化 |
| 全局本地探针、使用日志、管理员分组访问、图像定价保护 | 可单独使用，不依赖监控 Stream |

未启用 Redis 时，已保存的数据库历史仍可查询，实时统计和请求级余额预估不可用。启用 Redis 后应保持连接可用。相关参数见[配置参考](configuration-reference.md)。

## 配置顺序

1. 配置 Redis 和唯一节点身份，确认监控消费者、日持久化及成本后台正常。多实例使用可区分的 `CHANNEL_MONITOR_CONSUMER_ID` 或 `INSTANCE_ID`。
2. 在 `/channel-monitor` 配置上游倍率、余额及换算，先“测试获取”再保存。分组倍率策略可先用“仅记录”核对结果。
3. 同一余额池需要跨渠道共用时创建[上游账户](channel-monitor/upstream-accounts.md)。只需复用登录凭据时使用[共享变量](channel-monitor/shared-variables.md)，不要据此合并余额。
4. 配置余额预警与自动禁用阈值，成功同步建立基准，检查[余额预估](channel-monitor/balance-estimation.md)的单位与完整性。预警和禁用是两个独立条件。
5. 按需配置[独立自动任务](channel-monitor/upstream-automation.md)。测试或保存不执行触发接口，启用后的检查才按条件执行；它不依赖渠道同步总间隔继续运行。
6. 选择少量文本模型启用状态/分组探测。真实探测可能收费，记录调度样本时状态探测间隔至少 60 秒；禁止自动探测的渠道使用[业务周期监测](channel-monitor/probe-policy.md)。
7. 确认成本倍率、业务样本和分组策略后启用[智能调度](channel-monitor/smart-scheduling.md)，并按路由明确参与。
8. 按实际需要配置单渠道限额、[共享限流组](channel-monitor/shared-limits.md)或[逻辑归组](channel-logical-group/README.md)。三种共享关系互不自动建立。
9. 若使用 [API Key 自动禁用](channel-monitor/token-auto-disable.md)，配置持久化 `TOKEN_AUTO_DISABLE_JOURNAL_DIR`，并核实单实例约束。

主页面数据以手动刷新为主，后台任务持续运行。刷新按钮不强制执行上游查询或成本记账。

## 常见问题

| 现象 | 应检查 |
| --- | --- |
| 实时数据显示降级 | Redis、消费者、队列分段进度及覆盖字段；降级不表示零流量 |
| 智能调度未接管 | 总开关、分组策略、参与状态、模型能力、保护/冷却及样本；未托管时沿用原有选路 |
| 分组倍率被抬高 | `update_group_ratio` 策略、参与渠道最高成本倍率及持久化分组系数 |
| 余额恢复仍未启用 | 常规监控须估算完整；独立任务看本轮真实上游余额；两者仍受恢复开关、倍率和人工禁用保护 |
| 用户没看到分组监控入口 | 服务状态与 pricing 导航/访问设置；展示清单来自监控配置，显示不授予调用权限 |
| 探测成功而调度样本未增 | 是否记录样本、间隔、事件资格；本地响应不生成上游成功样本 |
| 修改共享限流后仍受限 | 在线修改保留物理渠道当前并发和最近一分钟 RPM，不重置用量 |
| 图像生成直接返回错误 | 原始模型未配置图像倍率，选渠和预扣前拒绝并跳过重试 |

运行状态和诊断操作见[运行状态与诊断](channel-monitor/recovery-troubleshooting.md)。

## 关闭与停用

| 配置 | 关闭后的行为 |
| --- | --- |
| 智能调度总开关 | 新选路回到原有 Ability、优先级和权重；历史状态保留 |
| `CHANNEL_LOGICAL_GROUP_ENABLED=false` | 新请求使用物理渠道路径，关系和历史保留 |
| 渠道同步间隔 0 | 停止该定时同步；独立账户刷新、自动任务须分别配置 |
| 全局本地探针 | 公开请求继续正常选渠和中继 |
| 小输入本地响应 | 恢复实际转发；关闭禁止自动探测会同时关闭小输入响应 |
| 单渠道并发/RPM 上限 0 | 该维度不设单渠道上限；所属共享组上限仍生效 |
| 共享限流组删除 | 成员恢复独立限流，已有物理渠道计数保留 |
| API Key 自动禁用总开关 | 不再新触发；已禁用记录必须由管理员解除 |
| 可靠成本生产开关关闭 | 紧急退回内存 batcher，已接受的可靠事件仍需排空 |

多实例应使用支持相同功能的版本。关闭功能不会取消已经发生的费用；在途请求、待退款和待结算记录继续处理。
