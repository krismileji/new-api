# 下游功能集成指南

本文说明当前下游功能如何叠加到上游网关，以及推荐的启用顺序。所有用户可见文案和下游 API 消息使用简体中文；不要为这些功能新增 i18n 键。

## 功能依赖

```text
Redis >= 6.2
  └─ 渠道监控 runtime（事件流、实时投影、调度副作用）
        ├─ 上游同步 / 余额策略 / 邮件通知
        ├─ 智能调度
        ├─ 状态探测 / 分组监控 / 连通性测试
        ├─ 模型检测（另需检测器地址）
        └─ 本地探针响应（可选，不依赖事件流即可拦截公开请求）

逻辑归组 ──> 只影响智能调度、状态探测、模型检测的共享身份
使用日志用户侧视图 ──> 独立于渠道监控
中继失败切换 ──> 使用渠道并发、智能调度排除集和错误映射
管理员分组访问 ──> 独立于渠道监控
图像生成定价保护 ──> 独立于渠道监控，发生在选渠之前
```

渠道监控管理入口是 `/channel-monitor`，API 前缀 `/api/channel_monitor`。没有 Redis 时进程不能启动监控 runtime；历史成本和日志仍可按数据库路径工作，但实时页和调度实时窗口会降级。

## 推荐启用顺序

1. **确认 Redis**  
   启用 Redis `>= 6.2`，并保证监控进程能创建 `channel_monitor:v1:events` 消费组。多节点部署时为每个实例设置可区分的 `CHANNEL_MONITOR_CONSUMER_ID` 或 `INSTANCE_ID`。

2. **先看观测，再改路由**  
   打开 `/channel-monitor`，确认概览、成本和性能能读到数据。先配置上游同步和分组倍率，不要立刻打开智能调度。

3. **配置上游同步**  
   按渠道选择 New API / Sub2API / 自定义上游，分别打开倍率或余额同步。先用“测试配置”验证，再保存。分组倍率策略建议从“仅记录”开始。

4. **打开探测**  
   状态探测和分组监控都会真实请求上游并产生费用。先选少量文本模型，间隔不要低于 `60s` 如果要记录调度样本。

5. **最后启用智能调度**  
   确认目标分组已有足够样本和成本倍率后，再为该分组配置策略并标记参与。没有策略时系统保持上游原有优先级/权重。

6. **按需打开保护功能**  
   渠道并发限制、本地探针响应、错误信息映射、图像倍率保护互不依赖，可单独启用。

7. **逻辑归组放在调度之后**  
   只有多个物理渠道确实代表同一上游身份时才归组。归组不会合并成本或余额。

## 配置最佳实践

- 智能调度性能窗口默认 `60` 分钟；稳定性窗口默认 `5` 分钟。窗口过大或过小都会让分数抖动。
- 分组自动同步从“仅记录”观察一段时间，再改为更新分组倍率。系数会持久化。
- 余额自动禁用只处理监控自己写下的禁用原因，不会覆盖人工禁用。
- 并发上限 `0` 表示不限制。显式指定渠道满载时，系统最多等待 `channel_concurrency_wait_seconds`（默认 `1s`）后返回 HTTP 429。
- 本地探针只对 `/v1/responses` 和 `/v1/chat/completions` 的单轮纯文本生效。连通性测试不走该拦截。
- 模型检测器地址保存在数据库；`GPT56_DETECTOR_URL` 只在数据库为空时提供初始值。活动轮次结束前不会切换正在使用的地址。

## 常见问题

**实时页显示降级或空数据**  
先看 Redis、消费者是否运行、`pending_count` 和 `realtime_degraded`。降级不是零流量。历史成本和分钟趋势仍可查。

**智能调度没有接管流量**  
检查总开关、分组策略、路由是否参与、渠道是否启用、模型能力、429 冷却和样本是否达到 `min_samples`。没有托管策略时会回退上游 Ability。

**分组倍率被意外抬高**  
查看该组策略是否为 `update_group_ratio`，以及同步系数。手动“按最高成本倍率更新”也会持久化系数。

**探测成功但调度样本没有增加**  
状态探测需要打开“记录样本”，且间隔至少 `60s`。手动连通性测试默认不是调度样本，除非上下文显式标记 `scheduling_eligible`。

**逻辑组看起来没有成本**  
这是预期行为。成本、余额、并发和普通性能始终记在物理渠道上。

**用户看不到分组监控**  
需要 `group_monitor_enabled=true`，pricing 导航模块可用，并且当前账号能看到对应分组。用户侧不含渠道 ID 和错误详情。

**图像生成直接失败且不重试**  
原始模型未配置图像倍率。该检查发生在选渠和预扣费之前，错误标记为不可重试。

## 回退

| 功能 | 关闭后的行为 |
| --- | --- |
| 智能调度 | 回退 Ability 和渠道优先级/权重；已写入的路由状态保留 |
| 逻辑归组 `CHANNEL_LOGICAL_GROUP_ENABLED=false` | 新请求走物理渠道路径；关系和历史保留 |
| 上游同步间隔 `0` | 停止定时更新；已保存倍率和余额保留 |
| 本地探针 | 请求继续正常选渠、计费和中继 |
| 渠道并发 `0` | 不限制并发 |
| 可靠成本 outbox `false` | 紧急回滚到内存 batcher，不是默认语义 |

## 冲突管理

下游功能优先使用新文件、新路由和新 Option 键。必须改上游文件时，把行为限制在窄钩子里，例如选渠后的并发租约、中继完成后的事件发布、图像生成前的倍率检查。上游同步提交应与下游功能提交分开。
