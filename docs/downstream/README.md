# 二开功能文档

本目录集中记录当前下游分支相对上游新增或改变的功能。代码仍是行为的最终依据；文档用于说明功能入口、配置、数据影响、运维要求和与上游的差异。

首次盘点基于 2026-07-25 的 `main` 分支，并以 `upstream/main...HEAD` 的差异为范围。后续每个二开功能都应在同一变更中更新这里的索引和对应专题文档。

## 文档导航

- [功能总览](feature-catalog.md)：当前二开功能清单和入口。
- [中继重试与错误可见性](relay-reliability/README.md)：失败渠道切换、亲和规则和日志隔离。
- [管理员分组访问](admin-group-access/README.md)：管理员使用全部已配置分组的规则。
- [图像生成定价保护](image-pricing-guard/README.md)：未配置图像倍率时的请求保护。
- [文档维护约定](maintenance.md)：新增、修改和下线二开功能时的记录要求。
- [渠道监控](channel-monitor/README.md)：渠道监控、上游同步、成本统计、智能调度、连通性测试和并发限制的完整文档。

## 目录边界

每个独立二开功能使用一个专属子目录，并以该目录的 `README.md` 作为入口。渠道监控相关内容只放在 `channel-monitor/`；其他功能也按稳定业务主题建立同级目录，避免把功能文档散落在根目录或堆入一个总文档。

上游原有功能不在这里重复说明；只有二开改变了上游行为、接口、权限、数据或运维方式时，才记录差异。

## 维护入口

新增或修改二开功能时至少完成以下事项：

1. 更新 [功能总览](feature-catalog.md) 的状态和入口。
2. 新增或更新对应功能目录的 `README.md` 或专题文件；渠道监控内容必须写入 `channel-monitor/`。
3. 记录用户入口、接口或配置、持久化数据、权限边界、失败行为和验证方式。
4. 标明与 `upstream/main` 的差异以及同步上游时需要重点复核的文件。
5. 不在文档中写入访问令牌、密码、完整 API Key 或真实用户数据。
